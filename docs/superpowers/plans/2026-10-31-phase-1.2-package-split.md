# Phase 1.2 Package Split Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship `Ariadne.NET.Abstractions` as a dependency-free, AOT-proven package holding the rule-pack schema and pack contracts, with the `Ariadne.NET` engine and the surfaces on top.

**Architecture:** Move six schema types and three interfaces with `git mv` into a new project under one flat namespace; the engine references it and every consumer swaps a `using`. A Native AOT smoke app proves the package publishes without trim or AOT warnings.

**Tech Stack:** .NET 10, C#, xUnit + FluentAssertions, ZInject source generator, Native AOT.

**Spec:** `docs/superpowers/specs/2026-10-31-phase-1.2-package-split-design.md`; file-by-file map and execution order in `docs/superpowers/specs/2026-10-31-phase-1.2-package-split-impact-analysis.md` — read both.

## Global Constraints

- Target framework `net10.0`, `Nullable` and `ImplicitUsings` enabled, as in every existing project.
- Namespace = assembly = PackageId = `Ariadne.NET.Abstractions` for everything in the new project; flat folder, no subfolders.
- `Ariadne.NET.Abstractions.csproj` has **no** `PackageReference` and **no** `ProjectReference`. The analyzers from `Directory.Build.props` are `PrivateAssets=all` and do not count.
- `IsAotCompatible` is `true` on Abstractions.
- No behaviour change. Member names, signatures and `init` defaults of the moved types stay byte-identical apart from the `namespace` line and `using` lines.
- Move files with `git mv` so history follows them.
- Baseline: 261 tests pass (225 `Ariadne.NET.Tests`, 26 `Mcp.Tests`, 10 `Cli.Tests`); a `--no-incremental` build gives 27 warnings. Do not add warnings.
- Commits: conventional format, scope free. **No `Co-Authored-By: Claude` trailer, no session links.** No nested parentheses in commit bodies.
- Work from the worktree; push with `git push -u origin HEAD:fix/mcp-composite-template`.

## Review Focus

1. **Abstractions quietly gains a dependency** — someone adds a ZInject attribute or YamlDotNet attribute to a moved type. Expect the build to stay green but the package to stop being dependency-free. Pinned by `AbstractionsAssemblyTests.References_only_framework_assemblies` in Task 1.
2. **Moved interfaces stop resolving from DI** because they now live in another assembly. Expect `AddAriadneNETServices()` to still register `IRulePackLoader`, `IRulePackResolver`, `IBuiltinPackRegistry`. Pinned by the existing `ServiceRegistrationTests`, run at Task 1's checkpoint.
3. **Built-in packs or MCP resources go missing at runtime** after the move. Expect `builtin://clean-architecture` and `ariadne://packs/{name}` to keep working. Pinned by the existing `BuiltinPackRegistryTests`, `BuiltinPackIntegrationTests` and `PackResourcesTests`, run at Task 1's checkpoint.
4. **The smoke app ships as a NuGet package**, because CI packs the whole solution. Expect only `Ariadne.NET.Abstractions` and `Ariadne.NET` packages. Pinned by the pack check in Task 2.
5. **A consumer of `Ariadne.NET` does not get Abstractions transitively.** Expect the engine `.nuspec` to list `Ariadne.NET.Abstractions` as a dependency. Pinned by the pack check in Task 2.
