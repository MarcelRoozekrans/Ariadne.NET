## Task 4: The fail-the-build proof job

**Files:** `.github/workflows/ci.yml`

- [ ] In `pack-validate`, after the pack step, add `actions/upload-artifact` of `artifacts/packages` named `packages`, `retention-days: 1`. Use the major version the other workflows use, or the current major if none.
- [ ] Add a job `fail-the-build` (`needs: pack-validate`, ubuntu, `timeout-minutes: 15`) that checks out, sets up .NET 10, downloads the artifact, installs the tool with `dotnet tool install Ariadne.NET.Cli --tool-path "$RUNNER_TEMP/tool" --add-source <download dir> --version "$PACKAGE_VERSION"` (read the version as `pack-validate` does), restores `tests/fixtures/broken` and `tests/fixtures/clean`, then:
  - runs `"$RUNNER_TEMP/tool/ariadne" validate tests/fixtures/broken --format sarif --output "$RUNNER_TEMP/ariadne.sarif"` with `set +e` and fails with an `::error::` line unless the exit code is exactly 1;
  - checks the SARIF file exists and that `runs[0].results[0]` has a `ruleId` and `level` `error` (python3 one-liner);
  - runs the same command on `tests/fixtures/clean` and fails unless it exits 0.
- [ ] Add a comment above the job: what it proves and that the example workflows use the same command line.
- [ ] Run `actionlint` on the workflow if installed; the two known `create-github-app-token` false positives (rhysd/actionlint#648, #669) are the only allowed findings.
- [ ] Extend the Task 3 test: it also asserts that the `fail-the-build` job in `.github/workflows/ci.yml` runs `ariadne validate` with `--format sarif --output`. Run it: it passes.
- [ ] Commit: `ci: prove a broken fixture fails the build`.
