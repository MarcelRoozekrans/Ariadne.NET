# Phase 2.2 Rule Schema v2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Packs load only as strict `schema: 2` YAML with selectors, `forbid`/`allowOnly` rules, exceptions and a required `id` and `because`; the engine enforces layer dependencies, `forbid` and `allowOnly` on the 2.1 type graph; every built-in pack and this repo's pack are migrated; `lint` is gone.

**Architecture:** `Ariadne.NET.Abstractions` gets the v2 model. In `Ariadne.NET`, a hand-written node walk over YamlDotNet's representation model (`RuleLoader/PackYamlReader`) replaces the reflection deserializer for packs and reports every problem with line and column. `RulePackMerger` applies the v2 `extends` rules and fails on conflicts. In `Analysis/`, compiled globs and type selectors back a selector-based `LayerMap`, and `LayerRules`, `ForbidRules` and `AllowOnlyRules` run over the `TypeGraph` edges.

**Tech Stack:** C# / .NET 10, YamlDotNet 16.3.0 (`YamlDotNet.RepresentationModel`), Roslyn 5.9.0, ZeroAlloc.Results, ZeroAlloc.Validation, ZeroAlloc.Inject, ZeroAlloc.TestHelpers, xunit 2.9.3, FluentAssertions 8.

**Spec:** `docs/superpowers/specs/2026-11-05-phase-2.2-rule-schema-v2-design.md`. Binding input: `docs/superpowers/specs/2026-11-04-milestone-2-design.md`, sections "Decisions" and "Calls made". Read both before starting.

## Global Constraints

- Shared VM: one build or test run at a time, never in parallel. Never run a Native AOT publish locally; the AotSmoke publish runs in CI only.
- `TreatWarningsAsErrors` is on with Meziantou, Roslynator, ErrorProne.NET, Hyperlinq and ZeroAlloc analyzers. Fix warnings, never suppress them.
- YamlDotNet stays at 16.3.0 and Roslyn at 5.9.0. No new package except where a task names one.
- `Ariadne.NET.Abstractions` stays AOT-compatible; the AotSmoke test must stay green.
- Expected failures return `Result<T, AriadneError>`; argument nulls throw `ArgumentNullException`.
- Glob matching is ordinal and case-sensitive. Layer names and rule ids, as identifiers inside a pack, are compared `OrdinalIgnoreCase`, as in v1.
- `extends` references stay `builtin://<name>` and `import://<name>`; nested `extends` of an extended pack are not resolved, as today.
- Exit codes keep their meaning: 0 clean, 1 violations, 2 error.
- Commits: conventional commits; no `Co-Authored-By` trailer, no session link; no nested parentheses in commit bodies. Implementation runs on `feat/phase-2.2-rule-schema-v2`, in its own worktree, from `ariadne/main` after the design-and-plan PR has merged. Push with `git push ariadne HEAD:feat/phase-2.2-rule-schema-v2`, never to `origin`.
- Breaking commits carry `!` and a `BREAKING CHANGE:` footer: Tasks 5, 6, 9 and 10.

## Review Focus

1. **A pack file with duplicate keys, a YAML anchor and alias, CRLF line endings or a UTF-8 BOM.** Expected: duplicate keys are a load error with the second key's line; aliases resolve; line and column numbers are the same as for the LF, BOM-less file. Tests in Task 4.
2. **A pack whose root is a sequence or a scalar, or a file of only comments.** Expected: an `Invalid` error naming the problem, never an exception. Tests in Task 4.
3. **A dependency on a constructed generic, such as a field `List<ISubagentRunner>` or `Func<ISubagentRunner>`.** Expected: it counts as a dependency on `ISubagentRunner` and an `allowOnly` on that type fires. Test in Task 8.
4. **A type in the global namespace, or a nested type, against `**` and `types` selectors.** Expected: `**` matches the global namespace; `Outer.Inner` is matched by `**.Outer.Inner`, not by `**.Inner`. Tests in Tasks 2 and 3.
5. **A child pack that retargets an inherited layer to selectors that now overlap another layer.** Expected: a `LayerOverlap` violation per covered source type at validation time, not a load error. Test in Task 7.

### Task 4: Strict v2 pack reader

**Model:** opus. Error collection across a recursive node walk with exact positions is the riskiest code of the phase.

**Files:**
- Create: `src/Ariadne.NET/RuleLoader/PackYamlReader.cs`, `src/Ariadne.NET/RuleLoader/PackProblem.cs`, `src/Ariadne.NET/RuleLoader/KeySuggestion.cs`
- Test: `tests/Ariadne.NET.Tests/RuleLoader/PackYamlReaderTests.cs`

**Interfaces:**
- Consumes: the v2 model (Task 1), `Glob` (Task 2) to check patterns.
- Produces:
  - `internal readonly record struct PackProblem(int Line, int Column, string Message)`, with 1-based `Line` and `Column`.
  - `internal static class PackYamlReader` with `static Result<RulePack, IReadOnlyList<PackProblem>> Read(string yaml)`. It is not wired into loading until Task 6.
  - `internal static class KeySuggestion` with `static string? Closest(string key, IReadOnlyList<string> allowed)`, the allowed key at Levenshtein distance ≤ 2 with the lowest distance, ties by list order, or null.
- **Allowed keys,** camelCase:
  - top level: `schema`, `name`, `version`, `author`, `extends`, `layers`, `rules`, `componentRoles`, `namingConventions`
  - layer: `name`, `id`, `because`, `description`, `namespaces`, `assemblies`, `allowedDependencies`
  - rule: `id`, `because`, `description`, `forbid`, `allowOnly`, `exceptions`, `locked`
  - `forbid`/`allowOnly`: `from`, `to`
  - target: `layers`, `namespaces`, `assemblies`, `types`
  - exception: `namespaces`, `assemblies`, `types`, `because`
  - role: the eight v1 keys
  - `namingConventions`: `namespace`, `filePath`
- **Entry classification:**
  - A layer entry with only `name`, `namespaces` and `assemblies` becomes a `LayerRetarget`. Otherwise it is a `LayerDefinition`, which needs `name`, `id`, `because` and at least one selector.
  - A rule entry with only `id` and `exceptions` becomes a `RuleAmendment`. Otherwise it is a `RuleDefinition`, which needs `id`, `because` and exactly one of `forbid` or `allowOnly`.
  - Retargets and amendments in a pack with no `extends` are problems.
- **Messages,** exact text:
  - `unknown key '<k>' in <where>` with `; did you mean '<s>'?` when one is suggested. `<where>` is `the pack`, `layer '<name>'`, `rule '<id>'`, `the forbid of rule '<id>'`, and so on, or `layers[<i>]` before a name is known.
  - `<where> has no '<k>'`
  - `'<k>' in <where> must be <a string|a list of strings|true or false|a mapping|a list>`
  - `duplicate key '<k>' in <where>`
  - `'schema: 2' is required; this looks like a v1 pack. See https://marcelroozekrans.github.io/Ariadne.NET/how-it-works/rule-schema#migrating-from-v1` when `schema` is absent. Use `'schema' must be 2` for any other value.
  - `'codeFeatureRules' is not part of schema 2; typed code-feature rules arrive in a later release`
  - `rule '<id>' must have exactly one of 'forbid' or 'allowOnly'`
  - `a target in rule '<id>' cannot mix 'layers' with 'namespaces', 'assemblies' or 'types'`
  - `<where> needs at least one of 'namespaces', 'assemblies'<, 'types'>`
  - `'<pattern>' in <where> is not a valid pattern: <Glob failure>`
  - `layer '<name>' only changes selectors, which needs 'extends'`, and the rule-amendment equivalent
  - `typeKind '<v>' in role '<name>' must be one of <CSharpTypeKind names>`
- **Positions:** each problem takes the start mark of the offending key node. A missing key uses its parent mapping. Parse errors from YamlDotNet become a single problem at the exception's start mark, with the parser's message.

### Task 7: Layer rules on selectors, with overlap

**Files:**
- Create: `src/Ariadne.NET/Analysis/LayerRules.cs`, `src/Ariadne.NET/Analysis/RoleRules.cs` (renamed from the V1 files)
- Modify: `src/Ariadne.NET/Analysis/ArchitectureValidator.cs`, `ViolationKind.cs`
- Delete: `src/Ariadne.NET/Analysis/V1LayerMap.cs`, `V1LayerRules.cs`, `V1RoleRules.cs`
- Test: `tests/Ariadne.NET.Tests/Analysis/LayerRulesTests.cs` and `RoleRulesTests.cs`, renamed and ported from the V1 tests, plus `ArchitectureValidatorTests.cs`

**Interfaces:**
- Consumes: `LayerMap` (Task 3).
- Produces:
  - `ViolationKind` gains `ForbiddenDependency = 5`, `DependencyNotPermitted = 6` and `LayerOverlap = 7`.
  - `internal static class LayerRules` with `static IReadOnlyList<ArchitectureViolation> Check(TypeGraph graph, LayerMap layers, RulePack pack)`.
  - `RoleRules` keeps the `V1RoleRules` members and behaviour, reading layers through `LayerMap`.
- **`DependencyNotAllowed`:**
  - `RuleId`: the source layer's `Id`; `Because`: its `Because`.
  - Message: today's `Layer '<src>' is not allowed to depend on '<tgt>': <S> references <T>[ <n> times]`.
  - Aggregation and location: as today.
- **`LayerOverlap`:**
  - `RuleId`: the ids of all covering layers joined with `+`, in pack order.
  - `Because`: `A type must belong to at most one layer.`
  - Message: `Type '<T>' is covered by layers <'A', 'B'>`.
  - `SourceType` is the type and `Target` is null.

- **Semantics:**
  - `forbid`: an edge S→T with S ∈ `From`, T ∈ `To`, and S matched by no exception.

  - Aggregation is one violation per (rule, S, T) with `ReferenceCount`, located at the first edge, as in `LayerRules`.
- **Violation fields:** `RuleId` and `Because` from the rule.
  - `ForbiddenDependency` message: `Rule '<id>' forbids this dependency: <S> references <T>[ <n> times]`.
  - `DependencyNotPermitted` message: `Rule '<id>' allows only selected types to depend on <T>: <S> references <T>[ <n> times]`.
