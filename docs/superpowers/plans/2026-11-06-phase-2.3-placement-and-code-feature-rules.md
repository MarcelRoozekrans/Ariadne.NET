# Phase 2.3 Placement and Code-Feature Rules Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A pack can state a `require` rule (layer, kind, accessibility, implements) over types selected by namespace, assembly, name, base type, interface or attribute, and `CODE-001` and `CODE-002` are reported by rule id from the pack's roles.

**Architecture:** `TargetSelector` gains three lists and `RuleKind` gains `Require`; `TypeSelector` learns the new matches; `PackYamlReader` reads the `require` rule; a new `RequireRules` checker runs next to `ForbidRules` in `ArchitectureValidator`. Roles stay engine-internal: `RoleRules` keeps its matching and only changes the ids and the `because` of its violations.

**Tech Stack:** C# / .NET 10, YamlDotNet 16.3.0, Roslyn 5.9.0, ZeroAlloc.Results, ZeroAlloc.Validation, xunit 2.9.3, FluentAssertions 8.

**Spec:** `docs/superpowers/specs/2026-11-06-phase-2.3-placement-and-code-feature-rules-design.md`. Also read `2026-11-05-phase-2.2-rule-schema-v2-design.md` for the selector and merge rules this builds on.

**Refinements against the spec**, decided while planning:
- Role expansion is engine-internal, not rewritten into `pack.Rules`. `RoleRules` already matches case-insensitively on the simple name, first role in the layer wins, and checks kind, accessibility and missing interface. Keeping that code keeps every behavior the spec asks to preserve. Only the violation ids and `because` change.
- A `for` selector cannot mix `layers` with the other keys, as `TargetMatcher` already requires for `from` and `to`.
- A type covered by two layers gets `LayerOverlap` only; a `layer` requirement does not add a `WrongLayer` for it.
- CLI `rules` and MCP `get_rules` list `require` rules like the others. Roles stay listed as roles.

## Global Constraints

- Shared VM: one build or test run at a time, never in parallel. Never run a Native AOT publish locally; the AotSmoke publish runs in CI only.
- `TreatWarningsAsErrors` is on with Meziantou, Roslynator, ErrorProne.NET, Hyperlinq and ZeroAlloc analyzers. Fix warnings, never suppress them.
- YamlDotNet stays at 16.3.0 and Roslyn at 5.9.0. No new package.
- `Ariadne.NET.Abstractions` stays AOT-compatible; the AotSmoke test must stay green.
- Expected failures return `Result<T, AriadneError>`; argument nulls throw `ArgumentNullException`.
- Glob matching is ordinal and case-sensitive, except the role name-suffix match, which stays `OrdinalIgnoreCase`.
- Checks are open-world: a type no layer covers is not a violation, except for a `require` rule whose `for` selects it and whose `layer` it misses.
- Generated code is not a rule subject; the graph's `SourceTypes` already exclude it.
- Exit codes keep their meaning: 0 clean, 1 violations, 2 error.
- Commits: conventional commits; no `Co-Authored-By` trailer, no session link; no nested parentheses in commit bodies; footer lines under 100 characters. Implement on `feat/phase-2.3-placement-and-code-feature-rules`, from `ariadne/main` after the design PR merges.
- Task 5 is breaking: commit it `feat(analysis)!:` with a `BREAKING CHANGE:` footer. Release-please reads only one footer from a squash commit, so before merging the PR, put a `BEGIN_COMMIT_OVERRIDE` block in the PR body with one line per commit and the breaking text in the subject.

## Review Focus

1. **A type implements `IRepository<T>` through a base class and the selector says `interfaces: ["**.IRepository"]`.** Expected: it matches; arity is dropped and inherited interfaces count. Test in Task 2.
2. **An attribute written `[Obsolete]` against `attributes: ["System.ObsoleteAttribute"]`.** Expected: it matches, because the glob runs on the attribute class's real name. Test in Task 2.
3. **A `require` rule whose `for` selects nothing.** Expected: no violation and no error; vacuity is phase 2.5. Test in Task 4.
4. **A pack that declares a rule or layer id of `CODE-001`, `CODE-002` or starting `ROLE-`.** Expected: a load error naming the reserved id. Test in Task 3.
5. **A type in two layers against a `require` rule with `layer`.** Expected: one `LayerOverlap` violation and no `WrongLayer`. Test in Task 4.
