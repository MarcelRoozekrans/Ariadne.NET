# Phase 4.2 Type-level Conditions Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Packs express ArchUnitNET's type-level predicates and conditions: selector traits (`names`, `kinds`, `accessibility`, `assignableTo`, `sealed`, `abstract`, `static`, `nested`), and `require` gains `is` and `isNot`. Every `KnownGaps` entry with phase `4.2` is closed against the parity harness.

**Architecture:** The traits are new members of `TargetSelector` (Abstractions), compiled into `TypeSelector` (engine) and accepted next to `layers` by `TargetMatcher`. `RequireRules` compiles `is` and `isNot` into one `TypeSelector` per key and reports `ViolationKind.RequirementNotMet` per failed key. `PackYamlReader`, the JSON Schema, `RulePackDescriber` and the docs follow. Then the 4.1 parity packs gain their missing rules and the 4.2 `KnownGaps` entries go.

**Tech Stack:** .NET 10, Roslyn, ZeroAlloc.Validation, YamlDotNet representation model, xUnit, FluentAssertions, `TngTech.ArchUnitNET` 0.13.2 (parity tests only).

**Spec:** `docs/superpowers/specs/2026-11-11-phase-4.2-type-level-conditions-design.md`

## Global Constraints

- Nothing is breaking: `require` keys `kind`, `accessibility` and `implements` keep their current behaviour and messages, including skipping enums and delegates. Commits are `feat:`, `fix:`, `test:` or `docs:`, never `feat!`.
- The new public API in this plan is approved by the owner, through the approved design and again at ready-check on 2026-11-12: the selector traits, `is` and `isNot` on `require`, the trait members on `TargetSelector` and `RuleException`, and `ViolationKind.RequirementNotMet`. Build it in full; the owner reviews it in the PR.
- New `TargetSelector` members, with these exact names and types: `IList<string> Names`, `IList<CSharpTypeKind> Kinds`, `IList<string> Accessibility`, `IList<string> AssignableTo`, `bool? Sealed`, `bool? Abstract`, `bool? Static`, `bool? Nested`. YAML keys: `names`, `kinds`, `accessibility`, `assignableTo`, `sealed`, `abstract`, `static`, `nested`.
- `RuleRequirement` gains `TargetSelector? Is` and `TargetSelector? IsNot`; YAML keys `is` and `isNot`.
- `RuleException` gains the same eight trait members with the same names, types and YAML keys as `TargetSelector`. An exception's keys are AND-ed; an exception with only traits is valid. This is an owner decision of 2026-11-11 from the CodeRabbit review of PR #84, recorded in the spec's Decisions.
- `ComponentRoleDefinitionValidator` rejects a `TypeKind` of `Enum` or `Delegate`, and `RuleRequirementValidator` a `Kind` of either, through a `Must` rule listing the five values. `CodeGeneratorService.Generate` throws `ArgumentException` for an `Enum` or `Delegate` role, because direct callers skip the validators.
- `CSharpTypeKind` gains `Enum` and `Delegate`, appended after `RecordStruct`. YAML `kinds` values: `class`, `interface`, `record`, `struct`, `recordStruct`, `enum`, `delegate`. `kind` and role `typeKind` reject `enum` and `delegate`.
- `accessibility` trait values, exactly: `public`, `internal`, `protected`, `private`, `protected internal`, `private protected`.
- `ViolationKind.RequirementNotMet = 13`.
- `sealed: true` matches a class or record class declared `sealed`, and a static class. `abstract: true` matches a class or record class declared `abstract`, never a static class. Every other kind is neither sealed nor abstract.
- `names` are flat globs (`Glob.Flat`) over the innermost simple name without arity. `assignableTo` uses the `types` grammar over the type itself, every class in its base chain including `System.Object`, and every interface in `AllInterfaces`.
- Traits are allowed in the `for` of `require`, the `from` and `to` of `forbid` and `allowOnly`, in `is` / `isNot`, and in `exceptions`, also an amendment's. They may sit next to `layers`. `layers` next to `namespaces`, `assemblies`, `types`, `baseTypes`, `interfaces`, `attributes` or `members` stays an error. `is` and `isNot` accept every selector key except `layers` and `members`.
- Analyzers run with `TreatWarningsAsErrors`; zero warnings. CLAUDE.md conventions: `IList<T>` on public models, explicit `StringComparer`, one type per file, `ConfigureAwait(false)`.
- Every new pack key gets a valid and an invalid case in `tests/Ariadne.NET.Tests/PackSchema` and is in `docs-site/static/schema/pack.schema.json`.
- Commit bodies have no nested parentheses; footer lines stay under 100 characters; no `Co-Authored-By` trailer or session link.
- Shared VM: one build or test at a time; no local AOT publish (CI runs `aot-smoke`).

## Review Focus

- **A trait-only selector.** `for: { sealed: true }` must select the sealed types, not nothing and not everything; `TypeSelector.IsEmpty` is false for it. Pinned in Task 2 (`Trait_only_selector_is_not_empty`).
- **`sealed: false` on non-classes.** An interface, struct or enum matches `sealed: false` and `abstract: false`, and never `true`. Pinned in Task 2 (`Non_class_kinds_are_neither_sealed_nor_abstract`).
- **Old `require` keys unchanged.** A rule with only `kind: class` over an enum still yields no violation, while `is: { kinds: [class] }` over the same enum yields one. Pinned in Task 3 (`Old_keys_still_skip_enums_new_keys_do_not`).
- **`layers` with traits versus `layers` with namespaces.** The first loads and matches the intersection; the second is still a load error at the right location. Pinned in Task 2 (`Layers_and_traits_intersect`) and Task 4 (`Layers_with_namespaces_still_fails`).
- **A stale 4.2 gap.** After the phase, no `KnownGaps` entry has phase `4.2`, and the catalogue says `covered` or `divergence` for every row that had notes `4.2`. Pinned in Task 9 (`No_known_gap_left_for_phase_4_2`).
