# Issue #127: check Razor component code — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Syntax trees from the Razor source generator are checked as hand-written source, with violation locations mapped to the `.razor` file.

**Architecture:** `ProjectCompiler` (Workspaces) recognises Razor trees by the generator-type folder above the hint name in the generated document's path and puts them in a new `AnalyzedProject.RazorTrees`; `GeneratedTrees` keeps the other generator trees. The engine's `GeneratedCode.IsGeneratedTree` never calls a Razor tree generated, and `TypeReferenceWalker` reports locations in a Razor tree through `#line` mapping, falling back to line 1 of the `.razor` file.

**Tech Stack:** .NET 10, Roslyn 5.12 (`Microsoft.CodeAnalysis.*`), MSBuildWorkspace, xUnit, FluentAssertions.

**Spec:** `docs/superpowers/specs/2026-11-14-issue-127-razor-components-checked-design.md`

## Global Constraints

- The Razor generator's type name, matched exactly (ordinal): `Microsoft.NET.Sdk.Razor.SourceGenerators.RazorSourceGenerator`. The assembly segment is not matched.
- Every other generator's trees stay skipped. No pack schema change, no option to turn this off.
- Razor trees are not recognised by file name (`*_razor.g.cs`), only by the generator segment.
- Zero build warnings (`TreatWarningsAsErrors`); analyzer conventions from CLAUDE.md (explicit `StringComparison`, `ConfigureAwait(false)`, one type per file).
- Commit messages: conventional commits, no nested parentheses in bodies, no Claude trailer or session link.

## Review Focus

- A component with markup only: no `#line` mapping in its trees. Expect its `.g.cs` locations at line 1 of the `.razor` file through `#pragma checksum`. Test in Task 1.
- A Razor tree with neither a mapping nor a pragma, such as a `.decl.g.cs` without `@code`: expect the generated file's own path, no crash. Test in Task 1.
- Windows paths: the workspace's `FilePath` uses `\` while `HintName` uses `/`. Expect the Razor match on both separators. Test in Task 2 with a backslash path.
- A component with a hand-written `Counter.razor.cs` partial: the type's declaration location is the smallest by path, line and column. Expect the `.razor` file (`Counter.razor` sorts before `Counter.razor.cs`). Asserted in Task 3.
- `.editorconfig` with `generated_code = true` covering a Razor tree: the Razor set wins, so it is still checked. Test in Task 1.
