# Phase 4.8 — Attribute Arguments and Attribute Allow-Lists Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Packs select and require types by attribute arguments (`attributeArguments`) and by an attribute allow-list (`onlyAttributes`), so the six #95 catalogue rows leave `deferred` with harness cases and #95 closes.

**Architecture:** Abstractions gets `AttributeArgumentMatch` and two new lists on `TargetSelector` and `RuleException`. A new `AttributeArgumentMatcher` compares YAML scalar text with Roslyn `TypedConstant`s, and `TypeSelector` uses it in the attribute walk it already does. The loader accepts both keys wherever `attributes` is accepted. `RequireCondition` gets messages for them, then the schema, the parity fixtures, the catalogue and the docs follow.

**Tech Stack:** .NET 10, Roslyn, YamlDotNet representation model, ZeroAlloc.Validation 2.5.0, xUnit + FluentAssertions, TngTech.ArchUnitNET 0.13.5 (parity harness).

**Spec:** `docs/superpowers/specs/2026-11-15-phase-4.8-attribute-arguments-and-allow-lists-design.md`

## Global Constraints

- Key names: `attributeArguments` (entries with keys `attribute`, `arguments` and `named`) and `onlyAttributes` (dotted globs). Model names: `AttributeArgumentMatch` with `string? Attribute`, `IList<string> Arguments`, `IDictionary<string, string> Named` (ordinal); `TargetSelector.AttributeArguments`, `TargetSelector.OnlyAttributes`, `RuleException.AttributeArguments` and `RuleException.OnlyAttributes`.
- Both keys are accepted in exactly the key sets that hold `attributes`: `PlainTargetKeys`, `ConditionKeys`, `OtherSelectorKeys` and `ExceptionKeys`. They are listed right after `attributes`, `attributeArguments` first. A `bannedPackages` exception rejects them with the reason it gives for `attributes`.
- Entry semantics: `attribute`, `arguments` and `named` all apply to one attribute instance applied directly to the type. `arguments` values each equal some argument value of that instance, constructor or named, in any position. Entries are OR-ed.
- Value equality: string ordinal; char as one-character text; bool `true`/`false` case-insensitive; numbers numerically when the scalar parses with invariant culture; enum by simple member name, by the name qualified with the enum's full name, or by the underlying number; `typeof` by `TypeNames.FullNameOf` of the original definition; an array argument or an error constant never matches.
- The loader rejects a `null` value ("quote it to match the text 'null'"), a sequence or mapping as a value, an entry with neither `arguments` nor `named` (pointing to `attributes`), an unknown entry key, and an empty `onlyAttributes` or `arguments` list.
- `onlyAttributes` ignores these attribute classes on every type: `System.Runtime.CompilerServices.CompilerGeneratedAttribute`, `NullableAttribute`, `NullableContextAttribute`, `NullablePublicOnlyAttribute`, `IsReadOnlyAttribute`, `IsByRefLikeAttribute` and `Microsoft.CodeAnalysis.EmbeddedAttribute`.
- Abstractions stays AOT-compatible with no new dependency: `dotnet publish tests/Ariadne.NET.AotSmoke -c Release -r linux-x64 -p:PublishAot=true -warnaserror` stays green.
- The change is additive: commits are `feat`/`test`/`docs`. Commit bodies have no nested parentheses. `TreatWarningsAsErrors` is on.

## Review Focus

- Two instances of the same attribute, each holding one of two required values, must not match one entry. (Task 2 and Task 3 tests.)
- `onlyAttributes` on a metadata `to` target must not fail because of the compiler's `NullableContextAttribute`. (Task 3 test.)
- A type with no attributes at all matches `onlyAttributes`, but does not match `attributeArguments`. (Task 3 test.)
- An `attributeArguments` entry with `named` only must still satisfy "needs at least one of …" checks on a selector or exception that holds only that key. (Task 4 test.)
- `2.0` in YAML equals an `int` argument 2 and a `double` 2, but `"two"` must not crash the numeric path. (Task 2 test.)
