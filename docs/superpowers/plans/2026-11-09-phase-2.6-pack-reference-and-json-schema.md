# Phase 2.6 Pack Reference and JSON Schema Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Publish a JSON Schema for schema 2 packs, kept honest by conformance tests, document every rule type in a reference page, and delete the drifted `docs/how-it-works/` copy.

**Architecture:** `pack.schema.json` is hand-written under `docs-site/static/schema/` and served by the docs site. Tests in `Ariadne.NET.Tests` convert pack YAML to JSON and validate it against the schema, then compare the verdict with `YamlRulePackLoader`. The reference page is split out of the rule-schema page; the old docs copy is removed.

**Tech Stack:** .NET 10, xUnit, FluentAssertions, YamlDotNet 16.3.0 (already referenced by `Ariadne.NET`), a test-only JSON Schema validator (JsonSchema.Net), Docusaurus.

**Spec:** `docs/superpowers/specs/2026-11-09-phase-2.6-pack-reference-and-json-schema-design.md`

## Global Constraints

- Schema draft 2020-12; `additionalProperties: false` on every object; `schema` required and fixed to integer `2`.
- The loader stays the authority. The schema checks shape only.
- Page URL `/how-it-works/rule-schema` must keep working.
- Shared VM: one build or test run at a time, no local AOT publish.
- Commits: conventional, no `Co-Authored-By` trailer or session link, no nested parentheses in bodies, footer lines under 100 characters.
- Docs-only commits use `docs`; the test project change uses `test`. Nothing here is breaking.

## Review Focus

- A schema that accepts a pack the loader rejects for a shape reason (unknown key at any depth): invalid corpus runs through both.
- A schema that rejects a pack the loader accepts, such as the role shorthand, `layers` combined with other selector keys, retarget and amendment entries in a child pack: valid corpus covers built-in packs, the repo pack and the Daedalus fixture.
- `schema: 1` or a missing `schema` key accepted by the editor: invalid corpus.
- A scalar typed wrongly by the YAML-to-JSON converter, for example `version: 1.0` or `"2"`: converter tests.
- Inbound links to the deleted pages: link search in Task 5 plus `npm run build`.

**Interfaces:**
- Produces: `internal static class PackSchemaHarness` with
  - `static string RepoRoot()` — walks up from `AppContext.BaseDirectory` to the directory holding `src/Ariadne.NET.slnx`.
  - `static JsonNode YamlToJson(string yaml)` — plain scalars matching `^-?\d+$` become integers, plain `true`/`false` become booleans, every other scalar (including quoted ones) is a string; mappings and sequences map to objects and arrays; empty `{}` flow maps stay objects.
  - `static IReadOnlyList<string> SchemaErrors(string yaml)` — empty when the schema accepts the pack, otherwise one string per error.
  - `static bool LoaderAccepts(string yaml)` — `new YamlRulePackLoader().LoadFromString(yaml).IsSuccess`.

- [ ] **Step 2: Run** `dotnet test tests/Ariadne.NET.Tests --filter PackSchemaHarnessTests`. Expected: compile failure, `PackSchemaHarness` undefined.
- [ ] **Step 3: Implement `PackSchemaHarness`** over YamlDotNet's `YamlStream` representation model (check `YamlScalarNode.Style` for plain versus quoted). `SchemaErrors` loads the schema file from `RepoRoot()/docs-site/static/schema/pack.schema.json` once and evaluates with detailed output so each error carries its instance location.
- [ ] **Step 4: Write the failing frame tests**: `Schema_accepts_minimal_pack` (`schema: 2` and `name: x`), `Schema_rejects_missing_schema_key`, `Schema_rejects_schema_1`, `Schema_rejects_unknown_top_level_key`, `Schema_accepts_layers_roles_and_naming_conventions` using the layer, role and naming content of the Daedalus overview example, with `rules` omitted. - [ ] **Step 5: Write `pack.schema.json`** for the frame: `$schema` 2020-12, `$id` `https://marcelroozekrans.github.io/Ariadne.NET/schema/pack.schema.json`, `title`, required `schema` (const 2) and `name`, properties `version`, `author`, `extends` (array of strings), `layers`, `rules`, `componentRoles`, `namingConventions`. Use `$defs` for each shape. `rules` items are `{"type": "object"}` for now; Task 2 replaces that. Every property gets a `description` copied from the rule-schema page.
- [ ] **Step 6: Run** the filter from Step 2. Expected: all pass. Run `dotnet build src/Ariadne.NET.slnx` and expect no warnings.

- [ ] **Step 1: Write the failing test** `Every_shipped_pack_validates_and_loads` as a `[Theory]` over `MemberData` listing: every `src/Ariadne.NET/BuiltinPacks/*.yaml`, `.architecture/rules.yaml`, and every `*.yaml` under `tests/fixtures` (found with a recursive search, so new fixtures join automatically). - [ ] **Step 2: Run** `--filter ValidCorpusTests`. Expected: the pack files with `rules` fail on the placeholder only if they contain keys it rejects; at minimum the theory must run and any failures name the keys still missing. Record which keys fail.
- [ ] **Step 3: Extend the schema** with the rule shapes, taken from `PackYamlReader` (`KindKeys`, `TargetKeys`, `ToKeys`, `BannedPackagesKeys`, `UniqueNamesKeys`, `RequireKeys`, `ImplementsKeys`, `ExceptionKeys`) and the rule-schema page: a rule has `id`, `because`, optional `allowEmpty` (boolean), optional `exceptions` (array of exception objects), and exactly one body key among `forbid`, `allowOnly`, `require`, `bannedPackages`, `uniqueNames` (use `oneOf` with `required`). Define `$defs` for `selector` (the `from` side), `toSelector` (adds `members`), `require` body (`kind`, `accessibility`, `implements` and the listed keys), `bannedPackages` body, `uniqueNames` body and `exception`. Selectors keep the reader's rule that `layers` cannot be combined with the other selector keys; express it with `not` plus `required` or a `dependentSchemas` entry and describe it in the `description`.
- [ ] **Step 4: Run** the filter. Expected: all pass. Fix the schema, never the pack, when a shipped pack fails.
- [ ] **Step 5: Commit** `feat(schema): publish the pack JSON Schema for schema 2`.
