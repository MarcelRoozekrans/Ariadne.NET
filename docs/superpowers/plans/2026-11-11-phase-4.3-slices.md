# Phase 4.3 Slices Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Packs group types into slices by a namespace capture and require the slices to be free of cycles or independent; the built-in `modular-monolith` pack uses this for module isolation (#32), and every `KnownGaps` entry with phase `4.3` is closed against the parity harness.

**Architecture:** A new `slices` rule kind (`RuleKind.Slices`, `SliceDefinition` in Abstractions) is read by `PackYamlReader`. In the engine, `SlicePattern` captures a slice name from a namespace, and `SliceRules` runs once over every project's `TypeGraph`, as `UniqueNameRules` does, reporting `SliceDependency` per source and target type, or `SliceCycle` per slice edge inside a strongly connected component. Then the JSON Schema, the describer, the docs, the `modular-monolith` pack with a new fixture, and the parity packs follow.

**Tech Stack:** .NET 10, Roslyn, ZeroAlloc.Validation, YamlDotNet representation model, xUnit, FluentAssertions, NSubstitute, `TngTech.ArchUnitNET` 0.13.2 (parity tests only).

**Spec:** `docs/superpowers/specs/2026-11-11-phase-4.3-slices-design.md`

## Global Constraints

- Additive only in the schema and the public API. Engine and pack commits are `feat:`, `fix:`, `test:` or `docs:`, never `feat!`. The `modular-monolith` commit body says the pack now reports cross-module dependencies.
- Abstractions, exact names: `RuleKind.Slices = 6`; `public sealed class SliceDefinition` with `IList<string> Matching`, `bool FreeOfCycles`, `bool Independent`, `TargetSelector? Allow`; `RuleDefinition.Slices` (`SliceDefinition?`). YAML: rule key `slices` with keys `matching`, `freeOfCycles`, `independent`, `allow`.
- `ViolationKind.SliceCycle = 14`, `ViolationKind.SliceDependency = 15`. Do not use 13: Phase 4.2 owns it.
- Captures: `(*)` is exactly one segment, `(**)` one or more; exactly one capture per pattern, as a whole segment; the rest of the pattern is a dotted glob. Earliest capture start wins, then for `(**)` the shortest capture that lets the rest match. First pattern in list order wins across patterns. A capture never matches zero segments.
- Exactly one of `freeOfCycles: true` and `independent: true`. `allow` accepts the keys of a `forbid` `to` selector, `layers` included, `members` excluded, and at least one key. `exceptions` exempt source types only: an excepted type keeps its slice and still counts as a target.
- Only source types of some graph in the run have a slice, targets included. A nested type's namespace is its outermost containing namespace. Only `TypeGraph.Edges` count, not `MemberEdges`. Types are keyed by assembly name and display string, as `UniqueNameRules.Collect`'s `TypeId`; a type seen in several target frameworks of one project counts once. Edges are checked per framework scope, built as `ArchitectureValidator.AddMissingInterfaceViolations` builds its scopes: one per named target framework with that framework's graphs plus every null-framework graph, or one scope over all graphs when no project names a framework. A violation found in several scopes is reported once; `TargetFrameworks` lists the named frameworks of the scopes that found it, empty when every scope did.
- Messages, exactly:
  - `SliceDependency`: `Type '{source}' in slice '{a}' depends on '{target}' in slice '{b}', and rule '{id}' keeps slices independent` plus the reference-count suffix the other dependency violations use.
  - `SliceCycle`: `Slice '{a}' depends on slice '{b}' (first through '{source}' -> '{target}'), and slices {sorted, comma-separated} form a cycle, which rule '{id}' forbids`.
- `modular-monolith` version `1.1.0`, rule id `MM-MODULES-INDEPENDENT`, `allowEmpty: true`.
- Analyzers run with `TreatWarningsAsErrors`; zero warnings. CLAUDE.md conventions: `IList<T>` on public models, explicit `StringComparer`, one type per file, `ConfigureAwait(false)`.
- Every new pack key and load error gets a case in `tests/Ariadne.NET.Tests/PackSchema` and is in `docs-site/static/schema/pack.schema.json`.
- Commit bodies have no nested parentheses; footer lines stay under 100 characters; no `Co-Authored-By` trailer or session link. The PR body says `Closes #32`.
- Shared VM: one build or test at a time; no local AOT publish.

## Review Focus

- **Framework types under a `**`-led pattern.** A module type referencing `System.Foo.Core.Bar` or a NuGet type whose namespace matches `**.(*).Core.**` must give no violation. Pinned in Task 4 (`Reference_to_a_type_outside_the_run_has_no_slice`).
- **A cycle no single project holds.** Three projects, each holding one edge of `Orders → Billing → Orders`, must report the cycle. Pinned in Task 5 (`Cycle_across_graphs_is_found`).
- **A slice that only points into a cycle.** Its edge into the component is not reported, and it is not named in the cycle message. Pinned in Task 5 (`Edge_into_a_component_is_not_reported`).
- **A module's own `Public` and another module's `Public`.** Both allowed under the built-in rule; another module's `Core` is not. Pinned in Task 7 (the `modular` fixture test).
- **A slices rule in code paths that assume `From`.** Every rule iterator tolerates a `Slices` rule with an empty `From`, and `ariadne rules` describes it. Pinned in Task 3 (`Slices_rule_passes_every_other_checker_untouched`) and Task 6 (`Describes_slices_rule`).
