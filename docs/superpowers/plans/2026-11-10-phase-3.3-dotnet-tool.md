# Phase 3.3 — dotnet tool Implementation Plan

> Execution method: none now. This plan is built later, by an unattended run or by `start-next-phase`. Phases 3.1 and 3.2 must be merged first.

**Design:** `docs/superpowers/specs/2026-11-10-phase-3.3-dotnet-tool-design.md`
**Builds on:** Phase 3.2 — the flags `--format` and `--output` on `ariadne validate` and the exit codes 0, 1 and 2. Phase 3.1 — `Ariadne.NET.Testing` as a packed library and `tests/fixtures/twopacks`.
**Goal:** `ariadne` ships as the `Ariadne.NET.Cli` dotnet tool; CI installs it from the packed local feed and runs it; `publish-nuget` pushes it.
**Conventions:** conventional commits, no nested parentheses in bodies, no `Co-Authored-By` trailer or session link, footer lines under 100 characters. One build or test at a time; do not run the AOT publish locally. Never install the tool globally; use `--tool-path` in a temp folder.

## Task 3: Inspection script learns the tool package

**Files:** `tools/release/inspect_packages.py`, `tools/release/test_inspect_packages.py`

- [ ] Write failing cases in the script's tests for the tool package `Ariadne.NET.Cli`: accepted when it is a `DotnetTool` with command `ariadne`, no Ariadne dependencies in the nuspec, a `.snupkg` and the right compiled version; rejected for each of a wrong command name, an Ariadne dependency, a bundled `Microsoft.Build.dll`, a wrong version and missing symbols. ## Task 4: pack-validate installs and runs the tool

**Files:** `.github/workflows/ci.yml`

- [ ] Add a step after "Rehearse the push against a local feed" in `pack-validate` named "Install the tool from the local feed and run it". It restores `tests/fixtures/twopacks` and `tests/fixtures/clean` with `dotnet restore`, installs the tool with `dotnet tool install Ariadne.NET.Cli --tool-path "$RUNNER_TEMP/tool" --add-source "$RUNNER_TEMP/local-feed" --version "$PACKAGE_VERSION"`, then runs, each failing the step with an `::error::` line when wrong:
  - `ariadne --version` prints `$PACKAGE_VERSION`.
  - `ariadne validate tests/fixtures/twopacks --format json` exits exactly 1; stdout parses with `python3 -c 'import json,sys; d=json.load(sys.stdin); assert d["schema"]==1'` and contains the broken pack's name.
  - `ariadne validate tests/fixtures/clean` exits 0. The `clean` fixture needs its own `.architecture`; if it has none, point at a fixture that does, or add `tests/fixtures/clean/.architecture/rules.yaml` and say so in the commit body.
  - `echo '{}' | ariadne hook session-start` exits 0.
- [ ] Write the step with `set +e` and explicit exit-code capture, as the consumer step above it does. Add a comment block above it saying what it proves.
- [ ] Run `actionlint` on the workflow if it is installed; ignore only the two known `create-github-app-token` `client-id` false positives (rhysd/actionlint#648, #669).
- [ ] Commit: `ci: install and run the ariadne tool from the packed feed`.
