# Phase 4.1 Parity Catalogue and Harness Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A docs-site catalogue of every ArchUnitNET 0.13.2 type-level and slice rule kind, and a test project that runs ArchUnitNET and Ariadne side by side on one fixture project per in-scope kind and fails when they disagree outside `KnownGaps` and `Divergences`.

**Architecture:** A new test project `tests/Ariadne.NET.Parity.Tests` holds a C# case table (`ParityCases.All`). Each case's ArchUnitNET rule is fluent C#, and its Ariadne rule lives in a real pack, `tests/fixtures/archunit-parity/<Kind>/.architecture/rules.yaml`, run through `ArchitectureCheck.Run(<csproj>)`. Results are projected to canonical type names, or to slice names, and compared. A markdown catalogue page is parsed and checked against the case table, `KnownGaps` and `Divergences`.

**Tech Stack:** .NET 10, xUnit 2.9.3, FluentAssertions 8.11.0, `TngTech.ArchUnitNET` 0.13.2 (test only), `Ariadne.NET.Testing` (project reference), Docusaurus markdown.

**Spec:** `docs/superpowers/specs/2026-11-11-phase-4.1-parity-catalogue-and-harness-design.md`

## Global Constraints

- ArchUnitNET is pinned at exactly `TngTech.ArchUnitNET` `0.13.2`, the core package, not the xUnit adapter, and is referenced only by `tests/Ariadne.NET.Parity.Tests`.
- The test project references `Microsoft.Build.Framework` `17.14.28` with `ExcludeAssets="runtime"`, like every Workspaces consumer in this repo, and is added to `src/Ariadne.NET.slnx`.
- Fixture projects target `net10.0` and live under `tests/fixtures/archunit-parity/`; `tests/fixtures/Directory.Build.props` stays empty.
- Namespaces per case: `Parity.<Kind>.Clean` / `Parity.<Kind>.Broken` (positive), `Parity.<Kind>.NotClean` / `Parity.<Kind>.NotBroken` (negative); helper targets in `Parity.<Kind>.Target`.
- Pack rule ids: `PARITY-<KIND>` and `PARITY-<KIND>-NOT`, with `<KIND>` the upper-cased kind folder name.
- Catalogue ids: kebab-case, prefix `p-` predicate, `c-` condition, `s-` slices, `x-` combinators; a case id is the row id plus an optional `:not`.
- Catalogue statuses, exactly: `covered`, `gap`, `divergence`, `deferred`, `out-of-scope`, `ariadne-only`.
- Scope decisions from the owner, 2026-11-11: `record` and enum/struct/value-type predicates are `gap` for `4.2`; class immutability is `deferred`; `AdhereToPlantUmlDiagram` is `out-of-scope`; type-level `static` is `ariadne-only` (no 0.13.2 counterpart, no case).
- Fixture code avoids lambdas, async methods, `const` and `nameof` in dependency positions, except in a fixture made for a `Divergences` entry.
- Analyzers run with `TreatWarningsAsErrors`; the build stays at zero warnings. Follow CLAUDE.md conventions: `ConfigureAwait(false)`, explicit `StringComparer`, one type per file.
- Commits are conventional, with no `Co-Authored-By` trailer, no session link and no nested parentheses in bodies.
- Shared VM: one build or test at a time.

## Review Focus

- **A selector that selects too much.** A `p-` case whose Ariadne selector also matches the `Clean` type that depends on `Target` must fail the case, not pass. Pinned in Task 3 (`Clean_flagged_fails_the_case`).
- **Nested and generic types.** `Outer+Inner`, ``Foo`1`` and `Outer<T>.Inner` must compare equal across the tools. Pinned in Task 2.
- **A stale `KnownGaps` entry.** Adding the pack rule for a gap case must fail the run until the entry is deleted. Pinned in Task 3 (`Gap_with_pack_rule_fails`).
- **A stale `Divergences` entry.** When the tools start agreeing on a divergence case, the run must fail. Pinned in Task 3 (`Divergence_that_no_longer_differs_fails`).
- **A pack error or skipped project.** It must fail the case with Ariadne's message, never read as "no violations". Pinned in Task 3 (`Pack_error_fails_with_message`).
