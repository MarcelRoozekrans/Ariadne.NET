# Phase 2.4 Banned Packages, Forbidden APIs and Name Collisions Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A pack can ban packages from a project's resolved package graph (`bannedPackages`), confine APIs by member with a `members` selector key on `forbid` and `allowOnly`, and forbid a type name from being kept in two layers (`uniqueNames`).

**Architecture:** `RuleKind` gains two values and `TargetSelector` gains `Members`; `PackYamlReader` reads the new keys. `uniqueNames` is a solution-wide pass over all type graphs. `bannedPackages` reads `AnalyzedProject.Packages`, which `Ariadne.NET.Workspaces` fills from `obj/project.assets.json`. Member uses become a second edge kind in `TypeGraph`, recorded only when some `members` pattern could match, and `DependencyRuleChecker` evaluates them for rules whose `to` holds `members`.

**Tech Stack:** C# / .NET 10, YamlDotNet 16.3.0, Roslyn 5.9.0, ZeroAlloc.Results, ZeroAlloc.Validation, xunit 2.9.3, FluentAssertions 8.

**Spec:** `docs/superpowers/specs/2026-11-08-phase-2.4-banned-packages-forbidden-apis-name-collisions-design.md`. Also read the 2.2 and 2.3 designs for the selector, exception and merge rules this builds on.

## Global Constraints

- Shared VM: one build or test run at a time, never in parallel. Never run a Native AOT publish locally; the AotSmoke publish runs in CI only.
- `TreatWarningsAsErrors` is on with Meziantou, Roslynator, ErrorProne.NET, Hyperlinq and ZeroAlloc analyzers. Fix warnings, never suppress them.
- YamlDotNet stays at 16.3.0 and Roslyn at 5.9.0. No new package in `src`. `Ariadne.NET.Abstractions` stays AOT-compatible, with no reflection.
- Expected failures return `Result<T, AriadneError>`; argument nulls throw `ArgumentNullException`.
- Globs are ordinal and case-sensitive; package ids match case-insensitively.
- Checks are open-world. Generated code is not a rule subject. Only source types are checked as a dependency source.
- Exit codes keep their meaning: 0 clean, 1 violations, 2 error.
- No breaking change: every commit is `feat` or `test` or `docs`, with no `!`, so no `BEGIN_COMMIT_OVERRIDE` block is needed. After the PR merges, check that the `feat` commits appear in the release-please PR.
- Commits: conventional commits; no `Co-Authored-By` trailer, no session link; no nested parentheses in commit bodies; footer lines under 100 characters. Implement on `feat/phase-2.4-banned-packages-forbidden-apis-name-collisions`, from `ariadne/main` once the design branch `docs/phase-2.4-design` is merged. Push with `git push ariadne HEAD:<branch>`, never to `origin`. Open no PR unless the owner asks.
- Performance: no regression beyond what the phase explains, against `docs/perf/phase-2.1-baseline.md` and the 2.2 note on this repository's solution.

## Review Focus

1. **A banned package id written `FluentValidation`, found in assets as `fluentvalidation`.** Expected: it matches, since NuGet ids are case-insensitive. Test in Task 4.
2. **A package that arrives only through a ProjectReference.** Expected: a violation for the referencing project, with the project hop in the path. Test in Task 5.
3. **An in-process `Validate(pack, compilation)` call with a `bannedPackages` rule and no package list.** Expected: `ArgumentException` naming the project, never a clean report. Test in Task 4.
4. **`SqlCommand.ExecuteReader()` against a pattern naming `DbCommand.ExecuteReader`, and `typeof(SqlCommand)` against `SqlCommand.*`.** Expected: the call is a violation through the override chain; the `typeof` is not a violation. Tests in Tasks 6 and 7.
5. **`Result` against `Result<T>`, a type in both the `for` and `against` sets, and one type seen in two target frameworks.** Expected: arity differs so no collision, a type never collides with itself, and the collision is reported once. Tests in Task 3.

- Test: `tests/Ariadne.NET.Tests/Analysis/MemberEdgeTests.cs` (create), `TypeGraphBuilderTests.cs`

**Interfaces:**
- Consumes: Task 1; the walker's symbol resolution.
- Produces:
  - `internal readonly record struct MemberEdge(INamedTypeSymbol Source, ISymbol Member, SourceLocation Location)`; `TypeGraph.MemberEdges` (`IReadOnlyList<MemberEdge>`).
  - `internal static class MemberNames` with `static IReadOnlyList<string> Chain(ISymbol member)`: the member's `Namespace.Type.Member` name (original definition, nested types joined with `+`, `.ctor` for constructors) followed by the names of everything it overrides or implements, upwards only.

  - A member use is a call (extension calls included), constructor call, property or field read or write, event subscription or method group conversion. A declaration and `nameof` are not uses. Type edges are unchanged.
