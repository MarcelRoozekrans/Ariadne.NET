# Phase 1.4 Publish Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ariadne.NET 0.1.0 on nuget.org as `Ariadne.NET.Abstractions` and `Ariadne.NET`, released by release-please from the public `MarcelRoozekrans/Ariadne.NET` repository, with CI, the ci-baseline@v1 checks, the docs site on Pages and a family-shaped README.

**Architecture:** Port Minos.NET's release setup, trimmed to two packages and without its 0.x refusal: `ci.yml` builds, tests, AOT-publishes, pack-validates and publishes on a tag dispatched by an App-token `release-please.yml`. The security and quality checks are not built here: `baseline-checks.yml` calls `MarcelRoozekrans/ci-baseline/.github/workflows/baseline.yml@v1`, and `ci.yml` uses its `coverage-gate` and `sbom` actions. Tasks 1–9 are code on the branch with Actions off; tasks 10–13 are the history check, going public, the PR and the release, each gated on the user.

**Tech Stack:** .NET 10, MSBuild props, GitHub Actions, release-please v5, NuGet Trusted Publishing, codecov OIDC, ci-baseline v1, Docusaurus, Python 3 for the package inspection.

**Spec:** `docs/superpowers/specs/2026-10-31-phase-1.4-publish-design.md`

## Global Constraints

- Work on `fix/mcp-composite-template` from a worktree; push with `git push -u origin HEAD:fix/mcp-composite-template`. The main worktree has the branch checked out at an older commit.
- Commits: conventional commits, scopes free; no `Co-Authored-By` trailer, no session link, no nested parentheses in commit bodies.
- Build stays at 0 warnings with `TreatWarningsAsErrors`; no `NoWarn`, no `continue-on-error`, no skipped step to turn a check green.
- `dotnet test src/Ariadne.NET.slnx` stays at 474 passing or more; merged line coverage stays at or above 80% (89.4% on 2026-11-03).
- `dotnet pack` gives exactly `Ariadne.NET` and `Ariadne.NET.Abstractions`; the Abstractions nuspec depends only on ZeroAlloc.Results and ZeroAlloc.Validation; `Ariadne.NET` depends on `Ariadne.NET.Abstractions` at exactly the package version.
- Release switch `-p:AriadneRelease=true`; any other build is `<manifest>-local`. Version source is `.release-please-manifest.json` only.
- ci-baseline references are `@v1`, never `@main`. Solution input `src/Ariadne.NET.slnx`.
- Action versions match Minos.NET: `actions/checkout@v7`, `actions/setup-dotnet@v6`, `actions/upload-artifact@v7`, `codecov/codecov-action@v7`, `actions/create-github-app-token@v3`, `googleapis/release-please-action@v5`, `NuGet/login@v1`.
- Nothing pushes to nuget.org except `publish-nuget` on a `v*` tag dispatch. No stored nuget.org API key.
- No repository rename, visibility change or Actions enablement before task 10 has passed and the user has confirmed in task 11.
- No private details from the owner's global CLAUDE.md in anything committed, including the gitleaks private-detail config.

## Review Focus

1. A release pack after a non-release build (`dotnet pack --no-build -p:AriadneRelease=true` after a plain build): the DLLs say `-local` while the package says `0.1.0`. `inspect_packages.py` must reject it. Test in task 4.
2. `.release-please-manifest.json` missing or without a `"."` semantic version: the build must fail naming the file, not build as `1.0.0`. Test in task 3.
3. A dispatch on a tag that differs from the manifest, or a prerelease manifest version: `publish-nuget` must refuse before packing. Check in task 5 by running the refusal script locally with fake `GITHUB_REF_NAME` values.
4. The coverage gate on the Windows leg: ci-baseline v1 fails on non-Linux runners, so the gate step must be conditioned on the ubuntu leg. actionlint does not catch this; task 5 checks the `if:`.
5. Windows path and line-ending assumptions in tests the Linux-only history never ran: the matrix leg is the test. Task 12 fixes failures in code, not by excluding the leg.
