# Phase 4.5 Migration Guide Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A docs-site page, `migrating-from-archunitnet.md`, maps every catalogued ArchUnitNET construct to pack YAML, explains the differences and the switch, and translates Daedalus.NET's architecture tests in full; tests load every YAML block on it and check its catalogue ids and Daedalus map.

**Architecture:** One Docusaurus page. `MigrationGuideSnippetTests` in `tests/Ariadne.NET.Tests/PackSchema/` extracts the page's fenced `yaml` blocks and runs each through `PackSchemaHarness.LoaderAccepts` and `PackSchemaHarness.SchemaErrors`, and checks the Daedalus test map against the worked-example pack. `MigrationGuideTests` in `tests/Ariadne.NET.Parity.Tests/` checks the construct map's catalogue ids against `ParityCatalogue` in both directions.

**Tech Stack:** Docusaurus markdown, .NET 10, xUnit, FluentAssertions, YamlDotNet (already referenced by `Ariadne.NET.Tests`), the Phase 4.1 parity test project.

**Spec:** `docs/superpowers/specs/2026-11-11-phase-4.5-migration-guide-design.md`

## Global Constraints

- The page is `docs-site/docs/migrating-from-archunitnet.md`, front matter `sidebar_position: 7`.
- ArchUnitNET is named at version 0.13.2, as the catalogue pins it.
- Every fenced block with info string `yaml` or `yml` is a complete pack: it contains `schema: 2` and a `name`. C# blocks use `csharp`.
- Construct-map tables have the exact header `| ArchUnitNET | Pack YAML | Catalogue id |`. The Daedalus test map has the exact header `| Daedalus test | Pack rule | Notes |`. Ids and rule ids in those columns are in code font; a cell may hold several, separated by `, `.
- Every catalogue row of `docs-site/docs/archunitnet-parity.md`, whatever its status, appears in exactly one construct-map row.
- The worked example translates Daedalus.NET at commit `1dd470b7` and links it as `https://github.com/MarcelRoozekrans/Daedalus.NET/tree/1dd470b7`. Read the files from that commit only: `gh api "repos/MarcelRoozekrans/Daedalus.NET/contents/<path>?ref=1dd470b7" --jq .content | base64 -d`.
- The Daedalus pack is one standalone schema 2 pack named `daedalus`, layers selected by assembly, rule ids prefixed `DAE-`, no `extends`.
- The Pack rule cell of the Daedalus map holds rule or layer ids of that pack, or exactly `stays in C#` or `not needed`.
- Phase 4.6 owns updating the worked example once Daedalus has switched; this phase does not change the Daedalus repository.
- Analyzers run with `TreatWarningsAsErrors`; the build stays at zero warnings. CLAUDE.md conventions: explicit `StringComparison`, one type per file, `ConfigureAwait(false)`.
- Commits are conventional (`docs:`, `test:`), with no `Co-Authored-By` trailer, no session link and no nested parentheses in bodies.
- Shared VM: one build or test at a time.

## Review Focus

- **A block the extractor skips.** A ```` ```yml ```` fence, or a fence with a title such as ```` ```yaml title="rules.yaml" ````, must still be extracted. Pinned in Task 1 (`Extracts_yaml_and_yml_fences_with_titles`).
- **Zero blocks found.** A renamed page or a changed fence must fail, not pass a theory with no cases. Pinned in Task 1 (`Page_has_yaml_blocks`).
- **A catalogue row the guide forgets.** A row added to the catalogue later must fail the guide test. Pinned in Task 2 (`Every_catalogue_row_is_mapped_on_the_guide`).
- **A Daedalus map that names a rule the pack lacks, or a pack rule no fact maps to.** Pinned in Task 3 (`Daedalus_map_names_only_rules_of_the_pack`).
- **A regex translation that changes meaning.** `^Thalos(\.|$)` must become `Thalos.**`, which matches `Thalos` and `Thalos.X` but not `ThalosX`; the guide must not write `Thalos*`. Checked by the reviewer against `03-rule-schema.md`'s namespace rules in Task 2.
