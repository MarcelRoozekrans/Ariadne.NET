# Phase 2.5 Vacuity Detection Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A rule, component role or layer that selects no type fails the run with `VacuousRule` or `VacuousLayer`, unless the rule or role sets `allowEmpty: true`.

**Architecture:** `RuleDefinition` and `ComponentRoleDefinition` gain `AllowEmpty`, read from YAML and carried through pack merges. A new internal `VacuityRules` pass runs once after the project loop in `ArchitectureValidator.Validate`, reusing `TargetMatcher` and `LayerMap`, and yields solution-level violations without a location. Built-in packs set `allowEmpty: true` on every role.

**Tech Stack:** C#, Roslyn, YamlDotNet 16.3.0, xUnit with FluentAssertions, ZeroAlloc.Validation, Native AOT-safe Abstractions.

**Spec:** `docs/superpowers/specs/2026-11-08-phase-2.5-vacuity-detection-design.md`

## Global Constraints

- Subject side only: `forbid` and `allowOnly` check `from`; `require` and `uniqueNames` check `from`; `to`, `against`, `members` and exceptions are never checked.
- New kinds: `ViolationKind.VacuousRule = 11`, `ViolationKind.VacuousLayer = 12`.
- `allowEmpty` defaults to `false`, is allowed only on rules and `componentRoles` entries, and is a bool.
- Built-in packs: `allowEmpty: true` on every component role, on no rule and on no layer.
- No cascade: a rule or role whose subject resolves only through layers already reported as `VacuousLayer` produces no `VacuousRule`.
- Error text is fixed wording plus the number of projects loaded; tests assert on kind and id, never on text.
- A breaking default: the commit that enables the check is `feat!` with a `BREAKING CHANGE` footer.
- Commit rules: conventional commits, no `Co-Authored-By` trailer or session link, no nested parentheses in commit bodies, every footer line under 100 characters.
- Shared VM: one build or test run at a time, no local AOT publish.
- Push only to remote `ariadne`, never `origin`.

## Review Focus

- A solution where one layer's types are all generated code: the layer is vacuous (generated types are not source types); the message must still name the layer. Test in Task 2.
- A layer that only describes referenced external code (for example EF Core namespaces): not vacuous, because edge targets count. Test in Task 2.
- A type in two layers (overlap): counts for both layers, so no `VacuousLayer` on top of `LayerOverlap`. Test in Task 2.
- A project built for two target frameworks: a rule matching in both is not reported twice, and a rule matching in neither is reported once. Test in Task 3.
- A pack extended by a child pack that retargets a vacuous layer: the retarget fixes the violation. Test in Task 3.

### Task 2: The vacuity pass

**Files:**
- Create: `src/Ariadne.NET/Analysis/VacuityRules.cs`
- Modify: `src/Ariadne.NET/Analysis/ViolationKind.cs` (add `VacuousRule = 11`, `VacuousLayer = 12`, with docs)
- Modify: `src/Ariadne.NET/Analysis/BannedPackageRules.cs` (make `AssemblyOf(AnalyzedProject)` internal; add `bool CompiledRule.SelectsAssembly(string assembly)` that tests `FromAssemblies` only, true when `FromAssemblies` is empty)
- Test: `tests/Ariadne.NET.Tests/Analysis/VacuityRulesTests.cs`

**Interfaces:**
- Consumes: `TargetMatcher.From(TargetSelector, LayerMap)` and `Matches(INamedTypeSymbol)`; `LayerMap.LayersOf`; `TypeGraph.SourceTypes` and `TypeGraph.Edges`; `RoleMatches.Items`; `BannedPackageRules.CompiledRule`.
- Produces: `internal static class VacuityRules` with
  `public static IReadOnlyList<ArchitectureViolation> Check(RulePack pack, LayerMap layers, IReadOnlyList<TypeGraph> graphs, IReadOnlyList<RoleMatches> roleMatches, IReadOnlyList<AnalyzedProject> projects)`.
  Violations have no `Location`. Layer violations: `Kind = VacuousLayer`, `RuleId = layer.Id` (the layer name when the id is empty), `SourceType = layer.Name`, `Because = layer.Because`. Rule violations: `Kind = VacuousRule`, `RuleId = rule.Id`, `SourceType = rule.Id`, `Because = rule.Because`. Role violations: `Kind = VacuousRule`, `RuleId = role.Name`, `SourceType = role.Name`, empty `Because`.

Rules of the pass: a layer is found when `layers.LayersOf(type)` contains it for any source type or any edge target of any graph; a layer with no namespaces and assemblies is never found. A `forbid`, `allowOnly`, `require` or `uniqueNames` rule is found when its `from` matcher matches any source type of any graph. A `bannedPackages` rule with an empty `from.assemblies` is never vacuous, otherwise it is found when a project's assembly name is selected. A role is found when some `RoleMatches.Items` holds it by name. Skip a rule or role with `AllowEmpty`. Skip a rule whose `from` names layers and all of them are in the vacuous set, and a role whose layer is in it. Message wording: rule `Rule '<id>' selects no type: its 'from' selector matches nothing in the <n> project(s) loaded.`; layer `Layer '<name>' covers no type in the <n> project(s) loaded.`; role `Role '<name>' matches no type in layer '<layer>' in the <n> project(s) loaded.` where `<n>` counts distinct project names.

- [x] **Step 1: Write failing tests in `VacuityRulesTests`**, each building a small compilation with the helpers used by `UniqueNameRulesTests` and calling `VacuityRules.Check`: `Forbid_rule_whose_from_matches_no_type_is_vacuous`, `Forbid_rule_whose_to_matches_no_type_is_not_vacuous`, `Allow_empty_silences_a_vacuous_rule`, `Require_rule_and_unique_names_rule_check_from_only`, `Layer_with_no_types_is_vacuous`, `Layer_that_only_selects_referenced_external_types_is_not_vacuous`, `Layer_whose_types_are_all_generated_is_vacuous`, `Type_in_two_layers_counts_for_both`, `Rule_selecting_only_a_vacuous_layer_gets_no_vacuous_rule`, `Role_with_no_matching_type_is_vacuous_unless_allow_empty`, `Role_in_a_vacuous_layer_gets_no_vacuous_rule`, `Banned_packages_with_empty_from_is_never_vacuous`, `Banned_packages_with_from_matching_no_project_is_vacuous`, `Violations_have_no_location_and_the_expected_kinds`.
- [x] **Step 2: Run `dotnet test src/Ariadne.NET.slnx --filter "FullyQualifiedName~VacuityRulesTests"`.** Expected: compile error or FAIL, `VacuityRules` does not exist.
- [x] **Step 3: Add the two kinds and the `BannedPackageRules` changes, then implement `VacuityRules.Check`** as described. Build matchers once per rule, stop scanning a rule at its first match, and make the result independent of graph order.
- [x] **Step 4: Re-run the filter.** Expected: PASS.
