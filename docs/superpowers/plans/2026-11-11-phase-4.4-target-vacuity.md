# Phase 4.4 Target Vacuity Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A `forbid`, `allowOnly` or `uniqueNames` rule can set `requireTarget: true`, and then fails as `VacuousRule` when its target selector matches nothing the loaded solution uses: a declared or referenced type, or a member edge, for `forbid` and `allowOnly`; a declared type for `uniqueNames`.

**Architecture:** `RuleDefinition` gains `RequireTarget`; `PackYamlReader` reads it on the three rule kinds and rejects it elsewhere; `RuleDefinitionValidator` backs that up for packs built in code. `VacuityRules.CheckRules` runs a second, independent pass per rule with `RequireTarget`, using the same `TargetMatcher` the rule's checker uses, over every graph's source types, edge targets and member edges. Schema, docs and a contract test for Phase 4.5 follow.

**Tech Stack:** .NET 10, Roslyn, ZeroAlloc.Validation, YamlDotNet representation model, xUnit, FluentAssertions.

**Spec:** `docs/superpowers/specs/2026-11-11-phase-4.4-target-vacuity-design.md`

## Global Constraints

- `RuleDefinition.RequireTarget`: `bool`, default `false`, with `[JsonIgnore(Condition = JsonIgnoreCondition.WhenWritingDefault)]` as `AllowEmpty` has. YAML key `requireTarget`, a strict boolean read with `OptionalBool`, as `allowEmpty` is.
- `requireTarget` is allowed on `forbid`, `allowOnly` and `uniqueNames` rules only. On any other kind the loader reports, at the key's location: `'requireTarget' applies only to forbid, allowOnly and uniqueNames rules`.
- A target is found when, in any graph of the run: for `forbid` and `allowOnly` with no `members` in `to`, `TargetMatcher.From(rule.To, map).Matches` is true for a source type or an edge target; with `members` in `to`, `TryMatchMember` is true for a member edge; for `uniqueNames`, `TargetMatcher.From(rule.Against, map).Matches` is true for a source type.
- A target not found gives one violation: `Kind = ViolationKind.VacuousRule`, `RuleId` and `SourceType` the rule id, `Because` the rule's `because`, no location, message exactly `Rule '<id>' requires its target, but its 'to' selector matches no type declared or referenced in the <n> project(s) loaded.`, for `uniqueNames` exactly `Rule '<id>' requires its target, but its 'against' selector matches no type declared in the <n> project(s) loaded.`, and for a `to` with `members` exactly `Rule '<id>' requires its target, but no code in the <n> project(s) loaded uses a member its 'to' selector names.` `<n>` is the distinct project count `VacuityRules.Check` already computes.
- The target pass ignores `AllowEmpty`, which is about the subject. It is skipped when `to` names layers only and every one of them is vacuous, as the subject pass skips a `from` that names only vacuous layers.
- Nothing is breaking: no default changes, no shipped pack sets the key. Commits are `feat:`, `test:` or `docs:`, never `feat!`.
- If Phase 4.3 has landed, a `slices` rule is one of the kinds that reject the key; take the reader's rule-kind dispatch as 4.3 leaves it.
- Every new pack key gets a valid and an invalid case in `tests/Ariadne.NET.Tests/PackSchema` and is in `docs-site/static/schema/pack.schema.json`.
- Analyzers run with `TreatWarningsAsErrors`; zero warnings. CLAUDE.md conventions: explicit `StringComparison`, one type per file, `ConfigureAwait(false)`.
- Commit bodies have no nested parentheses; footer lines stay under 100 characters; no `Co-Authored-By` trailer or session link.
- Shared VM: one build or test at a time; no local AOT publish.

## Review Focus

- **A target used only by another project.** The Daedalus case: the Agents project references `Thalos.ISubagentRunner`, the rule's subject never does. Found, no violation. Pinned in Task 2 (`Target_referenced_by_another_project_is_found`).
- **A `to` that names only vacuous layers.** The target pass is skipped and only the `VacuousLayer` is reported, as the roadmap goal says. Pinned in Task 2 (`Target_naming_only_vacuous_layers_is_skipped`).
- **A target that is declared but referenced by nobody.** A source type that matches counts as found; the rule protects a real type. Pinned in Task 2 (`Target_declared_but_unreferenced_is_found`).
- **A `members` target.** It must be looked up in member edges, not type edges, or every member rule with `requireTarget` reads as vacuous. Pinned in Task 2 (`Member_target_is_found_through_a_member_edge`).
- **`allowEmpty` next to `requireTarget`.** An empty subject is excused, an empty target is not; exactly one violation. Pinned in Task 2 (`AllowEmpty_does_not_excuse_the_target`).
- **A preventive rule without the key.** A `forbid` of a namespace nobody uses stays silent. Pinned in Task 2 (`Empty_target_without_requireTarget_is_silent`).

### Task 2: The target pass in `VacuityRules`

**Files:**
- Modify: `src/Ariadne.NET/Analysis/VacuityRules.cs`
- Test: `tests/Ariadne.NET.Tests/Analysis/VacuityRulesTests.cs`

**Interfaces:**

- Produces: no new public names. `VacuityRules.Check` returns, per rule, the subject violation first and the target violation second; its XML doc says so.

- [ ] **Step 1: Write the failing tests** — build graphs from small in-memory sources with the file's existing helpers; every test asserts the exact violation list:
  - `Target_referenced_by_another_project_is_found`: project `Domain` with `N.Domain.Order`, project `Agents` with `N.Agents.Runner` holding a field of `Lib.ISubagentRunner` from a referenced compilation; rule `forbid` from `N.Domain.**` to `types: ["Lib.ISubagentRunner"]` with `requireTarget: true` gives nothing.
  - `Renamed_target_is_reported`: the same with `to: { types: ["Lib.IRenamedRunner"] }` gives one violation, `Kind` `VacuousRule`, `RuleId` and `SourceType` the rule id, `Location` null, message `Rule 'R' requires its target, but its 'to' selector matches no type declared or referenced in the 2 project(s) loaded.`.
  - `Target_declared_but_unreferenced_is_found`: `to: { namespaces: ["N.Agents.**"] }` where nobody references `N.Agents.Runner` gives nothing.
  - `Member_target_is_found_through_a_member_edge`: `to: { types: ["Lib.Api"], members: ["Lib.Api.Call"] }` with `N.Agents.Runner` calling `Call` gives nothing; with the call removed, one violation with the exact `members` message, while `Lib.Api` is still referenced elsewhere.

  - `Empty_target_without_requireTarget_is_silent`: `to: { namespaces: ["Newtonsoft.**"] }`, nobody uses it, no key: nothing.
