# Phase 1.1 Design — Rename to Ariadne.NET

**Date:** 2026-10-31
**Phase:** 1.1
**Surface:** Refactor
**Stage:** phase (one phase, implementation-ready)

## Goal

Every `ArchGov` name in code, packages, CLI and docs becomes Ariadne.NET, while nothing is published yet, so the rename costs a find-and-replace now instead of a breaking change later.

## Intent and scope

Ariadne.NET joins the Cretan family (see `docs/superpowers/specs/2026-10-30-roadmap-design.md`). Packages in the family are named `X.NET.*`. This phase only renames; it changes no behaviour.

**Non-goals:**
- Splitting `Ariadne.NET.Abstractions` out of the engine. That is Phase 1.2.
- Renaming the GitHub repo or the local folder. That is Phase 1.4.
- Shipping the `ariadne` dotnet tool. That is M3.3.
- Rewriting historical `docs/plans/*` or the `docs/planning` history.

**Anti-goal:** a half-renamed state that still builds but fails at runtime, for example built-in packs that can no longer be found because embedded-resource names changed.

## Decisions

Decided with the user:

- **Namespace = assembly = package ID = `Ariadne.NET.*`**, like Rag.NET and Mnemosyne.NET, not short `Ariadne.*` like Minos and Thalos.
- **Final project names now**, so Phase 1.2 does not rename a second time:

  | Old | New |
  |---|---|
  | `src/ArchGov.slnx` | `src/Ariadne.NET.slnx` |
  | `ArchGov.Core` | `Ariadne.NET` |
  | `ArchGov.Host.Mcp` | `Ariadne.NET.Mcp` |
  | `ArchGov.Host.Cli` | `Ariadne.NET.Cli` |
  | `ArchGov.Host.Api` (MCP over HTTP) | `Ariadne.NET.Mcp.Http` |
  | `ArchGov.Core.Tests` | `Ariadne.NET.Tests` |
  | `ArchGov.Host.Mcp.Tests` | `Ariadne.NET.Mcp.Tests` |
  | `ArchGov.Host.Cli.Tests` | `Ariadne.NET.Cli.Tests` |

  Folders are renamed together with the projects. The `ArchGov.Core` PackageId becomes `Ariadne.NET`.
- **User-visible strings:**
  - MCP resource URI `archgov://packs/{name}` → `ariadne://packs/{name}`
  - MCP server key `"archgov"` in the README and docs config examples → `"ariadne"`
  - CLI wording in messages: "Run 'ariadne sync'". The exe keeps its assembly name `Ariadne.NET.Cli` until M3.3.
  - `.architecture/rules.yaml`: rule IDs `ARCHGOV-001`/`002` → `ARIADNE-001`/`002`, author `archgov-team` → `ariadne`
  - Temp-directory prefixes in code and tests: `archgov-*` → `ariadne-*`
  - Docusaurus site title → `Ariadne.NET`; CI workflow solution paths
- **Left alone:** the `.architecture/` folder name (generic, not branded), `docs/plans/*`, the planning history, the repo name.

## Approaches

- **A — Scripted move and replace in a few ordered commits (chosen).** `git mv` the folders, `.csproj` files and the slnx, so history follows the files. Then one ordered text replacement over code, csproj, YAML, workflows and docs: longest names first (`ArchGov.Host.Api` before `ArchGov.Host.`, which comes before `ArchGov.Core`), then the lowercase strings. After that come build, tests and a grep gate. Chosen because nothing is published, so no consumer needs to keep compiling between steps, and the real risks are runtime strings, which A's tests and grep gate cover as well as the other approaches would.
- **B — Roslyn `rename_symbol` per namespace, then text for the rest.** Exact for C# symbols, but most hits are in project files, paths, YAML, docs and strings that Roslyn never sees. Far slower, and the text pass is still needed.
- **C — One project per commit, bottom-up.** Easy to bisect, but every intermediate commit mixes old and new names, and the cross-project `using` lines mean each step repeats the same edits.

## Approach

1. **Move:** `git mv` every `src/ArchGov.*` and `tests/ArchGov.*` folder and its `.csproj` (and `ArchGov.Host.Api.http`) to the new names, and the slnx to `src/Ariadne.NET.slnx`.
2. **Replace** across tracked files, excluding `docs/plans/` and `docs/planning/`, in this order: `ArchGov.Host.Api` → `Ariadne.NET.Mcp.Http`, `ArchGov.Host.` → `Ariadne.NET.`, `ArchGov.Core.Tests` → `Ariadne.NET.Tests`, `ArchGov.Core` → `Ariadne.NET`, `ArchGov.slnx` → `Ariadne.NET.slnx`, then the generated `AddArchGov…` method names (exact replacements follow from what ZInject derives from the new assembly names; `refactor-analysis` confirms them), then `archgov://` and the other lowercase and upper-case strings above, and finally any remaining prose `ArchGov` → `Ariadne.NET`.
3. **Verify:** `dotnet build` and `dotnet test` on the new slnx, then the grep gate, then run the CLI and MCP smoke paths that load built-in packs.
4. **Docs:** README, `CLAUDE.md`, `docs/` (outside the historical folders) and `docs-site/` follow in the same replacement; read them once afterwards for sentences that only made sense under the old name.

**Embedded resources:** pack resource names change from `ArchGov.Core.BuiltinPacks.<name>.yaml` to `Ariadne.NET.BuiltinPacks.<name>.yaml`. `BuiltinPackRegistry.ExtractPackName` takes the segment after the last dot before `.yaml`, so it is unaffected by the prefix. `BuiltinPackRegistryTests` loads every pack and guards this.

## Files / Modules Touched

A starting hint; `refactor-analysis` produces the full list.

- `src/**` and `tests/**`: every project, folder, namespace, `using`, `.csproj` reference and PackageId
- `src/ArchGov.slnx`: renamed and its project paths updated
- `.github/workflows/ci.yml`, `publish.yml`: slnx path
- `.architecture/rules.yaml`: rule IDs, author
- `README.md`, `CLAUDE.md`, `docs/features.md`, `docs/how-it-works*`, `docs-site/docs/**`, `docs-site/docusaurus.config.js`
- `src/ArchGov.Host.Mcp/Resources/PackResources.cs`: resource URI
- `src/ArchGov.Core/RuleLoader/RulePackResolver.cs`: CLI wording in messages

## Tests

- **Unit and integration:** the existing suite (224 Core + 25 Mcp + 9 Cli) passes unchanged apart from renamed namespaces, URIs and temp-directory prefixes.
- **Regression:**
  - `BuiltinPackRegistryTests` loads all 10 built-in packs by name after the resource-name change.
  - `PackResourcesTests` passes with the `ariadne://` URI.
- **Gate:** `git grep -i archgov -- . ':!docs/plans' ':!docs/planning' ':!docs/superpowers'` returns nothing. The excluded folders are historical. The specs folder is excluded because specs, this one included, name the old identifiers on purpose.
- **Warnings:** no new build warnings beyond the roughly 26 that already exist.

## Open Questions

None.

## Risks

| Risk | Impact | Mitigation |
|---|---|---|
| A text replacement in the wrong order produces a wrong name, for example `Ariadne.NET.Host.Api` | Projects don't resolve, or are misnamed | Fixed order, longest first; the build plus a grep for `Ariadne.NET.Host` and `Ariadne.NET.Core` catch leftovers |
| Runtime strings (resource names, MCP URI, ZInject method names) miss the replacement | The build is green but behaviour breaks | The existing pack-loading and PackResources tests, plus the grep gate |
| `obj/` and `bin/` keep stale generated code under the old names | Confusing build errors | Clean `obj`/`bin` before the first build after the move |
| The main worktree still has `fix/mcp-composite-template` checked out | Its local branch falls behind the pushed one | Push from this worktree with `HEAD:fix/mcp-composite-template`; the main checkout fast-forwards when it next pulls |
