## Goal

A pack can say what ArchUnitNET says about a type's shape, as a selector and as a `require` condition, in both polarities: name, kind (including enum, struct, value type and record), accessibility, assignability, base type, interface, attribute, `sealed`, `abstract`, `static` and `nested`. Every `KnownGaps` entry with phase `4.2` is closed.

## Why

Phase 4.1 catalogues ArchUnitNET 0.13.2 and records each kind Ariadne cannot express as a `KnownGaps` entry against a settled ArchUnitNET answer. Most of the type-level gaps have one cause: a selector can *select* by base type, interface and attribute, but `require` can only *demand* a layer, a kind, `internal` and an interface, and nothing can be demanded in the negative. This phase closes those gaps with one vocabulary for both sides, as ArchUnitNET's `That()` and `Should()` share one.

## Decisions

Taken with the owner on 2026-11-11:

- **Shared traits plus `is` and `isNot`.** Selectors gain the trait keys below. `require` gains `is:` and `isNot:`, each taking a selector, so every trait works as a predicate and as a condition. The existing `require` keys `kind`, `accessibility` and `implements` stay exactly as they are, as shorthand, so no existing pack changes its verdict. Nothing in this phase is breaking.
- **Globs only.** Ariadne patterns stay globs. ArchUnitNET's regex methods (`HaveNameMatching`, `HaveFullNameMatching`, `ResideInNamespaceMatching`, `ResideInAssemblyMatching`, `HaveAssemblyQualifiedNameMatching` and their negations) are `out-of-scope` in the catalogue, with the reason that a regex with a glob form is translated by hand; 4.4's guide shows how. `StartingWith`, `EndingWith`, `Containing` and exact names map to globs and are in scope.
- **A static class is `sealed` but not `abstract`.** `sealed: true` matches sealed and static classes, because neither can be derived from, which agrees with ArchUnitNET reading `abstract sealed` from IL. `abstract: true` excludes static classes, as a C# developer expects. That one difference is a `Divergences` entry with a fixture.
- **Traits combine with `layers`** in `for`, `from` and `to`; the other selector keys still cannot.
- **Traits in exceptions.** Added by the owner on 2026-11-11 after the CodeRabbit review of PR #84. An exception takes the eight traits next to `namespaces`, `assemblies` and `types`, so a negative predicate on a list trait is a rule whose exception names the trait: ArchUnitNET's `AreNotAssignableTo(T)` is a `forbid` with an exception `assignableTo: [T]`. Before this, `p-are-assignable-to:not` had no Ariadne form, because an exception could not exclude the subtypes of a type. An exception's keys are AND-ed, as a selector's are, and an exception with only traits is valid. Exceptions already compile to `TypeSelector`, so the engine change is the compile call in `DependencyRuleChecker`, `RequireRules` and `UniqueNameRules`.
- **Attribute arguments and attribute allow-lists are deferred.** `HaveAttributeWithArguments`, `HaveAttributeWithNamedArguments`, `OnlyHaveAttributes` and their predicate forms and negations are `deferred` in the catalogue, with one GitHub issue for them. `HaveAnyAttributes` and `DoNotHaveAnyAttributes` are in scope through `attributes`.

## Approaches considered

- **A — Shared traits on the selector, `is` and `isNot` on `require` (chosen).** One vocabulary. A trait added to the selector is immediately a predicate (`for`, `from`, `to`) and a condition (`is`, `isNot`). The cost is that `kind` / `kinds`, `accessibility` in two places, and `implements` / `is: { interfaces }` overlap; the old keys are documented as shorthand.
- **A' — As A, and make the old keys consistent.** `accessibility` would check every value and `kind` would apply to enums. Rejected: it changes verdicts for existing packs and needs a `feat!` for no parity gain.
- **B — Flat fields on `require`.** `name`, `baseType`, `attribute`, tri-state `sealed` and so on, with `notName`-style negatives, and separate selector keys. Rejected: two vocabularies and many more keys.

## Approach

### Selector traits

`TargetSelector` gains these keys. Like the existing keys, values within one list are alternatives and the keys of one selector are AND-ed; a boolean that is not set does not constrain. They work wherever `baseTypes` works today: the `for` of `require`, the `from` and `to` of `forbid` and `allowOnly`, and the new `is` and `isNot`. They also work in a rule's `exceptions` and in an amendment's `exceptions`, next to `namespaces`, `assemblies` and `types`. They do not work in layer definitions, `uniqueNames` or `bannedPackages`.

**Traits combine with `layers`** (owner, 2026-11-11). In `for`, `from` and `to`, a target may have `layers` together with trait keys, and a type must be in one of the layers and match every trait. `TargetMatcher.From` today rejects `layers` next to any other key; it now allows the trait keys. Mixing `layers` with `namespaces`, `assemblies`, `types`, `baseTypes`, `interfaces` or `attributes` stays a load error. So "every class in Domain must be sealed" is `for: { layers: [Domain], kinds: [class, record] }` with `is: { sealed: true }`.

| Key | Type | Matches |
|---|---|---|
| `names` | list of flat globs | The type's simple name, without namespace, containing types or generic arity. `*Service` matches `OrderService` and `OrderService<T>`. |
| `kinds` | list of `class`, `interface`, `record`, `struct`, `recordStruct`, `enum`, `delegate` | The declared kind, as `RoleRules.ActualKind` reads it, extended with enum and delegate. `struct` does not include `recordStruct`. ArchUnitNET's `AreStructs` is `[struct, recordStruct]`, `AreValueTypes` is `[struct, recordStruct, enum]` and `AreRecord` is `[record]`. |
| `accessibility` | list of `public`, `internal`, `protected`, `private`, `protected internal`, `private protected` | The type's declared accessibility, spelled as role `accessibility` already is. |
| `assignableTo` | list of `types` globs | The type itself, any class in its base chain (`System.Object` included, so `System.Object` selects every class), or any interface it implements or inherits. This is ArchUnitNET's `AssignableTo`, which a selector cannot otherwise express because it cannot OR across `types`, `baseTypes` and `interfaces`. |
| `sealed` | boolean | `true`: a class or record class declared `sealed`, or a `static` class. `false`: any other type. |
| `abstract` | boolean | `true`: a class or record class declared `abstract`. A static class is not abstract. `false`: any other type. |
| `static` | boolean | `true`: a `static` class. ArchUnitNET 0.13.2 has no type-level counterpart, so the catalogue row `c-be-static` stays `ariadne-only`. |
| `nested` | boolean | `true`: a type with a containing type. ArchUnitNET's `AreNestedIn(T)` is `nested: true` plus a `types` glob under `T`. |

`sealed` and `abstract` describe classes, as ArchUnitNET's class predicates do: an interface, struct, enum or delegate is neither, so `sealed: false` matches it. A pack that wants "classes must be sealed" writes `kinds: [class, record]` in `for`, as an ArchUnitNET rule writes `Classes()`.

A selector with only traits is valid and selects something; `TypeSelector.IsEmpty` counts the trait keys. A selector that has a key with an empty list, as today, is a load error.

`CSharpTypeKind` gains `Enum` and `Delegate`, as additive public API in `Ariadne.NET.Abstractions`. The loader accepts them only in `kinds`. The `require` key `kind` and the role key `typeKind` keep their five values and reject the new two. A pack built in code skips the loader, so `ComponentRoleDefinitionValidator` rejects a `TypeKind` of `Enum` or `Delegate` and `RuleRequirementValidator` rejects a `Kind` of either, through a `Must` rule that lists the five values; `[IsInEnum]` alone would accept them. `CodeGeneratorService.Generate` is also called directly, without the validators, so it throws `ArgumentException` for a role whose `TypeKind` is `Enum` or `Delegate`, as it does for a role the pack lacks, and the `ArgumentOutOfRangeException` arm stays for values outside the enum. `RoleRules.ActualKind` stays as it is for roles and the old `kind` key; the `kinds` trait uses a new mapping that adds `TypeKind.Enum` and `TypeKind.Delegate`. Enums and delegates are already source types in the graph (`TypeReferenceWalker` visits their declarations), so no walker change is needed.

`names` matches the innermost simple name: for `Outer.Inner`, `names: ["Inner"]` matches and `names: ["Outer"]` does not. The harness decides whether ArchUnitNET agrees.

### `is` and `isNot`

`require` gains two keys, each taking a selector without `layers` and `members`:

```yaml
rules:
  - id: SHOP-DOMAIN-SEALED
    because: Domain classes are not extension points.
    require:
      for: { namespaces: ["Shop.Domain.**"], kinds: [class, record] }
      is: { sealed: true }
      isNot: { names: ["*Impl", "*Helper"] }
```

- **Every selector key except `layers` and `members` is a condition:** the traits, and also `namespaces`, `assemblies`, `types`, `baseTypes`, `interfaces` and `attributes`. So ArchUnitNET's `ResideInNamespace`, `HaveFullNameEndingWith`, `InheritFrom`-style and `HaveAnyAttributes` conditions are `is` keys, and their negations `isNot` keys. The message is built from one template per key: what the key wanted and what the type has.
- **Each key is its own requirement.** In `is`, the type must match every key: one violation per key it fails. In `isNot`, the type must match none of the keys: one violation per key it matches. Both behave like `require`'s existing keys, which already report one violation per failed requirement. Within one key, values stay alternatives, so `isNot: { names: [A, B] }` means "matches neither A nor B".
- **The new keys apply to every selected type,** enums and delegates included. The old shape keys keep skipping enums and delegates, as documented today.
- **The violation kind is a new `ViolationKind.RequirementNotMet` (13).** Its message names the rule, the type, `is` or `isNot`, the key and what was found, for example `Type 'OrderService' is selected by rule 'SHOP-DOMAIN-SEALED' and should be sealed but is not`, and `... should not have a name matching '*Impl' but is named 'OrderImpl'`. The JSON and SARIF writers and the docs' violation-kind table carry the new value.
- **At least one of `layer`, `kind`, `accessibility`, `implements`, `is` and `isNot` is needed,** extending today's load error.
- **ArchUnitNET's `NotExist`** becomes `require` with `isNot: { types: ["**"] }` and `allowEmpty: true`: every selected type matches `**`, so each one is a violation, and an empty selection is not vacuous.

`RuleRequirement` gains `Is` and `IsNot` (`TargetSelector?`). `RequireRules` compiles them once per rule into one `TypeSelector` per key, so a failure names its key without re-matching.

### Loader, JSON Schema and docs

- `PackYamlReader` adds the keys to its closed key sets with the same strictness: unknown values in `kinds` and `accessibility` list the valid ones, booleans must be `true` or `false`, and `names` uses the flat glob validation. `TargetSelectorValidator` and `RuleRequirementValidator` get the matching member rules as the backstop for packs built in code.
- `RulePackReferenceCheck` needs no change: traits name no layer or role. `RulePackMerger` passes selectors through whole and needs none either.
- `RulePackDescriber`, which describes rules for `ariadne rules` and the MCP tools, describes the new selector keys and `is` / `isNot` the way it describes `baseTypes` and `interfaces` today.
- `docs-site/static/schema/pack.schema.json` gains the keys, and `tests/Ariadne.NET.Tests/PackSchema` gains a valid and an invalid case per new key, as CLAUDE.md requires.
- `03-rule-schema.md`'s Selectors section documents the traits. `rule-types.md`'s Require section documents `is`, `isNot`, the per-key reporting and the `NotExist` idiom, and its violation-kind table gets `RequirementNotMet`. `docs/features.md` is not updated (issue #57).

### Closing the parity gaps

For every `KnownGaps` entry with phase `4.2`, add the rule with the case's `AriadneRuleId` to `tests/fixtures/archunit-parity/<Kind>/.architecture/rules.yaml`, delete the entry, and set the catalogue row's status to `covered`, or to `divergence` with a `Divergences` entry when the harness shows an IL-versus-source difference. 4.1's `Gap_has_no_ariadne_rule` fails for any entry whose rule was added and not deleted, so the order is forced.

- Predicate cases keep 4.1's shape: a `forbid` from the trait selector to `Parity.<Kind>.Target.**`. Negative predicates (`AreNot…`) use `false` for booleans. For list traits they use an exception that names the trait, such as `assignableTo: [T]` for `AreNotAssignableTo(T)` or `names: ["*Service"]` for `DoNotHaveNameEndingWith("Service")`, or move the negation into the trait, such as `kinds` listing every other kind. The builder picks per case and notes it in the catalogue's Ariadne column.
- Condition cases use `require` with `is` for the positive and `isNot` for the negative case.
- **The static-class divergence:** the `c-be-abstract` and `p-are-abstract` fixtures each get a static class in their `Broken` namespace. ArchUnitNET treats it as abstract and Ariadne does not, and the `Divergences` entry records exactly that type, the reason, and that a C# developer expects Ariadne's answer. The `c-be-sealed` and `p-are-sealed` fixtures also get a static class, to prove the two tools agree there.
- When the harness shows a difference this design did not foresee, triage it as 4.1's "Measuring today's kinds" says: an IL-versus-source difference is a `Divergences` entry, a small bug is fixed with a test, and anything larger is a `KnownGaps` entry with phase `unplanned` and an issue, reported to the owner.

At the end of the phase `KnownGaps.Entries` has no entry with phase `4.2`, and a test asserts it.

This phase is built after 4.1 has merged, so the exact list of entries is read from `KnownGaps.cs` on `main` when the phase starts. The plan therefore closes them as a loop over that list, grouped by trait, with the names fixed by the 4.1 plan's Task 3, and its first task runs the guard check that pins those names.

## Tests

- **Unit, selector:** each trait matches and rejects on source types: nested, generic, static, record, record struct, enum, delegate, each accessibility; `assignableTo` on self, an indirect base, an inherited interface and `System.Object`; `sealed` and `abstract` on a static class.
- **Unit, `require`:** `is` and `isNot` report one violation per failed key with the new kind and message; an enum is checked by `is`; old keys still skip enums; `NotExist` idiom with `allowEmpty`.
- **Unit, exceptions:** an exception `assignableTo: [Base]` exempts `Base` and every subtype from a `forbid` and leaves an unrelated type flagged; a trait-only exception loads; the same holds for `require`.
- **Unit, code-built packs:** `ComponentRoleDefinitionValidator` reports `TypeKind` for `Enum` and `Delegate`, `RuleRequirementValidator` reports `Kind`, and `CodeGeneratorService.Generate` throws `ArgumentException` naming the role for an `Enum` role.
- **Unit, loader:** each new key parses, also in `exceptions`; an unknown `kinds` or `accessibility` value, a non-boolean trait, `layers` inside `is`, and `enum` in `kind` or `typeKind` are load errors with locations; a trait-only selector is accepted.
- **Schema conformance:** a valid and an invalid case per key in `PackSchema`.
- **Parity:** every 4.2 case passes `ParityTests.Case_agrees`, the static-class divergence is recorded, and a new fact asserts no `KnownGaps` entry has phase `4.2`.
- **Regression:** the whole solution, including the repo's own `ariadne validate` in CI, stays green with no change to existing verdicts.

## Risks

| Risk | Impact | Mitigation |
|---|---|---|
| ArchUnitNET's `Name` for a nested or generic type differs from the simple name Ariadne matches | Name cases disagree | The harness decides. A naming difference from IL becomes a `Divergences` entry with the two spellings; a fixture never hides it. |
| Records, record structs or delegates look different in IL (for example a record class's `IsSealed`, a delegate counted as a class) | Kind or sealed cases disagree | Fixtures include one record and one record struct per kind-related case. Each difference is a fix, a divergence or an `unplanned` gap, never filtered. |
| A selector with only traits changes vacuity or `IsEmpty` semantics elsewhere | A rule with `for: { sealed: true }` is treated as empty, or every rule is | Unit tests for `IsEmpty` with each trait alone, and the existing vacuity tests stay green. |
| The `TypeSelector` hot path slows down | The check on large solutions gets slower | Trait checks are field reads on the symbol and run after the cheap glob checks; compare the repo-pack check against `docs/perf/phase-2.5-baseline.md` and note the result in the PR body. |
| 4.1 lands with catalogue statuses that differ from the list above | 4.2 closes the wrong set | 4.2 works from `KnownGaps.Entries` with phase `4.2` as they are on `main`, and the guard check in the 4.1 plan pins the names it relies on. |
