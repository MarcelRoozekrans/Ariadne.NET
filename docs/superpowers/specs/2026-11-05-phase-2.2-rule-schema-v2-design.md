# Phase 2.2 Design — Rule schema v2

**Date:** 2026-11-05
**Milestone:** 2 — Rule engine v2
**Phase:** 2.2
**Surface:** Backend
**Inputs:** `docs/superpowers/specs/2026-11-04-milestone-2-design.md` (decisions and calls), the Daedalus appendix in `docs/superpowers/specs/2026-10-30-roadmap-design.md`, the engine on `main` at `e6d41c0` after Phase 2.1, and the owner's answers of 2026-11-05.

## Intent

A pack becomes a strict, versioned contract. It says which types each layer covers through namespace globs and assembly names, not by a single namespace segment. It can forbid a dependency, or allow only named users of one, and it explains each rule with a `because` that every violation repeats. A pack that loads is a pack whose every line was read: a typo is an error with a file, line and column, not a silently dropped key.

After this phase a v2 pack can express and enforce the 18 Daedalus tests that are layer dependencies, `forbid` on external code, and `allowOnly` with exceptions. Placement, typed code-feature rules, banned packages, name collisions and vacuity follow in phases 2.3 to 2.5, and each adds its own keys to the same schema.

## Where things stand

Read from `main` at `e6d41c0`:

- `YamlDocument` deserializes with YamlDotNet's reflection deserializer and `IgnoreUnmatchedProperties`, so an unknown key is dropped. Errors come from `YamlFailure.ToError`, first error only.
- `RulePack` in `Ariadne.NET.Abstractions` has `Name`, `Version`, `Author`, `Extends`, `Layers`, `ComponentRoles`, `CodeFeatureRules` and `NamingConventions`. `LayerDefinition` is a name, a description and `AllowedDependencies`. `CodeFeatureRuleDefinition.AppliesTo` is an untyped dictionary that nothing evaluates.
- Phase 2.1's engine (`Analysis/`) builds a `TypeGraph` from a `Compilation`. `V1LayerMap` assigns a type to a layer when one namespace segment equals the layer name, so the dotted layers of `modular-monolith` match nothing. `V1LayerRules` reports `DependencyNotAllowed`; `V1RoleRules` carries the hard-coded `CODE-001` and `CODE-002` checks. `ArchitectureViolation` already has `RuleId`, `Kind`, `Because`, `Target`, `Location`, `ReferenceCount` and `TargetFrameworks`; `Because` is empty today.
- `RulePackMerger` unions layers by name, lets the last role with a name win, and turns an override of a `locked` code-feature rule into a warning.
- Readers of the pack model: `RulePackReferenceCheck`, `RulePackMerger`, `LayerInferenceEngine`, `CodeGeneratorService`, `WorkspaceOrchestrator`, `GenerateOrchestrator`, `Linter`, CLI `rules`, `init` and `generate`, MCP `get_rules` (`RuleTools`) and `TemplateTools`.
- `.architecture/rules.yaml` extends `clean-architecture` but defines its own `Core`, `Host` and `Tests` layers, and two `codeFeatureRules` that nothing enforces.
- Only `Ariadne.NET.Abstractions` is marked `IsAotCompatible`; the YAML loader lives in `Ariadne.NET`.

## Goals

1. A v2 pack format with a required `schema: 2`, selectors on layers, a `rules:` list with `forbid` and `allowOnly`, per-rule exceptions, and a required `id` and `because` on every layer and rule.
2. A strict loader that rejects unknown keys, missing required keys and wrong value types, and reports every problem in the file in one pass with `file:line:column`.
3. `extends` with the merge rules below, enforced as errors.
4. The engine enforces layer dependencies, `forbid` and `allowOnly` on the 2.1 type graph, and every violation carries the rule's id and `because`.
5. The 10 built-in packs and `.architecture/rules.yaml` are migrated, and every reader of the pack model moves to v2. `CodeFeatureRuleDefinition` is deleted.
6. A fixture solution shaped like Daedalus holds one rule of each type this phase enforces, in a clean and a broken variant.

## Non-goals

- Placement by role, typed code-feature rules, and enforcing `CODE-001`/`CODE-002` from the pack: phase 2.3. Until then the hard-coded role checks from 2.1 stay, now reading role layers through the v2 layer map.
- Base-type, interface and attribute selectors: phase 2.3, with placement, which is where they are first needed.
- Member-level `forbid` targets, banned packages and name collisions: phase 2.4.
- Vacuity detection and `allowEmpty`: phase 2.5. A selector that matches nothing is not an error in this phase.
- The JSON Schema and the full pack reference: phase 2.6.
- Validating `namingConventions`.
- Isolating modules from each other. `modular-monolith`'s `**.Core.**` puts every module's Core in one layer, so `Orders.Core` to `Billing.Core` is allowed. Its layers match for the first time in v2, which is already more than v1 did. A module-isolation rule type is tracked in #32 for a later phase.

## Anti-goals

- A v1 compatibility loader or a converter shipped in the product. v2 is a clean break; the loader names the problem and points at the docs.
- Keys in the schema that no engine reads. Each key added in 2.2 is enforced in 2.2.
- Warnings where the milestone asks for errors. A merge conflict or an amended `locked` rule fails the load.

## Approaches considered

### Loader

- **A. Node walk over YamlDotNet's representation model (chosen).** Parse to `YamlStream`, walk the nodes by hand into the v2 types, with an allow-list of keys per mapping. Every node has a start mark, so every error has a line and column, and all errors are collected in one pass. A misspelled key gets a did-you-mean. Cost: a hand-written mapper of a few hundred lines. Chosen because the error messages are the user-facing product of strict loading, and agents in Milestone 5 read them too.
- **B. Strict YamlDotNet deserializer.** Remove `IgnoreUnmatchedProperties`. Smallest change, but it stops at the first error, its messages name C# properties, `forbid`/`allowOnly` need custom converters, and a missing `because` still needs a separate pass.
- **C. Validate against a JSON Schema first.** One schema for loader and editors, but it pulls 2.6 forward, adds a library, and loses line numbers in the YAML-to-JSON step.

### Pack shape

- **Layers plus a rules list (chosen).** A layer declares its selectors, its `allowedDependencies`, an `id` and a `because`. Everything else is an entry in `rules:`. Short packs; a layer violation reports the layer's id and `because`.
- **Everything is a rule.** Layers are only named selectors and every layer-to-layer constraint is its own rule. Maps one-to-one to Daedalus tests, but a four-layer pack needs about six rules where v1 needed four lists.
- **Both.** `allowedDependencies` as shorthand that expands to rules. Two ways to say one thing.

### `extends`

- **Retarget selectors only (chosen).** A child may replace an inherited layer's selectors, add rules, and add exceptions to inherited rules that are not `locked`. It cannot change an inherited layer's `allowedDependencies` or `because`.
- **Full override** lets a child quietly loosen the architecture it claims to follow. **No changes** makes built-in packs unusable for any solution that does not follow their namespace naming.

### Scope against 2.3

- **Roles strict now, code-feature rules later (chosen).** `componentRoles` move to v2 with their current fields, strictly typed. `codeFeatureRules` is removed and comes back typed in 2.3.
- **Design every key now** would ship keys without an engine behind them for a phase.

## The v2 pack

```yaml
schema: 2
name: daedalus
version: "1.0.0"
author: daedalus-team
extends:
  - builtin://clean-architecture

layers:
  - name: Domain                     # inherited; only selectors may change
    assemblies: [Daedalus.Domain]
  - name: Agents
    id: DAEDALUS-LAYER-AGENTS
    assemblies: [Daedalus.Agents]
    allowedDependencies: [Domain, Application]
    because: Agents orchestrate use cases; they never reach into the API.

rules:
  - id: DAEDALUS-NO-EFCORE-IN-DOMAIN
    forbid:
      from: { layers: [Domain] }
      to: { namespaces: ["Microsoft.EntityFrameworkCore.**"] }
    because: Persistence belongs to Infrastructure.
  - id: DAEDALUS-RAGNET-ONLY-IN-AGENTS
    allowOnly:
      to: { assemblies: ["Rag.NET*"] }
      from: { layers: [Agents] }
    because: Retrieval is an agent concern.
  - id: DAEDALUS-SUBAGENT-RUNNER
    allowOnly:
      to: { types: [Daedalus.Application.Agents.ISubagentRunner] }
      from: { types: [Daedalus.Application.Agents.SubagentRunExecutor] }
    exceptions:
      - types: [Daedalus.Infrastructure.Agents.SubagentRunner]
        because: The implementation must name its interface.
      - types: [Daedalus.Api.Composition.AgentRegistration]
        because: DI registration wires the interface to its implementation.
    because: Subagents start only through the executor, which records the run.

componentRoles: [...]          # as v1, strictly typed
namingConventions: {...}       # as v1, not validated
```

### Top level

| Key | Required | Meaning |
|---|---|---|
| `schema` | yes | Must be the integer `2`. Absent or any other value fails the load with a message that names v2 and links the docs page. |
| `name` | yes | Pack name. |
| `version`, `author` | no | The pack author's own metadata, as in v1. Unrelated to `schema`. |
| `extends` | no | List of pack references, as in v1 (`builtin://…` and relative paths). |
| `layers` | no | List of layers. |
| `rules` | no | List of `forbid` and `allowOnly` rules. |
| `componentRoles` | no | As v1: `name`, `layer`, `typeKind`, `requiresInterface`, `interfaceRole`, `accessibility`, `description`, `alternativeNames`. `layer` must name a layer of the merged pack. |
| `namingConventions` | no | As v1: `namespace`, `filePath`. |

`codeFeatureRules` is not a v2 key in this phase; a pack that has it fails with "unknown key", plus a hint that typed code-feature rules arrive in a later release.

### Layers

| Key | Required | Meaning |
|---|---|---|
| `name` | yes | Unique in the merged pack. Referenced by `allowedDependencies`, rule targets and roles. |
| `id` | yes, unless the entry retargets an inherited layer | The rule id that layer-dependency violations carry. Unique across all layer and rule ids in the merged pack. |
| `because` | yes, same exception | Why the layer may depend only on what it lists. |
| `description` | no | Free text. |
| `namespaces`, `assemblies` | at least one, same exception | Selectors; see below. |
| `allowedDependencies` | no, default `[]` | Layer names this layer may depend on. |

Dependency check, open-world as the milestone set it: for each edge from a type in layer L to a type in layer M, with M ≠ L and M not in L's `allowedDependencies`, report `DependencyNotAllowed` with L's `id` and `because`. Edges to a type that no layer covers are not checked. A type in no layer is not a subject.

A type that two layers both cover is reported once as `LayerOverlap` naming both layers, and is treated as in no layer for the dependency check, so one pack mistake does not cascade into a list of false dependency violations. There is no precedence rule such as v1's "innermost segment wins": with built-in globs like `**.Domain.**`, a namespace such as `Shop.Application.Domain` is an overlap, and the pack author resolves it by retargeting a layer. `LayerOverlap` fails `validate` like any other violation. Overlaps are reported for source types, with their declaration as location; a metadata type covered by two layers is reported once, without a location, when it is the target of a checked edge.

Layer selectors apply to metadata types as well as source types, so a layer can cover external code such as Thalos by assembly.

### Rules

Each entry has exactly one of `forbid` or `allowOnly`.

| Key | Required | Meaning |
|---|---|---|
| `id` | yes | Unique across all layer and rule ids. |
| `because` | yes | Repeated on every violation. |
| `description` | no | Free text. |
| `forbid` | one of | `{ from: <target>, to: <target> }`: no type in `from` may depend on a type in `to`. Reported as `ForbiddenDependency`. |
| `allowOnly` | one of | `{ to: <target>, from: <target> }`: a type in `to` may be depended on only by types in `from`, or by types in `to` itself. Any other source is reported as `DependencyNotPermitted`. |
| `exceptions` | no | List of selectors, each with a required `because`. A source type that an exception matches is exempt from the rule. |
| `locked` | no, default `false` | A child pack cannot add exceptions to this rule. |

A **target** is either `{ layers: [...] }` or a selector made of `namespaces`, `assemblies` and `types`. Mixing `layers` with selector kinds in one target is a load error.

Both rule kinds apply regardless of layers: a `forbid` between two types of the same layer still fires. Violations are aggregated as in 2.1, one per source type and target type with a reference count, and they carry the rule's `id`, `because`, and the `because` of nothing else.

### Selectors

A selector has up to three lists. Values within one list are alternatives (any may match). When a selector has more than one list, a type must match each list it has. So `{ assemblies: [Daedalus.Agents], namespaces: ["**.Api.**"] }` means "the Api namespaces inside the Agents assembly". A selector with no lists is a load error.

- **`namespaces`** match a type's containing namespace, split on `.` into segments. `**` as a whole segment matches zero or more segments. `*` inside a segment matches any characters within that segment, so `*` alone matches exactly one segment and `EntityFrameworkCore*` matches a segment starting with that text. `**.Domain.**` matches `Domain`, `Shop.Domain` and `Shop.Domain.Orders`. Matching is ordinal and case-sensitive, like C# names; v1's case-insensitive layer matching is gone, and the migration note says so.
- **`assemblies`** match the type's containing assembly name as one string, where `*` matches any characters, dots included. `Rag.NET*` matches `Rag.NET` and `Rag.NET.Abstractions`.
- **`types`** match the type's full name, namespace and containing types joined with `.`, without generic arity or type arguments, using the namespace glob rules with the type name as the last segment. `Daedalus.Application.Agents.ISubagentRunner` names one type; `**.I*Repository` names every repository interface. A generic type `Foo<T>` is matched as `Foo`.

Layer entries accept `namespaces` and `assemblies` only. A layer of named types has not been needed.

### `extends` and merging

Packs are merged parent first, in `extends` order, then the child.

- **Layers.** A child layer whose `name` matches an inherited layer may only set `namespaces` and `assemblies`; together they replace the inherited selectors. Any other key on such an entry is a load error that names the inherited pack. A new name adds a layer.
- **Rules.** A child entry whose `id` matches an inherited rule may only carry `exceptions`, which are appended. Any other key, or an amendment of a `locked` rule, is a load error. A child entry with an unknown `id` must be a full rule.
- **Conflicts.** Two parents that define the same layer name or rule id fail the load, naming both packs. There is no last-one-wins. This applies to template composition too: `clean-architecture+cqrs` works because `cqrs` defines roles only, while `clean-architecture+microservice` fails because both define `Domain`, `Application` and `Infrastructure`. A solution picks one base architecture and retargets it.
- **Role-only packs.** A pack with roles and no layers, such as `cqrs` or `ddd-tactical`, loads on its own. A role's `layer` is checked against the merged pack only once that pack has at least one layer, as in v1.
- **Roles and naming conventions** merge as in v1: the last role with a name wins, the last pack's `namingConventions` wins.
- **Ids** are unique across layers and rules of the merged pack.

### Load errors

The loader collects every problem in the file and in the merged result, then fails once. Each problem has the file path, line and column from the node's start mark, and a message in pack terms, not C# terms:

```text
.architecture/rules.yaml:12:5: unknown key 'allowedDependancies' in layer 'Core'; did you mean 'allowedDependencies'?
.architecture/rules.yaml:20:3: rule 'NO-EFCORE' has no 'because'
.architecture/rules.yaml:1:1: 'schema: 2' is required; this looks like a v1 pack. See https://…/packs/v2
```

The result is an `AriadneError` with code `Invalid`, a one-line `Message` that gives the count, and the list in `Detail`, one problem per line. Did-you-mean is offered when an allowed key is within edit distance 2.

Checks done after parsing: unknown keys, missing required keys, wrong value types and empty selectors (parse); then references to unknown layers in `allowedDependencies`, targets and roles, duplicate names and ids, merge violations (merge). The existing `ZeroAlloc.Validation` attributes on the model stay as a backstop for callers that build a `RulePack` in code.

## Engine changes

- `V1LayerMap` becomes a selector-based `LayerMap` with the per-symbol cache it has today. `V1LayerRules` becomes `LayerRules` and fills `Because`. New `ForbidRules` and `AllowOnlyRules` run over the same edges. `V1RoleRules` reads role layers through `LayerMap` and keeps `CODE-001`/`CODE-002` until 2.3.
- `ViolationKind` gains `ForbiddenDependency`, `DependencyNotPermitted` and `LayerOverlap`.
- Selector matching compiles each glob once per check run. The hot path is per-edge, so matching a type is cached per symbol, as `V1LayerMap` does. The Phase 2.1 perf baseline in `docs/perf/phase-2.1-baseline.md` is re-measured; a regression is explained in the PR.

## Migration

- **Abstractions** (breaking, `feat!`): `RulePack` gains `Schema` and `Rules` and loses `CodeFeatureRules`. `LayerDefinition` gains `Id`, `Because`, `Namespaces` and `Assemblies`. New `RuleDefinition`, `TargetSelector` and `RuleException`. `CodeFeatureRuleDefinition` is deleted. The AotSmoke test keeps covering the model.
- **Built-in packs:** all 10 get `schema: 2`, an `id` prefix per pack (for example `CA-` for `clean-architecture`), a `because` per layer written for that architecture, and selectors of the form `**.<Segment>.**`. `modular-monolith`'s dotted layers get `**.Public.**`, `**.Core.**` and `**.Infrastructure.**` style selectors, so they match for the first time. `codeFeatureRules` entries are removed.
- **`.architecture/rules.yaml`:** a standalone pack, no `extends`, selected by assembly: `Core` = `Ariadne.NET.Abstractions`, `Ariadne.NET`; `Workspaces` = `Ariadne.NET.Workspaces` → Core; `Host` = `Ariadne.NET.Cli`, `Ariadne.NET.Mcp`, `Ariadne.NET.Mcp.Http` → Core, Workspaces; `Tests` = `*.Tests`, `Ariadne.NET.AotSmoke` → all. `ARIADNE-001`/`002` become a `forbid` from Core to the host assemblies and to `Microsoft.AspNetCore.**` and `System.CommandLine.**`. CI runs `ariadne validate` on the repo's own solution with this pack.
- **Linter removed:** `Validation/Linter.cs` with `ILinter`, `LintResult` and `LintViolation`, CLI `lint` and MCP `lint_source` are deleted. They are a second syntax-only directory scan that matches one namespace segment to a layer name, which v2 selectors replace, and the milestone keeps one engine. This is a breaking change to the CLI and the MCP tool list.
- **Readers:** `RulePackReferenceCheck` and `RulePackMerger` implement the rules above. CLI `rules` prints layers with their selectors and the rule list. CLI `init` writes a v2 starter pack. MCP `get_rules` returns the merged `rules` list in place of `codeFeatureRules`; `TemplateTools` returns v2 layers. `LayerInferenceEngine`, code generation and `WorkspaceOrchestrator` read role layer names and naming conventions, which keep their shape.
- **Docs:** the docs-site pack page gets a short v2 section and a v1-to-v2 migration note, enough for 0.3.0 users. The full reference is 2.6.

## Testing

- Loader: one test per error class, asserting the message and the line and column; a file with several errors reports all of them; every built-in pack loads.
- Merge: retarget, appended exceptions, locked amendment, two-parent conflict, unknown-id amendment.
- Selector matching: unit tests for `*`, `**`, in-segment wildcards, assemblies with dots, nested and generic types.
- Engine: a `tests/fixtures/daedalus-shape` solution with clean and broken variants for a layer dependency, `forbid` on an external namespace, `forbid` on an external assembly, `allowOnly` on an external assembly, and `allowOnly` on a type with two exceptions. Each broken variant fails with that rule's id and `because`. Later phases add their rule types to the same fixture.
- AotSmoke, and the perf baseline comparison.
