# Phase 4.8 Design — Attribute arguments and attribute allow-lists

**Date:** 2026-11-15
**Phase:** 4.8
**Surface:** Backend
**Stage:** phase (one phase, implementation-ready)
**Status:** approved 2026-11-15

## Goal

Packs can select and require types by the arguments of an attribute applied to them, and can say that a type carries no attribute outside a given set. The six #95 catalogue rows then leave `deferred` with harness cases, and #95 closes.

## Intent

The 2026-11-15 Milestone 4 re-audit failed on criterion 3. Nine type-level catalogue rows are `deferred`, but the criterion allows deferral for member-level kinds only. The owner chose gap phases over amending the criterion. This phase takes the six #95 rows and phase 4.9 takes the three #96 rows. Criterion 3 allows `out-of-scope` for custom predicates only, so each row needs a pack form and a harness case.

- **Goal:** one pack form per ArchUnitNET method family of the six rows, valid in rule targets, in `is`/`isNot` and in exceptions, with a harness case per row and polarity that agrees with ArchUnitNET 0.13.5, or a `Divergences` entry where the tools differ on purpose.
- **Non-goals:** inherited attributes, since both tools read only the attributes applied directly to the type. Member-level attributes, which #94 tracks. Attribute arguments in `layers` definitions, `implements` or role definitions. Glob matching of argument values. A `null` argument value.
- **Anti-goal:** a key whose meaning differs between a selector, a condition and an exception. A second meaning of `attributes`.

## Approaches

The owner picked approach 1 on 2026-11-15.

1. **Two new additive selector keys (chosen):** `attributeArguments` and `onlyAttributes`. They are valid wherever `attributes` is valid. `TargetSelector.Attributes` keeps its type, so the change is a `feat` and not a breaking change.
2. **A mixed `attributes` list,** where an entry is a glob or a mapping. One key for users, but `TargetSelector.Attributes` and `RuleException.Attributes` would change from `IList<string>` to a new type. That breaks the public Abstractions API.
3. **C#-like strings** such as `'Shop.RouteAttribute("api/orders", Version = 2)'`. Short, but it needs its own parser, awkward YAML quoting and weaker schema validation.

## How ArchUnitNET 0.13.5 matches

Read from `ObjectPredicatesDefinition.cs` and `AttributeExtensions.cs` at tag `0.13.5`:

- `HaveAttributeWithArguments(A, values)` holds when some instance of `A` on the type contains **every** given value among **all** its argument values. Position and order are ignored, and the values of named arguments count too. A `System.Type` value is resolved to the architecture's type and compared as a type.
- `HaveAttributeWithNamedArguments(A, pairs)` holds when some instance of `A` contains every given `(name, value)` pair among its named arguments.
- `HaveAnyAttributesWithArguments` and `HaveAnyAttributesWithNamedArguments` are the same without the attribute class: any attribute instance may match.
- `DoNot…` and `Not…` are not plain negations. The measurement against 0.13.5, now in the fixtures in `tests/fixtures/archunit-parity` shows that `DoNotHaveAttributeWithArguments`, `DoNotHaveAnyAttributesWithArguments`, `NotHave…WithArguments` and the `…NamedArguments` variants reject a type when any one of the given values or pairs appears on any attribute instance, or on any instance of that attribute for the `…AttributeWith…` forms. The positive forms need all values on one instance. A pack says the negative form with one `attributeArguments` entry per value or pair, with `attribute` for the `…AttributeWith…` forms, in an exception or in `isNot`.
- `OnlyHaveAttributes(set)` holds when no attribute class on the type is outside the set. A type with no attributes holds. `OnlyHaveAttributesThat()` takes the set from a predicate.
- Roslyn's `GetAttributes()` on a source type returns only the attributes written in source, while a metadata type shows the attributes the compiler emitted, such as `NullableContextAttribute` and `NullableAttribute` in a project with `<Nullable>enable</Nullable>`. This design first assumed that ArchUnitNET counts those for `OnlyHaveAttributes`. a measurement of ArchUnitNET 0.13.5 shows it does not, so the `only` rows are `covered`.

## Decided behaviour

### `attributeArguments`

A list of entries. Each entry matches one attribute instance applied directly to the type:

```yaml
attributeArguments:
  - attribute: "Shop.RouteAttribute"   # optional dotted glob over the attribute class's full name
    arguments: ["api/orders", 2]       # every value must equal some argument value of that instance
    named: { Version: 2, Obsolete: false }  # every pair must equal a named argument of that instance
```

- **An empty `named` mapping** is rejected at load and by the schema (`minProperties: 1`), as an entry with neither `arguments` nor `named` is.
- **Within an entry:** `attribute`, `arguments` and `named` are AND-ed, and all three apply to the **same** instance. An entry without `attribute` matches any attribute class, as `HaveAny…` does. An entry needs `arguments` or `named` or both. An entry with neither is rejected at load with a message that points to `attributes`.
- **Across entries:** any one entry may match, as values do in every selector list.
- **`arguments`:** as in ArchUnitNET, each value must equal at least one argument value of the instance: a constructor argument or the value of a named argument, in any position. Duplicates need no multiplicity.
- **`named`:** a mapping from the property or field name, compared ordinal and case-sensitive, to a value. Each pair must equal a named argument of the instance.
- **Value equality:** a YAML scalar is compared with the attribute's `TypedConstant`:
  - string: ordinal text.
  - char: a one-character text.
  - bool: YAML `true` or `false`, case-insensitive.
  - integral and floating-point: numeric equality, when the scalar parses as a number with invariant culture. An integral constant compares exactly, by `long` or `ulong` parsing with a fraction of only zeros dropped, so a scalar with an exponent or a fraction that is not zero never equals it, a `float` constant as `float` and a `double` constant as `double`, so `0.1` equals `0.1f`, so a `long` above 2^53 never equals a neighbour and `1e100` can equal a `double`. So `2` and `2.0` both equal a `double` 2.
  - enum: the member name, either simple (`Singleton`) or qualified with the enum's full name (`Shop.Lifetime.Singleton`), or the underlying numeric value.
  - `typeof(T)`: the type's full name in the `types` grammar, as `TypeNames.FullNameOf` gives it for the original definition: dotted, with containing types and without arity.
  - array: never equal to a scalar. A YAML sequence or mapping as a value is rejected at load.
  - A YAML `null` is rejected at load: "quote it to match the text 'null'". An argument whose constant has an error kind never matches.
  - Quoting does not change the comparison: `"2"` and `2` are the same scalar text. This is a call made for this design. ArchUnitNET compares boxed CLR objects, so a string `"2"` does not equal an int `2` there. The fixtures do not rely on the difference.

### `onlyAttributes`

A list of dotted globs over attribute class full names, as `attributes` uses them. It matches a type when **every** attribute class applied directly to the type matches at least one glob. A type with no attributes matches. An empty list is rejected at load and by the schema (`minItems: 1`), with a pointer to `isNot: { attributes: ["**"] }`, because the model cannot tell it from an absent key.

The compiler's own attributes never count against the set, on any type. They are `System.Runtime.CompilerServices.CompilerGeneratedAttribute`, `NullableAttribute`, `NullableContextAttribute`, `NullablePublicOnlyAttribute`, `IsReadOnlyAttribute`, `IsByRefLikeAttribute` and `Microsoft.CodeAnalysis.EmbeddedAttribute`. A source type never shows them through Roslyn. A metadata type, such as a `to` target in a referenced assembly, does. Leaving them out gives one meaning for both kinds of type. This is a call made for this design. ArchUnitNET 0.13.5 does not count the nullable attributes for `OnlyHaveAttributes` either (measured), so the `only` rows do not diverge. ArchUnitNET's `OnlyHaveAttributes()` with no arguments, meaning "has no attributes", is `isNot: { attributes: ["**"] }` in a pack. `OnlyHaveAttributesThat()` maps to `onlyAttributes` with the globs that describe the predicate.

### Where both keys apply

Both keys go into every key set that holds `attributes` today, with the same neighbours:

- rule targets: `forbid` and `allowOnly` `from` and `to`, `require` `for`, `slices` `allow`, `uniqueNames` `for` and `against`;
- `is` and `isNot`, as `require` conditions with their own messages;
- exceptions of every rule kind except `bannedPackages`, which rejects them as it rejects `attributes`, including amendment exceptions and code-built amendments through `ExceptionKeyRules.UsedKeys`;
- not next to `layers`, since they join `OtherSelectorKeys`;
- not in `implements`, layer definitions or roles.

Each key alone is enough to make a selector or an exception non-empty: `RulePackReferenceCheck` and the "needs at least one of …" messages list them after `attributes`. `VacuityRules` needs no change, because it works on the compiled `TypeSelector`.

### Messages

`RequireCondition` gets one condition per key:

- `attributeArguments`: "should have an attribute matching 'Shop.RouteAttribute' with arguments 'api/orders', '2' and named arguments 'Version=2'", ending in "but does not" or, under `isNot`, "but does". Several entries are joined with "or".
- `onlyAttributes`: "should only have attributes matching 'Shop.**' but has 'Other.TagAttribute'", naming the first attribute class outside the set in declaration order. Under `isNot` it ends "but has only attributes matching them".

`RulePackDescriber` describes both keys.

## Model (Abstractions)

- `AttributeArgumentMatch`, a new `[Validate]` class with `string? Attribute`, `IList<string> Arguments` and `IDictionary<string, string> Named`, the last with `StringComparer.Ordinal`. Values stay scalar text, so the class is AOT-safe and has no Roslyn dependency.
- `TargetSelector` and `RuleException` each get `IList<AttributeArgumentMatch> AttributeArguments` and `IList<string> OnlyAttributes`, with the null-entry validation the other lists carry.
- `TypeSelector` compiles both into its `Matches` walk, after `_attributes`. One pass over `type.GetAttributes()` serves `attributes`, `attributeArguments` and `onlyAttributes`.

## Tests

- **Loader:** each key loads into its property in a target, a condition and an exception; every rejection above is reported at its line and column; an amendment exception with either key merges; a code-built amendment with either key on an inherited `bannedPackages` rule is rejected.
- **Analysis:** `AttributeArgumentMatcher` has one test per value kind (string, char, bool, each integral width, float and double, enum by simple name, qualified name and number, `typeof`, an array argument, and an error constant), plus the any-position and same-instance rules: two instances of the attribute, each holding one of two required values, do not match. `TypeSelector` tests cover `onlyAttributes` with no attributes, all inside the set, one outside it, and a metadata type whose only extra attribute is compiler-emitted. The loader rejects `onlyAttributes: []` and `arguments: []`. `RequireCondition` tests cover both messages and both polarities.
- **Schema:** the `PackSchema` valid and invalid cases above. The harness fails when the schema and the loader disagree.
- **Parity:** ten cases, one per row and polarity. ArchUnitNET has no negation of `OnlyHaveAttributes`, so the two `only` rows have no `:not` case. Each `:not` case of an arguments row uses the `HaveAny…` method, so the pack spelling without `attribute` is covered too:
  - `p-have-attribute-with-arguments`: `HaveAttributeWithArguments`, and `:not` with `DoNotHaveAnyAttributesWithArguments`, against `forbid` `from` and against an exception;
  - `c-have-attribute-with-arguments`: `HaveAttributeWithArguments` against `is`, and `:not` with `NotHaveAnyAttributesWithArguments` against `isNot`;
  - `p-have-attribute-with-named-arguments` and `c-have-attribute-with-named-arguments`: the same pattern with named arguments;
  - `p-only-have-attributes`: `OnlyHaveAttributes` against `forbid` `from` with `onlyAttributes`;
  - `c-only-have-attributes`: `OnlyHaveAttributes` against `is: { onlyAttributes }`.
  
  The arguments fixtures use a string and an int positionally and a string and a bool by name. One type holds the right values on two different instances, so the same-instance rule is checked against ArchUnitNET.
- **The compiler-attribute measurement:** each `only` fixture holds one type whose only other attribute in IL is compiler-emitted, for example a class with a nullable reference field. If ArchUnitNET flags it and Ariadne does not, the case gets a `Divergences` entry with that fixture. The expected answer is Ariadne's, since a developer who writes `OnlyHaveAttributes` means the attributes written in source. The row becomes `divergence` and the catalogue gets the entry. If the two tools agree, the row is `covered`.
- **Docs:** `CatalogueConsistencyTests`, `MigrationGuideSnippetTests` and `MigrationGuideTests` pass. The guide's new YAML blocks load.

## Risks

| Risk | Impact | Mitigation |
|---|---|---|
| ZeroAlloc.Validation cannot validate a list of nested `[Validate]` objects or a dictionary | Model validation for code-built packs is weaker than for the other keys | Validate the entries by hand in a `Must` method, as `HasNoNullEntries` does; the AOT smoke test must stay green |
| ArchUnitNET compares an enum argument as a boxed enum against IL's underlying integer, so an enum value may never match there | A fixture with an enum argument would diverge | The fixtures use no enum argument; enum equality is covered by unit tests only |
| The compiler-emitted attributes make the `only` cases disagree | Two `divergence` rows instead of `covered` | Measured on purpose by a fixture type, and recorded as a `Divergences` entry. Criterion 3 accepts `divergence` |
| The schema's `bannedPackages` `if`/`then` misses a new key | The schema accepts what the loader rejects | The invalid `PackSchema` cases fail until it is added |
