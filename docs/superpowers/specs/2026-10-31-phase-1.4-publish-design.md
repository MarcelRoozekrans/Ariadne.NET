# Phase 1.4 Design — Publish

**Date:** 2026-10-31
**Phase:** 1.4
**Surface:** Infra
**Stage:** phase (one phase, implementation-ready)

## Goal

Ariadne.NET 0.1.0 is on nuget.org as `Ariadne.NET.Abstractions` and `Ariadne.NET`, released by release-please from a public `MarcelRoozekrans/Ariadne.NET` repository whose CI builds, tests, runs the AOT smoke publish and reports coverage to codecov, with the docs site on GitHub Pages and a README in the family shape.

## Intent and scope

This closes Milestone 1. Until now nothing has been published, so every name and package shape could still change for free; after this phase a change is a release. The siblings already solved publishing, and some of their solutions came from incidents: Rag.NET shipped twelve tagged releases that never reached nuget.org because a release created with `GITHUB_TOKEN` starts no workflow. Ariadne copies their setup instead of rediscovering it.

**Goals:**
- CI on every push and pull request: build and test on ubuntu and windows, the AotSmoke publish, coverage to codecov, pack validation, and commitlint on pull requests.
- release-please on `main` cuts 0.1.0 as the first release, and the release publishes both packages to nuget.org through Trusted Publishing.
- The docs site deploys to GitHub Pages at the renamed repository's URL.
- The README leads with the library and carries the Family and Built on ZeroAlloc sections.
- ZeroAlloc.Analyzers is at 1.12.0 with the build still at zero warnings.
- Security and quality baseline in CI, added 2026-11-03 by the owner: gitleaks on every pull request after the one-time history scan, `NuGetAuditMode=all` so transitive packages are audited at restore, CodeQL for C#, a CycloneDX SBOM attached to each release, and a coverage floor in `codecov.yml`. Renovate, already on `main`, covers dependency updates. Trivy waits until a container image ships.
- The repository is renamed to `Ariadne.NET`, made public, and has Actions enabled, after a history check and a fresh confirmation from the user.
- Milestone 1's branch `fix/mcp-composite-template` is merged to `main` through a pull request with CI green.

**Non-goals:**
- Shipping the CLI as a dotnet tool (Phase 3.3) or the MCP server as a dotnet tool or npx package (Phase 5.1). Both stay `IsPackable=false` and run from a clone.
- Reviewing every how-it-works docs page against the code. Milestone 2 rewrites the rule schema, so those pages are only checked for stale names and broken links now.
- A reusable workflow shared across the family. It touches five other repositories and is its own project.
- GitHub Packages. No sibling publishes there.
- Benchmarks, nightly runs, AotSurface and live-smoke jobs from the siblings. Ariadne has none of the code they test.

**Anti-goals:**
- Any path that pushes to nuget.org other than the release run: no push on every merge to `main`, which the current `publish.yml` does.
- A long-lived nuget.org API key stored as a secret.
- A release that tags and announces a version that never reaches nuget.org, and stays green.
- Turning the repository public or enabling Actions before the history check has passed and the user has confirmed.
- A red check made green by `continue-on-error`, a skipped step or a suppressed warning.

## Decisions

Decided with the user on 2026-10-31:

- **First release is 0.1.0 on nuget.org.** Pre-1.0 because schema v2 in Milestone 2 is a deliberate clean break; release-please uses `bump-minor-pre-major`, so that break is a minor bump. 1.0 comes after Daedalus parity in Milestone 4.
- **The repository is renamed** from `architecture-governance-engine` to `Ariadne.NET`, in the go-public step. GitHub redirects the old URL.
- **Port Minos.NET's setup, trimmed to Ariadne's size** (approach A below).
- **ZeroAlloc.Analyzers goes to 1.12.0** in this phase.
- **Repo public and Actions on at the end of the phase**, after a history check, with a fresh confirmation from the user right before.
- **Trusted Publishing policy exists on nuget.org** for `MarcelRoozekrans/Ariadne.NET` and the workflow file `ci.yml`. The publish job therefore lives in `ci.yml`.
- The ZeroAlloc.Resilience timeout labelling bug from Phase 1.3 is filed upstream as ZeroAlloc-Net/ZeroAlloc.Resilience#263. Ariadne's own mapping in `Sync/SyncOperations.cs` stays as it is.

## Approaches

- **A — Port Minos.NET, trimmed (chosen).** Minos.NET is the sibling closest in shape: a library with an AOT smoke test. Its `ci.yml`, App-token `release-please.yml`, release-please config and manifest, `.commitlintrc.yml`, `codecov.yml` and `RELEASING.md` are brought over, with the comments that record why each guard exists. The cost is a larger diff to review.
- **B — Patch the four existing workflows.** A smaller diff, but it walks back into the failures the siblings already fixed, and Ariadne's CI ends up shaped differently from the rest of the family.
- **C — A shared reusable workflow for the family.** Removes the duplication everywhere, but touches five other repositories and becomes a separate project.

## Approach

**Release flow, as in Minos.NET.** Conventional commits on `main` make release-please keep a release PR open. Merging it tags `v0.1.0` and creates the GitHub release. `release-please.yml` runs on a token minted from the release bot GitHub App (`RELEASE_BOT_CLIENT_ID` variable, `RELEASE_BOT_PRIVATE_KEY` secret), not `GITHUB_TOKEN`, and dispatches `ci.yml` on the tag with `publish_to_nuget=true`. On that run `publish-nuget` waits for the build, test, AOT smoke and pack-validate jobs on the tagged commit, refuses a prerelease or a tag that differs from the manifest version, packs in release mode, logs in with `NuGet/login` (user from the `NUGET_USER` variable), pushes both `.nupkg` files with their `.snupkg` files, and attaches them to the GitHub release. A resume dispatch with `--skip-duplicate` finishes a push that died partway, as `RELEASING.md` in Minos.NET documents.

**One deliberate divergence from Minos.NET:** Minos.NET refuses to publish any 0.x version. Ariadne publishes 0.x, so that refusal is not ported; the prerelease and manifest-mismatch refusals are.

**Versioning.** The version comes from `.release-please-manifest.json`, as in Minos.NET: a release pack builds with a release switch (`-p:AriadneRelease=true`) and carries the manifest version; any other build is `X.Y.Z-local`, and pack validation rejects a release-mode DLL that does not carry the release version. GitVersion and `GitVersion.yml` are removed: once only a tag publishes, a second version source can only disagree with the manifest *(Claude's call)*.

**CI jobs in `ci.yml`.** Triggers: push to `main`, pull requests to `main`, and `workflow_dispatch` with `publish_to_nuget` and `resume` inputs. `concurrency` cancels superseded runs on the same ref. Default permissions `contents: read`; jobs widen only what they need (`id-token: write` for codecov OIDC and NuGet login).
- `build`: matrix ubuntu-latest and windows-latest, `fail-fast: false`, NuGet cache, restore, build Release, test with coverage in Cobertura, upload to codecov over OIDC. The three test projects are `Ariadne.NET.Tests`, `Ariadne.NET.Mcp.Tests` and `Ariadne.NET.Cli.Tests`; `Ariadne.NET.AotSmoke` is an executable, published by its own job.
- `aot-smoke`: on ubuntu, `dotnet publish tests/Ariadne.NET.AotSmoke -c Release -r linux-x64 -p:PublishAot=true -warnaserror`, then runs the produced binary and fails on a non-zero exit.
- `pack-validate`: packs in release mode, asserts exactly `Ariadne.NET` and `Ariadne.NET.Abstractions` come out, that the Abstractions nuspec depends only on ZeroAlloc.Results and ZeroAlloc.Validation, and rehearses the push against a local feed, including a second push that must leave the feed unchanged.
- `commitlint`: pull requests only, lints the commits the PR adds.
- `publish-nuget`: described above.

**Commit linting.** `.commitlintrc.yml` extends config-conventional with the same type list and header length as Minos.NET, but without a `scope-enum`, because `docs/planning/CONVENTIONS.md` records scopes as free *(Claude's call)*. This repository's existing history is not linted.

**Docs site.** `docs.yml` keeps deploying `docs-site/` to GitHub Pages. `baseUrl`, `projectName` and the edit links move to `Ariadne.NET`. A Getting started page shows `dotnet add package Ariadne.NET` and a minimal code sample that loads a built-in pack and checks a project. The how-it-works pages are checked for `ArchGov` and `architecture-governance-engine` remnants and broken links only.

**README.** Leads with what Ariadne is and the library install with the same code sample, then the CLI and MCP server as run-from-source, then badges (CI, codecov, NuGet for both packages, docs), a Family section listing the siblings in the same form as Minos.NET's, a Built on ZeroAlloc section, and the license. A `LICENSE` file (MIT, matching the `PackageLicenseExpression` both packages already declare) is added at the root; the repository has none today.

**Package metadata.** Both csproj `RepositoryUrl` values move to `https://github.com/MarcelRoozekrans/Ariadne.NET`, plus `PackageProjectUrl` pointing at the docs site, and the package README is the repository README. Shared metadata moves into `Directory.Build.props` where both packages repeat it *(Claude's call)*.

**Branch.** All Phase 1.4 work is committed onto `fix/mcp-composite-template`, so the one pull request in step 4 carries Milestone 1 and Phase 1.4 together, and its CI run is the first run of the new workflows *(Claude's call)*. `main` has five Renovate commits the branch lacks (`renovate.json` and four dependency bumps: ModelContextProtocol 1.4.1, FluentAssertions 8.11.0, xunit.runner.visualstudio 3.1.5, Meziantou.Analyzer 3.0.318). `main` is merged into the branch early in step 1, with the bumps re-applied to the renamed project files where the merge conflicts. `renovate.json` stays, as in the siblings.

**Release history.** The 0.1.0 changelog draws on the whole history, with no `bootstrap-sha` cutoff, because every feature is new to someone installing 0.1.0 *(Claude's call)*. The step 2 history check therefore also scans every commit body on the branch for nested parentheses, which make release-please drop a commit. None were found on 2026-10-31.

**Package dependency.** `Ariadne.NET` references `Ariadne.NET.Abstractions` by project reference, so the release switch must version both projects, and `pack-validate` also asserts that the packed `Ariadne.NET` nuspec depends on `Ariadne.NET.Abstractions` at exactly the release version. Every 0.x refusal in Minos.NET's jobs is left out, not only the one in `publish-nuget`.

**Coverage.** The test projects stay on VSTest with `coverlet.collector`: `dotnet test --collect:"XPlat Code Coverage"` with a `coverage.runsettings` producing Cobertura *(Claude's call)*.

**Order of work.**
1. On the branch, before Actions can run: delete `publish.yml`, so nothing can publish early. Then the analyzer bump, workflows, release config, commitlint, codecov config, `RELEASING.md`, `LICENSE`, package metadata, README and docs.
2. History check: scan all commits on all branches for secrets (gitleaks or an equivalent scanner) and for the private details listed in the owner's global CLAUDE.md, such as home hostnames, internal IPs and home-directory paths. Findings are reported to the user before anything is published. A secret found in history means rotating it and rewriting history before going public; that decision is the user's.
3. The user confirms. Then: rename the repository to `Ariadne.NET`, update the local remotes, make it public, enable Actions, enable Pages from Actions, all through `gh`. Any of these the API refuses goes to the user checklist instead.
4. Open the pull request from `fix/mcp-composite-template` to `main`. CI must be green on both OS legs. Add a `Main` ruleset requiring the `build` legs, `aot-smoke` and `pack-validate`, as Minos.NET has.
5. Merge. release-please opens the 0.1.0 release PR. Check that the Milestone 1 `feat:` and `fix:` commits appear in it, since release-please silently drops a commit it cannot parse. Merge it, watch the dispatched publish run, and confirm both packages on nuget.org.

**Settings only the user can make,** listed in `RELEASING.md` and in the plan as a checklist: install the release bot GitHub App on the renamed repository; set `RELEASE_BOT_CLIENT_ID`, `RELEASE_BOT_PRIVATE_KEY` and `NUGET_USER`; reserve the `Ariadne.NET` id prefix on nuget.org (both ids were still free on 2026-10-31); add the repository on codecov. The Trusted Publishing policy is done. The checklist is confirmed complete before the 0.1.0 release PR is merged.

## Open Questions

None blocking. The user settings above are needed before step 5 and are tracked as a checklist, not open decisions.

## Risks

| Risk | Impact | Mitigation |
|---|---|---|
| Analyzers 1.12.0 adds diagnostics that fail the build | Phase grows | Fix each at its source as the first task; no `NoWarn`. If one is an analyzer bug, file it upstream and stop for the user's call. |
| The history scan finds a secret or private detail | Going public would leak it | Stop before step 3; the user decides on rotation and history rewriting. |
| Windows leg fails on path or line-ending assumptions the Linux-only history never exercised | PR cannot merge | Fix in code; that is what the matrix is for. |
| The release bot App is not installed when the release PR merges | Tag and release exist, nothing published | `RELEASING.md` resume dispatch; the checklist is confirmed before merging the release PR. |
| The `Ariadne.NET` id prefix is not reserved, or the policy's owner does not hold the reservation | Push refused with 409 "The package ID is reserved", or someone else takes an id first | Reservation is on the checklist before the release PR merges; `RELEASING.md` documents the 409 cases as in Minos.NET. |
| Merging `main`'s Renovate commits conflicts with the renamed project files | Dependency bumps lost | Re-apply each bump by hand and check the versions after the merge. |
| release-please drops a commit with an unparsable body | A change ships uncredited | Inspect the release PR's changelog against `git log` before merging it. |
| A redirect from the old repository name hides a stale URL | Broken links after an unrelated repo takes the old name | Grep for `architecture-governance-engine` outside historical plan docs; none may remain. |
