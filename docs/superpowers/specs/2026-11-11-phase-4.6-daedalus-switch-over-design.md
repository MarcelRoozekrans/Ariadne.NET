## Goal

Daedalus.NET checks its architecture with an Ariadne pack through one `Ariadne.NET.Testing` test, its ArchUnitNET tests and package are gone, and Ariadne's migration guide shows the pack Daedalus actually ships.

## Why

Milestone 4 ends with its first real consumer switched over. It proves that the guide works on a codebase that was not written for Ariadne, and it removes a second architecture tool from Daedalus.

## Decisions

Taken with the owner on 2026-11-11:

- **The `Directory.Packages.props` check is dropped.** `bannedPackages` stops every project from resolving the banned packages, which is what the facts protect. A central version entry that no project references is harmless. The milestone DoD stands as written: the only architecture tests left in C# are `NuGetPackageRootPathTests` and the DI integration test.
- **Side by side first, then red checks, then delete.** One Daedalus PR with three steps. First the pack and the Ariadne test are added while the ArchUnitNET tests still run, and both are green. Then, for each rule group, the builder applies the mutation that the Daedalus test's `Red:` comment describes, or an equivalent one where the comment has none, confirms that the Ariadne test fails with the expected rule id, and reverts. The results go in the PR body as a table. Last, the ArchUnitNET tests and the package are deleted.
- **Checks in Daedalus:** build `dotnet build Daedalus.sln`, tests `dotnet test tests/Daedalus.Tests.Unit`. The integration tests need PostgreSQL and run in Daedalus's CI.

## Approach

### Where it runs

The phase runs in a session opened on the Daedalus.NET repository, not in this one; an unattended run of this repository never builds it. Its last task runs in this repository again, to update the guide. The phase completes here through `complete-phase` once both PRs have merged.

### Preconditions

- **A release with Milestone 4 in it.** The guide's pack uses Phase 4.2's selector traits, at least `names`, `kinds` and `abstract`. The phase starts on the latest `Ariadne.NET.Testing` on nuget.org and checks that it contains them. If it does not, the phase stops and asks the owner to merge the release-please PR. It never builds against an unreleased package or a local feed.
- **The guide's pack loads.** The guard check in the 4.5 plan runs first, in this repository.

### Bringing the example up to date

Daedalus keeps moving. The phase starts from Daedalus `main` as it is then, and diffs its architecture test files against `1dd470b7`, the commit the guide translates. Each new or changed fact is translated with the guide's construct map and joins the pack and the guide's test map in the same way. A fact that no longer exists leaves the pack and the map.

### The Daedalus change

All on one branch, in one PR, in Daedalus's own conventions: conventional commits, PR required, squash merge.

1. **Add the pack and the test.**
   - `.architecture/rules.yaml` at the Daedalus repository root, holding the guide's `daedalus` pack, updated as above.
   - `Directory.Packages.props` gains `Ariadne.NET.Testing` at the release found above; `tests/Daedalus.Tests.Unit` references it.
   - One test, `tests/Daedalus.Tests.Unit/Architecture/AriadneArchitectureTests.cs`, with one fact, `Solution_follows_the_architecture_pack`, that calls `ArchitectureCheck.AssertValid` on `Daedalus.sln`, found by walking up from the test assembly's folder.
   - Both the ArchUnitNET tests and the Ariadne test pass, locally and in Daedalus CI.
2. **Red checks.** One mutation per rule group: each layer's `allowedDependencies`, each `forbid` rule, the `allowOnly` rules, each `require` rule, the `uniqueNames` rule and each `bannedPackages` rule. For each, the builder confirms the Ariadne test fails and its message names the expected rule or layer id, then reverts. Nothing of the mutation is committed. A rule that does not go red is a defect in the pack: fix it and re-run, or stop and report when the fix is not clear.
3. **Delete ArchUnitNET.**
   - Delete `tests/Daedalus.Tests.Unit/Architecture/CleanArchitectureTests.cs` and `NoEntityFrameworkTests.cs`.
   - Delete any helper or `using` they alone needed.
   - Remove `TngTech.ArchUnitNET.xUnit` from `Directory.Packages.props` and from every project.
   - Keep `NuGetPackageRootPathTests.cs` and the integration test `tests/Daedalus.Tests.Integration/Architecture/CleanArchitectureTests.cs`.
   - `grep -ri archunit` over the repository, outside `bin`, `obj` and `CHANGELOG.md`, finds nothing.

The PR body holds the red-check table, the Ariadne version used, and a note that the package-absence facts' `Directory.Packages.props` part is dropped on purpose.

Merging the PR is the owner's call. The PR is not merged by the builder unless the owner says so.

## Risks

| Risk | Impact | Mitigation |
|---|---|---|
| No release contains Milestone 4 when the phase starts | The pack cannot load | Stop and ask the owner to merge the release-please PR |
| The pack flags code that ArchUnitNET passes, because Ariadne reads source and ArchUnitNET reads IL | The side-by-side step is red | Look the difference up in the catalogue's `Divergences`. When it is listed, adjust the pack and say so in the PR body. When it is not, stop and report: it is a parity gap for this repository |
| Loading Daedalus with MSBuildWorkspace in its unit tests is slow or needs something its CI lacks | Slower CI, or a red build | Record the test's time in the PR body. On a load failure, read `ArchitectureCheckException`'s message; a missing restore is fixed in the test setup, anything else is reported |
| Daedalus moved in a way the guide cannot express | The pack is incomplete | Translate what the guide covers; a fact that needs a rule kind Ariadne lacks stays a C# fact, is reported to the owner, and is filed as an Ariadne issue |
| The owner does not merge the Daedalus PR soon | The milestone stays open | 4.6 has no dependants; the owner decides whether M4 waits or closes without it, as the milestone design says |
