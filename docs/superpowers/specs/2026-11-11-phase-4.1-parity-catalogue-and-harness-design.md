**Status:** approved 2026-11-11

## Goal

A docs-site page lists every type-level and slice rule kind of ArchUnitNET 0.13.2 with its Ariadne equivalent or status, and a test project runs ArchUnitNET and Ariadne side by side on one fixture project per in-scope kind. CI fails when they disagree, except where a `KnownGaps` or `Divergences` entry covers the difference.

## Why

Milestone 4 claims "what you write in ArchUnitNET, you can write in Ariadne". This phase builds the yardstick for that claim. Phases 4.2 and 4.3 close gaps against it, 4.4's migration guide quotes its packs, and the catalogue is the user-facing statement of what holds today.

## Decisions

Taken with the owner on 2026-11-11:

- **One fixture project per catalogue kind**, not per kind and variant. Each project has a `Clean` and a `Broken` namespace, and one rule covers the whole project. That gives about 40 projects instead of 80, and roughly halves the load time. A broken type can only leak into its own kind's `Clean` namespace, and the harness asserts `Clean` is never flagged. This overrides the milestone design's "one project per rule kind and variant".
- **4.1 builds the fixture and the ArchUnitNET side for every in-scope kind**, including those Ariadne cannot express yet. A `KnownGaps` entry means "the Ariadne pack for this kind is missing". 4.2 and 4.3 add the pack and delete the entry, against an ArchUnitNET answer that is already settled.
- **Kinds outside the milestone's named scope:**
  - `record` (`BeRecord`, `AreRecord`) and enum, struct and value type as *predicates* (`AreEnums`, `AreStructs`, `AreValueTypes` and their negations) join 4.2's scope as `KnownGaps` entries. They are one-field additions of the same shape as 4.2's other conditions.
  - Class immutability (`BeImmutable`, `AreImmutable`) inspects members, so it is `deferred` and goes into the member-level issue.
  - `AdhereToPlantUmlDiagram` is `out-of-scope`: Ariadne rules are YAML, not diagrams.
- **Approach A: a C# case table plus a real pack per kind** (approaches below).

## Findings that shape the work

- **ArchUnitNET 0.13.2's vocabulary**, read from the package's metadata:
  - `TypePredicatesDefinition` / `TypeConditionsDefinition`: reside in namespace or assembly (exact and `Matching`), assignable to, implement interface, enums, structs, value types, nested and nested in, member-with-name, `Be` and `NotBe` specific types.
  - `ClassPredicatesDefinition` / `ClassConditionsDefinition`: abstract, sealed, record, immutable.
  - `AttributePredicatesDefinition` / `AttributeConditionsDefinition`: abstract and sealed attribute classes.
  - Object-level conditions and predicates: dependencies, names, accessibility, attributes, calls and similar. The catalogue task enumerates these from the package itself; this list is not exhaustive.
  - Slices: `Slices().Matching(...)` and `MatchingWithPackages(...)`, then `BeFreeOfCycles()` and `NotDependOnEachOther()`.
  - Member level: method, property and field conditions.
- **`static` has no type-level counterpart in ArchUnitNET 0.13.2.** Only members have `BeStatic`. 4.2 still adds a `static` condition, but the catalogue marks it `ariadne-only`: there is nothing to compare it against, so it gets no harness case. This is an input for 4.2's design.
- **ArchUnitNET reads built assemblies.** Its `ArchLoader` loads DLLs through Mono.Cecil, so the parity fixture must be **built**. The existing fixtures are only restored.
- **Type names are written differently.** Ariadne's `ArchitectureViolation.SourceType` is Roslyn's `ToDisplayString()`, for example `Ns.Outer.Inner` and `Ns.Foo<T>`. ArchUnitNET's `FullName` is metadata style, for example `Ns.Outer+Inner` and ``Ns.Foo`1``. The harness maps both to one canonical form before comparing.
- **ArchUnitNET's dependencies include framework types.** "Only depend on" in ArchUnitNET counts dependencies such as `System.Object`, whereas Ariadne's `allowOnly` has the opposite direction: who may depend *on* a target. The catalogue therefore maps `OnlyDependOn` with care, most likely to a layer's `allowedDependencies`. The harness decides; where the semantics cannot match, the entry gets a `Divergences` record with a fixture and a reason.
- **`Ariadne.NET.Testing` takes a project path.** `ArchitectureCheck.Run(path)` accepts a `.csproj` and finds `.architecture/` from that project's folder upward. Each kind's folder can therefore carry its own pack, and the Ariadne side runs exactly the call a consumer makes.

## Approaches considered

- **A — C# case table plus a pack per kind (chosen).** Each in-scope id has a `ParityCase` in the test project: the id, the fixture project and the ArchUnitNET rule written as ordinary fluent C#. The Ariadne side is `tests/fixtures/archunit-parity/<Kind>/.architecture/rules.yaml`, run through `ArchitectureCheck.Run`. A markdown table on the docs site is the catalogue, and a test parses it and checks it against the case table, `KnownGaps` and `Divergences`. ArchUnitNET rules stay in the C# readers will write, and the packs are real files that 4.4 can quote.
- **B — Data-driven manifests.** One YAML manifest per kind holds the pack and a textual ArchUnitNET rule, and the catalogue page is generated from the manifests. This gives a single source of truth. It was rejected because it needs a parser that turns strings into ArchUnitNET fluent calls, a private DSL, and a doc-generation step in CI.
- **C — Tests generated from the catalogue page by a source generator.** Rejected: more machinery than A, and no stronger claim.

## Approach

### Catalogue

The catalogue is a new docs-site page, `docs-site/docs/archunitnet-parity.md`. It has one markdown table per group: type predicates, type conditions, class, attribute, object-level, slices, member level and combinators. Every row has these columns:

| Column | Content |
|---|---|
| Id | Stable kebab-case id. Predicates (`That()`) start with `p-` and conditions (`Should()`) with `c-`, for example `p-reside-in-namespace` and `c-reside-in-namespace`. Slices start with `s-` and combinators with `x-`. A positive and negative pair, such as `ResideInNamespace` and `DoNotResideInNamespace`, is one row. |
| ArchUnitNET | The method or methods, in code font. |
| Ariadne | The equivalent pack construct in code font, or `—`. |
| Status | Exactly one of `covered`, `gap`, `divergence`, `deferred`, `out-of-scope`, `ariadne-only`. |
| Notes | For `gap`, the phase that closes it (`4.2` or `4.3`). For `deferred` and `out-of-scope`, the reason. For `divergence`, a link to the divergence section. |

A `## Divergences` section on the same page lists each divergence: its fixture, the reason, and which tool's answer a developer would expect. The intro states that the version is pinned at 0.13.2, that only types declared in source are compared, and that compiler-generated types are left out (see Comparison).

`covered`, `gap` and `divergence` rows are in scope and have a harness case. `deferred`, `out-of-scope` and `ariadne-only` rows have none.

Combinators: `And` maps to several fields in one selector, and `Or` within one predicate maps to several values in one list. Both are `covered` only when a case proves them. `Or` across predicates, nested `Not`, and `AndShould` / `OrShould` chains are `out-of-scope`: Ariadne adds fields, not an expression language. `Because` maps to `because` and needs no case.

### Fixture

The fixture is `tests/fixtures/archunit-parity/`:

- `Parity.slnx` lists every kind project.
- `<Kind>/Parity.<Kind>.csproj` targets `net10.0`. It holds the namespaces of its cases (see Cases), plus any helper namespace a rule needs as a target, such as `Parity.<Kind>.Target`.
- `<Kind>/.architecture/rules.yaml` exists only when Ariadne can express at least one of the kind's cases. It holds one rule per expressible case.
- `<Kind>` is PascalCase, derived from the row id, for example `PResideInNamespace`.

A project may reference a second fixture project only when the kind is about assemblies, such as `ResideInAssembly`. Fixture code avoids lambdas, async methods, `const` and `nameof` in dependency positions, except in a fixture that exists to show a divergence.

`tests/fixtures/Directory.Build.props` is empty and stops the repository's analyzers from applying. The parity fixture keeps that behaviour.

### Cases

A **case** is one testable rule. A catalogue row has one case per polarity: `p-reside-in-namespace` covers `ResideInNamespace` and `p-reside-in-namespace:not` covers `DoNotResideInNamespace`. A row with one polarity, such as `s-free-of-cycles`, has one case. Every case of a row lives in that row's single fixture project, under its own namespace prefix:

- `Parity.<Kind>.Clean` and `Parity.<Kind>.Broken` for the positive case;
- `Parity.<Kind>.NotClean` and `Parity.<Kind>.NotBroken` for the negative case.

Each case's rule, on both sides, selects only its own prefix. The kind's pack holds one rule per case, with ids `PARITY-<KIND>` and `PARITY-<KIND>-NOT`. The harness keeps only the violations whose `RuleId` belongs to the case. The fixture therefore has one project per catalogue row, so about 40 to 50 projects. The count follows from the catalogue; it is not a target.

How each kind becomes a rule that can fail:

- **Conditions (`c-`)** are tested directly. For example, `Types().That().ResideInNamespace("Parity.CBeSealed.Broken").Should().BeSealed()` is set against a pack rule that requires the same.
- **Predicates (`p-`)** cannot fail on their own, so each is paired with one fixed condition that Ariadne already covers: `Should().NotDependOnAny(<the kind's Target namespace>)`, against a pack `forbid` rule. In `Broken`, a type the predicate selects depends on `Parity.<Kind>.Target`. In `Clean`, a type the predicate does *not* select also depends on it, so a selector that selects too much shows up as a flagged `Clean` type.
- **Combinators (`x-`)** that are in scope get their own rows and projects, for example `XAnd`.

### Comparison projection

Each case has a `Projection`:

- **`Types`**, the default, compares the set of failing types. On the ArchUnitNET side these are the failed objects. On the Ariadne side they are the violations' `SourceType`. Both report the type that breaks the rule, including for dependency rules, where that type is the one doing the depending. When a kind makes the two tools blame different sides, the case gets a `Divergences` entry with the reason. There is no per-case projection.
- **`Slices`** compares the set of *slice names* involved in a failure. A slice name is the value the case's capture pattern takes, for example `Orders` for `Parity.SNoCycles.Broken.(*)`. The ArchUnitNET side reads slice names from its failed slices, and for `BeFreeOfCycles` from the slices in each reported cycle. The Ariadne side maps each violation's `SourceType` through the same pattern. Slice rows are `gap` entries in 4.1. Their ArchUnitNET side runs now, and 4.3 builds Ariadne's slice violations so that this projection works: a slice violation's `SourceType` must lie in a slice the pattern names. That is an input for 4.3's design.

### Harness

The harness is a new test project, `tests/Ariadne.NET.Parity.Tests`: xUnit, FluentAssertions, a test-only `TngTech.ArchUnitNET` 0.13.2, a project reference to `Ariadne.NET.Testing`, and the `Microsoft.Build.Framework` line every Workspaces consumer in this repo carries. It is added to `src/Ariadne.NET.slnx`, so `dotnet test src/Ariadne.NET.slnx` and CI run it on Ubuntu and Windows. Its assembly name matches the repository pack's `*.Tests` layer.

- **Building the fixture.** The shared `tests/Shared/FixtureProjects.cs` gains an `EnsureParityBuilt()`. Under the same file lock, with its own marker file, it runs `dotnet build tests/fixtures/archunit-parity/Parity.slnx`; the build also restores. Only the parity project calls it, so the other test projects do not pay for it.
- **`ParityCase`** is a record with:
  - `Id`, the case id;
  - `Kind`, the folder name;
  - `Prefix`, the case's namespace prefix without `.Clean` or `.Broken`;
  - `AriadneRuleId`;
  - `Projection`, with a `SlicePattern` when it is `Slices`;
  - `Func<Architecture, IArchRule> Rule`.

  `ParityCases.All` lists every case of every in-scope catalogue row. ArchUnitNET loads each kind's built DLL from `bin/Debug/net10.0/`. A project's ArchUnitNET `Architecture` and Ariadne report are each built once and shared by its cases.
- **The parity theory** runs once per case that is not in `KnownGaps`:
  - It evaluates the ArchUnitNET rule and projects its failures.
  - It runs `ArchitectureCheck.Run(<csproj>)`, keeps the violations with the case's `AriadneRuleId`, and projects them.
  - It maps both sets to canonical names and asserts they are equal, unless a `Divergences` entry covers the case.
  - Whether or not they are equal, it asserts that nothing under the case's `Clean` prefix is flagged by either tool, and that `Broken` is flagged by both, at least once.
  - Ariadne's report must have no skipped projects, and no violation of a rule outside the kind's own cases. A pack error fails the case with the error's message.
- **`KnownGaps`** is a list of `(CaseId, Phase, Reason)`, keyed by case, so the two polarities of a row can close separately. For each entry:
  - ArchUnitNET still has to flag the case's `Broken` prefix, and only that. This proves the fixture.
  - The kind's pack must have no rule with the case's `AriadneRuleId`, or the kind has no pack at all. When a phase adds the rule, the test fails until the phase deletes the entry.
- **`Divergences`** is a list of `(Id, ArchUnitNetOnly, AriadneOnly, Reason, Expected)`, where `ArchUnitNetOnly` and `AriadneOnly` are sets of canonical type names. The theory asserts that the two tools disagree on exactly those types, so an entry cannot outlive the difference it records.
- **The catalogue test** parses `docs-site/docs/archunitnet-parity.md` and checks:
  - Every in-scope row has at least one case, and every case belongs to a row; a case id is its row id with an optional `:not`.
  - A row's status follows from its cases: `gap` when at least one case is in `KnownGaps` (the notes name the phase and, when only one polarity is a gap, which one), else `divergence` when at least one case is in `Divergences`, else `covered`.
  - Every `Divergences` case is linked from the page's `## Divergences` section.
  - No `KnownGaps` or `Divergences` entry names a case that does not exist.
- **Canonical type names.** A single `TypeNames.Canonical` turns both styles into one form: namespace, `.` between nesting levels, and generic arity as `` `N `` with type arguments dropped. It has unit tests for nested, generic and nested generic types.

### Comparison

"Offending types" are each tool's failing types: ArchUnitNET's failed objects and Ariadne's violation `SourceType`s. Only types declared in source are compared. Compiler-generated types, whose metadata names contain `<` or which carry `CompilerGeneratedAttribute`, are removed from ArchUnitNET's set in one place, `ParityHarness.SourceTypesOnly`. The catalogue intro states this rule. Fixtures avoid the constructs that make the rule matter, so no real difference hides behind it; a fixture that needs one is a `Divergences` entry.

### Measuring today's kinds

Every kind that the catalogue marks `covered` is measured, not assumed. When the tools disagree:

- **The difference comes from IL versus source**, for example an inlined `const`: add a `Divergences` entry and a catalogue row with status `divergence`.
- **It is a small bug in the current analysis**, small enough that its fix with a unit test fits one plan task: fix it in this phase, with a `fix:` commit.
- **Anything larger:** a `KnownGaps` entry with phase `unplanned`, plus a GitHub issue that the entry's reason names. The run's report lists it for the owner, who decides with `add-phase`. An unattended run never edits ROADMAP.md.

### Member-level issue

When the catalogue is written, file one GitHub issue in this repository. It lists every `deferred` row (member-level kinds and class immutability) with its ArchUnitNET method names, and links the catalogue page. The catalogue's notes column for those rows names the issue number.

## Tests

- **Unit:** `TypeNames.Canonical` on nested, generic and nested generic types in both styles. The catalogue parser on a small sample table.
- **Integration:** the parity theory over every non-gap case, the `KnownGaps` theory, the `Divergences` assertions and the catalogue test, all through `dotnet test src/Ariadne.NET.slnx`.
- **Smoke, first task:** ArchUnitNET 0.13.2 loads a built `net10.0` fixture assembly and evaluates one rule. If it cannot, stop and report: the milestone's approach A depends on it.
- **Regression:** the existing suites stay green. `FixtureProjects.EnsureRestored()` is unchanged for the other projects.
- **Timing:** record the parity project's test time, cold and warm, in the PR body.

## Calls made while writing this up

Settled by Claude after the builder check, not discussed; correct any of them.

- Each polarity of a catalogue row is its own case, in the row's one project, under its own namespace prefix and pack rule id.
- Predicate rows are tested by pairing them with one fixed condition, "does not depend on the kind's `Target` namespace", and `Clean` holds an unselected type that does depend on it, so a selector that selects too much is caught.
- One projection, failing types, for every type-level kind. A kind where the tools blame different sides becomes a divergence, not a special projection.
- Slices compare slice names. 4.3 must make an Ariadne slice violation's `SourceType` lie in a slice the pattern names.
- The harness is a separate test project, so ArchUnitNET, Mono.Cecil, Newtonsoft.Json and CycleDetection stay out of the other test projects.
- The fixture is built by a new `FixtureProjects.EnsureParityBuilt()`, called only by the parity project.
- A large gap found in a supposedly covered kind becomes a `KnownGaps` entry with phase `unplanned` and an issue, because an unattended run cannot run `add-phase`.

## Risks

| Risk | Impact | Mitigation |
|---|---|---|
| ArchUnitNET 0.13.2 cannot load `net10.0` fixture assemblies | Approach A fails | The first task proves it on a one-project fixture. If it fails, stop and ask the owner. |
| Building about 40 fixture projects slows CI | Longer test runs on both operating systems | One `dotnet build` of the slnx, cached by a marker as for the restore. Timing goes in the PR body. If it is over about 3 minutes warm, raise it with the owner. |
| ArchUnitNET reports a dependency Ariadne does not see, or the reverse, for reasons that are not IL versus source | `covered` rows that are not really covered | The harness is the arbiter. Every difference becomes a fix, a `Divergences` entry or a `KnownGaps` entry with an issue; nothing is filtered silently. |
| The catalogue page and the code drift | The page overstates parity | The catalogue test fails on any mismatch in either direction. |
| An unattended run finds a large gap in a kind thought to be covered | 4.1 grows | Record it as a `KnownGaps` entry with phase `unplanned` and an issue. The owner decides on a phase. |
| MSBuildWorkspace loads of about 40 projects collide on `obj` files on Windows | Flaky tests | The parity tests run in one non-parallel collection, as `FixtureSolutionCollection` does. |
