# Phase 1.2 Design — Package split

**Date:** 2026-10-31
**Phase:** 1.2
**Surface:** Refactor
**Stage:** phase (one phase, implementation-ready)

## Goal

`Ariadne.NET.Abstractions` ships as its own AOT-safe package holding the rule-pack schema and the pack contracts, with the `Ariadne.NET` engine and the surfaces building on top of it.

## Intent and scope

The Cretan family packages separate a small Abstractions package from the engine (see `docs/superpowers/specs/2026-10-30-roadmap-design.md`). Mnemosyne.NET's Abstractions is the model: records, interfaces and errors, `IsAotCompatible`, no dependency beyond ZeroAlloc.Results. Nothing is published yet, so the split is a move now instead of a breaking change later. Other tools (roslyn-codelens in M6.1) will reference Abstractions, and it is the one Ariadne package that must hold under Native AOT.

**Non-goals:**
- ZeroAlloc Results instead of exceptions, and a clean ZeroAlloc analyzer run. That is Phase 1.3.
- CI wiring for the AOT gate, and publishing. That is Phase 1.4.
- Making the engine AOT-safe. Roslyn Workspaces and YamlDotNet rule that out for now; the roadmap design records this risk.
- Replacing YamlDotNet. An AOT-safe YAML path (a ZeroAlloc YAML library, or YamlDotNet's static generator) is a separate project; when it exists, only the engine's loader changes.
- Any behaviour change. This phase only moves code.

**Anti-goal:** an Abstractions package that is a second engine — one that drags YamlDotNet, the merger or the built-in packs along — or one that claims AOT safety without anything proving it.

## Decisions

Decided with the user:

- **Abstractions holds types and interfaces, no loading.** It contains the six `RuleSchema/` types (`RulePack`, `LayerDefinition`, `ComponentRoleDefinition`, `CodeFeatureRuleDefinition`, `NamingConventions`, `CSharpTypeKind`) and the pack contracts `IRulePackLoader`, `IRulePackResolver` and `IBuiltinPackRegistry`. No package references.
- **The engine keeps loading.** `YamlRulePackLoader`, `RulePackResolver`, `RulePackMerger`, `BuiltinPackRegistry`, the embedded `BuiltinPacks/*.yaml`, `TemplateReference`, validation, sync, orchestration and code generation stay in `Ariadne.NET`. Reason: `RulePackResolver` needs the merger and the registry, so moving "the loader" would move most of the engine.
- **Flat namespace `Ariadne.NET.Abstractions`** for everything in the new package, matching `Mnemosyne.NET.Abstractions` and `Rag.NET.Abstractions` and the 1.1 rule namespace = assembly = package ID. `using Ariadne.NET.RuleSchema;` and the moved parts of `Ariadne.NET.RuleLoader` change across engine, surfaces and tests.
- **Validation contracts stay in the engine until M2.** `ISourceValidator`, `ILinter`, `IDependencyValidator` and their result and violation types do not move. M2.1 moves validation onto a Roslyn compilation, which will likely reshape these signatures; they move to Abstractions once stable.
- **The YAML library question is out of this phase.** YamlDotNet stays in the engine.
- **AOT is proven, not claimed.** Abstractions sets `IsAotCompatible`, and a smoke app `tests/Ariadne.NET.AotSmoke` (as in Mnemosyne.NET) references it and is published with `-p:PublishAot=true -warnaserror`, so any trim or AOT warning fails. It runs locally in this phase; Phase 1.4 adds it to CI.

## Approaches

| Approach | Trade-off | Outcome |
|---|---|---|
| Move files with `git mv` into a new project in one step | Simple, keeps history; churns `using` lines once | **Chosen** — the only sensible way while nothing is published |
| Type forwarding or a staged migration | Protects existing consumers | Rejected: there are no consumers yet |
| AOT gate: `IsAotCompatible` only | Cheapest; analyzers see only what they see, nothing publishes natively | Rejected |
| AOT gate: `IsAotCompatible` + AotSmoke publish | One extra project and a ~1 min publish; real proof, family precedent | **Chosen** by the user |
| AOT gate: defer to Phase 1.3 | No cost now; the AOT promise stays untested | Rejected |

## Approach

Create `src/Ariadne.NET.Abstractions/Ariadne.NET.Abstractions.csproj` (net10.0, nullable, implicit usings, `IsAotCompatible`, PackageId `Ariadne.NET.Abstractions`, the same package metadata as the engine with its own description). `git mv` the six schema files and the three interfaces into it and change their namespace to `Ariadne.NET.Abstractions`. Add it to `src/Ariadne.NET.slnx`.

The engine gets a `ProjectReference` to Abstractions; every file that used the moved types gets `using Ariadne.NET.Abstractions;`. The surfaces and test projects compile through the engine's transitive reference; add direct `using` lines where they name schema types. The engine's ZInject registrations are unaffected: the implementations stay in the engine and are still registered against interfaces that now live in Abstractions, so `AddAriadneNETServices()` keeps its name. Abstractions has no services and no ZInject reference.

Add `tests/Ariadne.NET.AotSmoke`: a console app (`OutputType Exe`, `IsPackable false`, `PublishAot true`) whose `Program.cs` constructs a `RulePack` with a layer and a component role and prints a summary, rooting the Abstractions assembly. Add it to the solution. Because `ci.yml` and `publish.yml` run `dotnet pack` on the solution, `IsPackable=false` keeps the smoke app out of the artifacts.

Update the docs that name the package layout: `CLAUDE.md` (architecture section) and the README and docs-site pages that list packages.

## Files / Modules Touched

Starting hint; `refactor-analysis` produces the authoritative list.

- `src/Ariadne.NET.Abstractions/` — new project; receives `RuleSchema/*.cs` and `RuleLoader/IRulePackLoader.cs`, `IRulePackResolver.cs`, `IBuiltinPackRegistry.cs`
- `src/Ariadne.NET/Ariadne.NET.csproj` — `ProjectReference` to Abstractions
- `src/Ariadne.NET/**` — `using` updates in RuleLoader, RuleEngine, Validation, Sync, Orchestration, CodeGeneration
- `src/Ariadne.NET.Mcp/**`, `src/Ariadne.NET.Cli/**` — `using` updates where schema types are named
- `tests/**` — `using` updates
- `tests/Ariadne.NET.AotSmoke/` — new
- `src/Ariadne.NET.slnx` — two new projects
- `CLAUDE.md`, `README.md`, `docs/` — package layout

## Tests

- Unit and integration: the existing 261 tests (225 engine, 26 Mcp, 10 Cli) pass unchanged, apart from `using` lines.
- AOT: `dotnet publish tests/Ariadne.NET.AotSmoke -c Release -r linux-x64 -p:PublishAot=true -warnaserror` succeeds and the binary runs.
- Packaging: `dotnet pack src/Ariadne.NET.slnx` produces `Ariadne.NET.Abstractions.*.nupkg` and `Ariadne.NET.*.nupkg`, and no AotSmoke package. The Abstractions nuspec lists no dependencies.
- Regression: a clean build gives no more warnings than the 27-warning baseline.

## Open Questions

## Risks

| Risk | Impact | Mitigation |
|---|---|---|
| A moved schema type uses something not AOT-safe (reflection, YamlDotNet attributes) | AotSmoke publish fails, or Abstractions gains a dependency | Checked 2026-10-31: the six files are plain `init` properties with no attributes. If one appears, the mapping goes into the engine's loader, never a package reference into Abstractions |
| The MCP server or CLI reflect over schema types by assembly or namespace name | Runtime break that the build does not catch | Checked 2026-10-31: every `.Assembly` lookup anchors on `BuiltinPackRegistry` or Mcp types, none of which move. `refactor-analysis` re-checks string type names; the Mcp and Cli suites cover the tools |
| Embedded resource names shift | Built-in packs not found at runtime | The built-in packs and `BuiltinPackRegistry` stay in the engine, so resource names do not change; existing registry tests cover it |
