## Goal

A docs-site page shows someone with ArchUnitNET tests how to move to an Ariadne pack: every catalogued ArchUnitNET construct mapped to pack YAML, the differences that matter, the steps of the switch, and Daedalus.NET's architecture tests translated in full as a worked example. CI fails when a YAML block on the page stops loading or a catalogue id it names disappears.

## Why

Phases 4.1 to 4.3 make Ariadne able to say what ArchUnitNET says, and the catalogue states which construct maps to which. The catalogue is a reference table, not a how-to. A team with a test class full of fluent rules needs to know what replaces `Types().That()…Should()…`, what to do with the facts that only exist to work around ArchUnitNET, and what a finished pack looks like for a real codebase. Phase 4.6 follows this guide to switch Daedalus over, so the guide is also 4.6's input.

## Decisions

Taken with the owner on 2026-11-11:

- **Proof: the YAML loads and the catalogue ids exist.** Every fenced `yaml` block on the guide page is a complete pack. A test loads each through the engine's loader and validates it against `pack.schema.json`, with the same `PackSchemaHarness` the valid corpus uses. A second test checks that every catalogue id the guide names exists in `archunitnet-parity.md`, and that every catalogue row is mapped on the guide. The worked example's verdicts on Daedalus's real code are proved by Phase 4.6, not here.
- **The worked example is complete.** A table maps every architecture `[Fact]` in Daedalus's three files to a rule id of the translated pack, or to "stays in C#" or "not needed", each with a reason. The full translated pack follows, then before-and-after pairs for a few representative tests.
- **Load-bearing facts map to `requireTarget`.** The `…IsLoaded…`, `…DoesDependOn…RulesAreLoadBearing` and `ApplicationDtoNames_Cover…` facts prove that a rule's target exists and is used, so the rule is not passing on nothing. Phase 4.4's `requireTarget: true` checks exactly that, so each such fact maps to the rule whose target it guards, and that rule sets `requireTarget: true`, wherever Daedalus code declares or references the target. Where it does not, as for Rag.NET, which Daedalus reaches only transitively, the fact stays in C# as a reflection check on the target's namespace. The guide says that `requireTarget` proves the target is used somewhere in the solution, not by which project, and why that is enough for Daedalus: its `forbid` rules flag every other layer that references Thalos. This replaces the earlier "not needed" mapping, which CodeRabbit flagged on PR #84: vacuity on the subject alone would let a renamed `Thalos.ISubagentRunner` pass.
- **Facts with no rule are explained, not filed.** The check on `Directory.Packages.props` entries is stated plainly as something `bannedPackages` does not see, since a central version entry that no project references is not a dependency. Phase 4.6 decides whether that fact stays in C#.

## Approach

### The page

A new page, `docs-site/docs/migrating-from-archunitnet.md`, with front matter `sidebar_position: 7`, after the catalogue at 6. Sections, in order:

1. **Intro.** Who the page is for, the pinned ArchUnitNET version (0.13.2, as the catalogue), and a link to the catalogue as the reference for what is covered.
2. **What changes.** Rules move from a test class to a pack under `.architecture/`. Ariadne reads source through Roslyn, ArchUnitNET reads IL, and the page links the catalogue's `## Divergences` section for where that shows. One `Ariadne.NET.Testing` call runs every pack, so there is one test instead of one per rule. Layers are open-world, so a dependency to a type in no layer is allowed.
3. **Switching over, step by step.** Add `Ariadne.NET.Testing`, run `ariadne init` or write the pack, add the one test with `ArchitectureCheck.AssertValid`, translate rule by rule with the construct map, run both side by side until they agree, then delete the ArchUnitNET tests and remove `TngTech.ArchUnitNET` and its xUnit adapter. The test snippet is C#, not YAML, so the snippet test skips it.
4. **Construct map.** One table per group, in the catalogue's group order: selecting types (`Types()`, `Classes()`, `Interfaces()` and so on become `kinds`), predicates (`That()`), conditions (`Should()`), negation, slices, combinators, and constructs with no rule. Each table has the header `| ArchUnitNET | Pack YAML | Catalogue id |`. Every catalogue row appears in exactly one map row, by its id in code font; a map row may name several ids when one YAML form answers them, such as a positive and a negative row. Rows the catalogue marks `deferred` or `out-of-scope` stay in the map, with the reason and, for regex methods, the hand translation.
5. **Translating patterns.** How a regex becomes a glob, with worked cases: `^Thalos(\.|$)` becomes `Thalos.**`, because `**` matches zero or more segments; `StartingWith`, `EndingWith` and `Containing` become `*` globs; a regex with alternation becomes several list values. What has no glob form, such as a character class inside a segment, has to be widened or listed. Slice patterns: ArchUnitNET's `X.(*)` and `X.(**)` both translate to `X.(**)`, because ArchUnitNET makes every full sub-namespace its own slice, and it ignores a suffix after `(*)`.
6. **Things that work differently.** Failing types: Ariadne reports the type that breaks the rule, with the rule's `because`, one violation per source and target. `NotExist` becomes `require` with `isNot: { types: ["**"] }` and `allowEmpty: true`. `OnlyDependOn` maps to a layer's `allowedDependencies` or to what the catalogue says after 4.1 measured it. Vacuity replaces the "is loaded" facts. A short list of the divergences, linking the catalogue for each.
7. **Worked example: Daedalus.NET.** See below.

Every `yaml` block on the page is a full pack: `schema: 2`, a `name`, and only what the example needs, so the reader can paste it and the test can load it. Short snippets that show one rule still carry the two header lines.

### The worked example

The example translates Daedalus.NET's architecture tests at commit `1dd470b7`, the milestone's input, and says so with a link to that commit. The builder reads the three files from that commit with `gh api` or a clone, never from a moving branch:

- `tests/Daedalus.Tests.Unit/Architecture/CleanArchitectureTests.cs`, 34 facts;
- `tests/Daedalus.Tests.Unit/Architecture/NoEntityFrameworkTests.cs`;
- `tests/Daedalus.Tests.Unit/Architecture/NuGetPackageRootPathTests.cs`, and the integration test in `tests/Daedalus.Tests.Integration/Architecture/CleanArchitectureTests.cs`, both listed as staying in C#.

**The test map** is a table with the header `| Daedalus test | Pack rule | Notes |`, one row per fact. The Pack rule cell holds a rule id or layer id of the translated pack in code font, or `stays in C#` or `not needed`. Expected mappings, which the builder confirms against the source:

| Daedalus facts | Translation |
|---|---|
| Layer facts, `X_ShouldNotDependOn_Y` between Domain, Application, Infrastructure, Api, Agents and Web | Layers selected by assembly, with `allowedDependencies`, each layer's `id` and `because` taken from the facts' `Because` texts |
| `…ShouldNotDependOn_Thalos`, `…ZeroAllocOrm`, `…ZeroAllocOutbox`, `…Cronos`, `OnlyAgentsProject_DependsOn_RagNet` | `forbid` rules to `namespaces: ["Thalos.**"]` and so on, or one `allowOnly` for Rag.NET |
| `OnlySubagentRunExecutor_DependsOn_ISubagentRunner` (`NotExist` over `DependOnAny` with `DoNotHaveFullName` exclusions) | `allowOnly` to `types: ["Thalos.ISubagentRunner"]`, with the listed types as `from` |
| `Endpoints_ShouldResideIn_ApiLayer`, `RepositoryInterfaces_…`, `RepositoryImplementations_…` | `require` with `layer`, using `names`, `kinds` and `abstract: false` from 4.2 |
| `WebLayer_KeepsNoCopyOf_AnApplicationDto` (reflection) | `uniqueNames` |
| `AgentsProject_DoesDependOn_Thalos_RulesAreLoadBearing` | the Thalos `forbid` rules, which set `requireTarget: true` |
| `SkillsAssembly_IsLoaded…`, `ChannelsAssemblies_AreLoaded…` | `not needed`: they make ArchUnitNET load two Thalos assemblies; Ariadne reads every referenced assembly, and no rule targets those namespaces on their own |
| `ZeroAllocOrmAssembly_IsLoaded…`, `ZeroAllocOutboxAssembly_IsLoaded…`, `CronosAssembly_IsLoaded…` | the matching Domain `forbid` rules, with `requireTarget: true` |
| `SubagentRunnerType_IsLoaded…` | the single-seam `allowOnly` rule, with `requireTarget: true` |
| `MemoryRagNetAdapter_DoesDependOn_RagNet_RuleIsLoadBearing` | `stays in C#`, as a reflection check that `IVectorStore` still lives under `Rag.`: nothing in Daedalus references Rag.NET directly, so `requireTarget` could never find the target |
| `ApplicationDtoNames_Cover…` | the `uniqueNames` rule, with `requireTarget: true` and `against: { namespaces: ["Daedalus.Application.DTOs.**"] }`, which covers the root namespace and every sub-namespace; the fact tested the C# helper `ApplicationDtoNames()`, which the switch removes |
| `No_project_references_ZeroAlloc_Scheduling`, the FluentValidation and CSharpFunctionalExtensions facts, `NoEntityFrameworkTests` | `bannedPackages`, with a note that entries in `Directory.Packages.props` that no project references are not covered |
| `NuGetPackageRootPathTests`, the DI integration test | `stays in C#`: a text scan of MSBuild files, and a test that needs the running container |

**The translated pack** is one `yaml` block: a standalone schema 2 pack named `daedalus`, layers by assembly, as the milestone design says Daedalus's pack must be. It does not extend a built-in pack, so 4.6 needs nothing from #36.

**Before and after** pairs show a few representative facts next to their YAML: a layer fact, the Thalos namespace rule with its regex, the single-seam `NotExist` rule, and the repository-implementation rule with `AreNotAbstract`.

The guide is not final until 4.6 has switched Daedalus over once. When 4.6 changes the pack, it updates this section in Ariadne in the same step, as 4.6's design says.

### Tests

- **`MigrationGuideSnippetTests`** in `tests/Ariadne.NET.Tests/PackSchema/`:
  - `Every_yaml_block_is_a_pack_that_loads_and_validates`: a `[Theory]` over the page's fenced `yaml` blocks, by index. Each must hold `schema: 2`, pass `PackSchemaHarness.LoaderAccepts`, have no `PackSchemaHarness.SchemaErrors`, and resolve its references: a standalone block passes `PackSchemaHarness.ReferencesResolve`, and a block with `extends` resolves through the engine's resolver, which checks references on the merged pack. Loading alone accepts an unknown layer name.
  - `Page_has_yaml_blocks`: at least one block, so a renamed page or a changed fence cannot make the theory pass with zero cases.
  - `Daedalus_map_names_only_rules_of_the_pack`: every rule or layer id in the Pack rule column of the test map, after splitting a cell that holds several on `, `, exists in the worked-example pack, and every rule id in that pack appears in the map.
- **`MigrationGuideTests`** in `tests/Ariadne.NET.Parity.Tests/`, because it needs `ParityCatalogue`:
  - `Every_catalogue_id_on_the_guide_exists`: each id in the Catalogue id column is a row of `ParityCatalogue.Load(ParityCatalogue.PagePath)`.
  - `Every_catalogue_row_is_mapped_on_the_guide`: the reverse.
- The page builds with `npm run build` and adds no broken-link warning.

## Risks

| Risk | Impact | Mitigation |
|---|---|---|
| 4.1's catalogue ends up with ids or statuses this design did not foresee | The construct map does not fit the catalogue | The map is written from the catalogue on `main` when the phase starts, and `Every_catalogue_row_is_mapped_on_the_guide` fails until every row is mapped |
| A 4.2 or 4.3 key is renamed after this phase is planned | Guide YAML stops loading | The guard checks in the 4.2 and 4.3 plans load a pack with every key the guide uses, and the snippet test loads every block |
| Daedalus's tests at `1dd470b7` have a fact the expected mappings above do not cover | The worked example leaves a fact unmapped | The map has one row per fact, read from the source; a fact with no rule is `stays in C#` or `not needed` with a reason, never left out |
| The translated pack loads but gives wrong verdicts on Daedalus's code | 4.6 meets surprises | 4.6 runs the pack on Daedalus and updates this guide in the same step; the guide says the example is pinned and when it was last checked |
| A C# snippet on the page is fenced as `yaml` by mistake, or a YAML snippet as `yml` | The snippet test misses a block or fails on C# | The extractor accepts `yaml` and `yml` fences, and the page's C# blocks use `csharp` |
