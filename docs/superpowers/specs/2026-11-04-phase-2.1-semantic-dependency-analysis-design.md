# Phase 2.1 Design — Semantic dependency analysis

**Date:** 2026-11-04
**Phase:** 2.1
**Surface:** Backend
**Stage:** phase (one phase, implementation-ready)

> Inputs: `docs/superpowers/specs/2026-11-04-milestone-2-design.md`, whose "Decisions" and "Calls made" sections bind this phase; a read of `main` at `e71267f`; and the user's answers of 2026-11-04 listed under Decisions.

## Goal

CLI `validate` and MCP `validate_source` check a `.sln`, `.slnx` or `.csproj` against today's v1 layer and role rules using the semantic type graph of its compilations, not its `using` lines. `SourceValidator` is gone, issue #1 is closed, and `Ariadne.NET.Workspaces` ships as the third package.

## Intent and scope

Every rule type in phases 2.2 to 2.5 is evaluated against the graph this phase builds. Phase 2.1 keeps the v1 pack format on purpose, so the new engine is proven on today's packs before the schema changes under it. A difference in verdicts between the old and the new engine in this phase comes from the engine, not from the schema.

**Goals:**
- A type dependency graph built from one or more Roslyn `Compilation`s, with a file and line on every edge.
- The v1 layer rules and the three hard-coded role checks (type kind, accessibility, missing interface) evaluated on that graph, with the same meaning they have today.
- The violation model the whole milestone uses, filled with what v1 packs can supply.
- `Ariadne.NET.Workspaces`: loads a solution or project through MSBuildWorkspace and MSBuildLocator, fails the run on an incomplete load, and is packed, inspected and published by CI.
- CLI `validate` and MCP `validate_source` on the new engine. `SourceValidator` and its types deleted.
- A recorded time and allocation baseline for checking this repo's own solution.

**Non-goals:**
- Schema v2, selectors, `because`, exceptions, `forbid` and `allowOnly`: phase 2.2.
- Detecting a type covered by two layers. The v1 layer mapping picks one layer per namespace and cannot overlap; the error arrives with 2.2's selectors.
- Placement and code-feature rules, `CODE-001` and `CODE-002` from the pack: phase 2.3.
- Banned packages and member-level forbidden APIs: phase 2.4.
- Vacuity: phase 2.5.
- Caching a loaded workspace between MCP calls. Each call loads afresh; caching is designed with the agent tools in Milestone 5, when the call pattern is known.
- `lint_source` and `Linter`. They scan directories for namespace-against-folder mismatches, which is a different question, and stay as they are.
- JSON and SARIF output: Milestone 3.
- The `docs/how-it-works/` copy. Phase 2.6 deletes it, so it is not updated here.

**Anti-goals:**
- A second, syntax-only path kept for speed or as a fallback. The milestone decided on one engine.
- Reporting violations from a half-loaded solution. A load that is not complete is an error, never a shorter violation list.
- Reading files from disk by directory glob. Input comes only from the projects' compilations, so `bin/` and `obj/` are never scanned.
- `Microsoft.Build.*` assemblies in the CLI's or MCP server's output folder. MSBuildLocator requires them to come from the SDK.

## Decisions

Taken by the user on 2026-11-04 during this brainstorm:

- **The graph is built by a bound syntax walk** (approach A below).
- **The MCP server loads the workspace on every `validate_source` call.** No cache in this phase.
- **Issue #1 was reopened.** PR #22 closed it automatically because its body quoted this phase's goal. This phase's implementation PR closes it.
- **A layer rule reports one violation per source type and target type,** not one per reference. It is located at the first reference and counts the others. ArchUnitNET also reports per type pair, and an agent or a person reading the output sees one design mistake once.
- **Every C# project the given path names is checked.** To leave test projects out, the caller points at a `.csproj`, a solution that lists only the production projects, or a `.slnf` solution filter. Choosing projects inside the pack can come with phase 2.2's assembly selectors.
- **The test-only `UnixFact` and `UnixNonRootFact` attributes move to one shared source file in this repo,** `tests/Shared/`, linked into each test project with `<Compile Include>`. They do not go to ZeroAlloc.TestHelpers, which has no xunit dependency by design.

Binding from the milestone design, repeated here because the plan needs them in view: the core engine takes `Compilation`s and does not reference MSBuild; MSBuildWorkspace lives in `Ariadne.NET.Workspaces`; dependencies are type references in the semantic graph, and an unused `using` is not one; checks are open-world; generated code is not a dependency source; a workspace that does not load fully fails the run; multi-targeting projects are checked per target framework and identical violations are reported once; CLI `validate` and MCP `validate_source` take a solution or project path; the violation model is designed here for the whole milestone.

## Approaches

**A. Bound syntax walk (chosen).** For each source syntax tree, walk the syntax and bind every name with the tree's `SemanticModel`. A type name gives an edge to that type; a member name gives an edge to the member's containing type. One mechanism covers base lists, member signatures, attributes, generic arguments and method bodies, and every edge carries the exact location of the name that caused it. Its blind spot is a type that is only inferred and never written, such as the type of a `var` local or an implicit conversion. That fits the definition of a dependency as a reference somebody wrote.

**B. Symbols plus `IOperation`.** Read signature-level dependencies from the type symbols and body-level ones from each method's `IOperation` tree. This catches implicit conversions and user-defined operators, but it is two mechanisms that must agree, and a signature edge only knows the declaration's location unless it is mapped back to syntax.

**C. Emit and read IL**, as ArchUnitNET does. Closest to ArchUnitNET's verdicts, which would help the Milestone 4 parity harness, but it needs a successful emit and PDBs to recover locations, and it loses the source-level exclusion of generated code. Rejected.

If Milestone 4's parity harness finds ArchUnitNET counting a dependency that A misses, the fix belongs in phase 4.3.

## Approach

### The type graph (core, `Ariadne.NET`)

Input is a list of analysed projects. Each one is a project name, an optional target framework, a `Compilation` and an optional set of the syntax trees that source generators produced. An in-process caller, such as a Thalos agent, builds this list itself; `Ariadne.NET.Workspaces` builds it from a solution. A convenience overload takes a single `Compilation`.

For every syntax tree of every compilation that is not generated code, a syntax walker visits the nodes and binds them:

- `IdentifierNameSyntax` and `GenericNameSyntax`, which covers type names in declarations, base lists, attributes, `typeof`, casts, patterns, `catch` clauses, generic arguments, qualified names and member accesses. In a qualified name every part is bound; parts that bind to a namespace give nothing, and a part that binds to an outer type gives an edge to it.
- `ImplicitObjectCreationExpressionSyntax` (`new()`), whose constructor's containing type is the target.
- Alias uses resolve through the `IAliasSymbol` to the aliased type.

The `var` keyword is skipped, so an inferred type is not an edge. `using` directives, global usings and alias declarations sit outside any type, so they produce no edge by themselves; only a use of what they import does. That closes the first half of issue #1, the usings inside a file-scoped namespace, by making usings irrelevant.

The source of an edge is the innermost type declaration around the node, nested types included. A node outside every type, such as an assembly attribute, gives no edge. Top-level statements belong to the compiler's `Program` type.

The target is normalised: a member becomes its containing type; a constructed generic type, array or pointer becomes its original definition or element type; a reduced extension method becomes its static class. Type parameters, `dynamic`, error types and edges from a type to itself are dropped. Edges are de-duplicated on source type, target type and location.

Generated code is recognised as Roslyn's analyzers recognise it: a tree in the analysed project's set of source-generator output; an `<auto-generated>` comment at the top of the file; a file name ending in `.g.cs`, `.g.i.cs`, `.designer.cs` or `.generated.cs`; `generated_code = true` from the analyzer config, read through `Compilation.Options.SyntaxTreeOptionsProvider`; and, for a single type, `[GeneratedCode]`. `Ariadne.NET.Workspaces` fills the generator-output set from the project's source-generated documents, so a generator whose hint names carry no `.g.cs` suffix and no header is still recognised. An in-process caller that leaves the set empty gets the other rules only. Generated trees are not walked, so they produce no edges and their types are not role-check subjects. Their types remain valid edge targets. A partial type split over a generated and a hand-written file gets edges from the hand-written part only. This closes the second half of issue #1: the SDK's `GlobalUsings.g.cs` and `AssemblyInfo` files are part of the compilation, but generated.

Each type's layer is computed once and cached per symbol, so the per-edge rule check does no string work after warm-up.

### v1 rules on the graph

The v1 meaning is kept exactly, applied to symbols instead of file text:

- **Layer of a type:** the last segment of the type's containing namespace that equals a layer name, case-insensitively, as `SourceValidator.DetectLayer` does today. This applies to source types and to metadata types from referenced assemblies alike, since today's validator maps any `using`. A type with no matching segment has no layer and is not constrained, as either source or target.
- **Layer dependency:** an edge whose source and target are in different layers is a violation when the target layer is not in the source layer's `allowedDependencies`. All edges between one source type and one target type make one violation, located at the first reference in file-path, line and column order, with the number of references.
- **Role match:** a source type in a role's layer whose name ends with the role name or one of its `alternativeNames`, case-insensitively, as today. Nested types are included, as `DescendantNodes` includes them today.
- **Type kind:** compared from the symbol, with `record` and `record struct` told apart through `IsRecord`.
- **Accessibility:** flagged only when the role asks for `internal` and the type's declared accessibility is not internal, as today. Read from the symbol's `DeclaredAccessibility`, so a top-level type with no access modifier, which is internal, now passes. Today's check looks for the `internal` keyword and reports such a type as "declared public", which is wrong; the PR names this as a changed verdict.
- **Missing interface:** when a role requires an interface role and types match the role, but no type anywhere in the checked projects matches the interface role, each matching type is a violation, as today. It is evaluated per target framework, like every other check.

### The violation model

Designed here for the whole milestone; phases 2.2 to 2.5 fill fields, they do not reshape the type. Lives in `Ariadne.NET` beside the engine, not in `Ariadne.NET.Abstractions`, because it is result data, not pack schema. A 0.x release may still change it.

Each violation carries:

- **Rule id.** v1 rules have no ids, so 2.1 derives them: `layer/<LayerName>` for a dependency violation, `role/<RoleName>` for a role check. Phase 2.2 replaces them with the pack's own ids.
- **Kind:** an enum, starting with `DependencyNotAllowed`, `TypeKindMismatch`, `AccessibilityMismatch` and `MissingInterface`. Later phases add members, which is not a breaking change.
- **Because:** empty for v1 packs.
- **Source type:** fully qualified name.
- **Target:** the target type's fully qualified name, or later a package id; absent for role checks.
- **Location:** absolute file path, line and column, 1-based; absent when there is none, as for a missing interface. For a dependency violation this is the first reference.
- **Reference count:** for a dependency violation, how many references from the source type to the target type it stands for; 1 or absent otherwise.
- **Target frameworks:** empty when the violation occurs in every target framework checked; otherwise the ones it occurs in.
- **Message:** a readable sentence built from the fields above.

The report holds the violations, `IsValid`, the projects checked with their target frameworks, the projects skipped with the reason, and the number of types checked. `FilesScanned` goes away; it was the number that depended on the SDK version in issue #1.

Multi-targeting projects arrive as one compilation per target framework. Violations are keyed on rule id, kind, source type and target; equal keys from several target frameworks of the same project merge into one violation, and the target-framework list is filled only when the violation is not in all of that project's target frameworks. The merged violation keeps the earliest location and the highest reference count.

### `Ariadne.NET.Workspaces`

A new packable project, `src/Ariadne.NET.Workspaces`, referencing `Ariadne.NET`, `Microsoft.CodeAnalysis.Workspaces.MSBuild` at the repo's Roslyn version, and `Microsoft.Build.Locator`.

- **Path resolution.** A `.sln`, `.slnx`, `.slnf` or `.csproj` path, or a directory that holds exactly one file of those kinds. Every C# project the path names is checked, test projects included. A directory with none or with several is an error that lists what it found.
- **MSBuildLocator.** The requirement is that a load works with the installed .NET SDK and that no `Microsoft.Build` assembly lands in the output. Roslyn 5.x's `MSBuildWorkspace` evaluates projects in an out-of-process build host, which may make the locator unnecessary; the plan's first task is a spike that settles this, and the rest of this bullet applies if the locator is still needed. It is registered once per process, guarded by `MSBuildLocator.IsRegistered`, before any type from `Microsoft.Build` or `Microsoft.CodeAnalysis.MSBuild` is touched. The code that registers lives in a different method and class from the code that opens the workspace, so the JIT does not load MSBuild types early. No .NET SDK found is an `Unavailable` error.
- **Restore.** Ariadne does not restore. A project that is not restored fails to load, and the error says to run `dotnet restore`.
- **Complete load or error.** A `WorkspaceFailed` diagnostic of kind `Failure`, a C# project that did not load, or any error-severity compiler diagnostic in a compilation fails the run with an `Invalid` error naming the project and the first few diagnostics. Warnings do not fail it. Any compile error fails it, not only unresolved types: it is a simpler rule to state and test, and a solution that does not compile cannot be trusted to give a complete graph.
- **Non-C# projects** (Visual Basic loads; F# does not) are not analysed. They are listed in the report's skipped projects, so the CLI can print them, instead of failing a mixed solution outright.
- **Lifetime.** The loaded workspace is disposed once the compilations have been checked.

A single entry point, `ISolutionValidator.ValidateAsync(RulePack pack, string path, CancellationToken)`, returns `Task<Result<ArchitectureReport, AriadneError>>`: it loads, checks and disposes. CLI `validate` and MCP `validate_source` both call it, so they cannot drift apart. `AddAriadneNETWorkspaces()` registers it.

### CLI and MCP

- **CLI `validate [path]`:** path defaults to the current directory. Prints the projects and types checked, any skipped projects, then each violation as `[Kind] file:line` followed by the message and, for a dependency violation with more than one reference, their number. The report holds absolute paths; the CLI shows them relative to the directory of the solution or project it loaded. Exit codes keep their meaning: 0 clean, 1 violations, 2 for a load or pack error.
- **MCP `validate_source`:** the `sourceDirectory` parameter becomes `path` with the same meaning as the CLI's. The tool returns the report; errors go through `ToolError` as today. The description says it checks a solution or project.

Both are breaking changes, as is removing `ISourceValidator`. The commit that removes them is marked `feat!:` or carries a `BREAKING CHANGE:` footer, and release-please releases the milestone as 0.2.0.

## Tests

- **Graph, unit:** in-memory `CSharpCompilation`s, no MSBuild. One test per edge source: base type, interface, attribute, field, property, parameter and return types, generic argument and constraint, object creation and `new()`, static member access, instance member access, extension method, `typeof`, cast, `is` pattern, `catch` type, nested type, fully qualified name, alias, global using. Negative tests: an unused `using` gives no edge; `var` gives no edge; a self-reference gives no edge; a `using` inside a file-scoped namespace with no use gives no edge, and with a use gives exactly the use's edge. Locations checked for line and column.
- **Generated code, unit:** one test per recognition rule; a partial type split over generated and hand-written files; a generated type is still a valid target.
- **v1 rules, unit:** the cases of `SourceValidatorTests` and `SourceValidationIntegrationTests` ported to compilations, so the verdicts of today's tests are kept on the new engine, apart from the accessibility change named above. Rule ids, kinds, locations and reference counts asserted, including a type that references a forbidden type several times and gets one violation. Multi-target merging: a violation in both frameworks reported once with an empty list, one in a single framework reported with its name.
- **Workspaces, integration:** small fixture projects under `tests/fixtures/`, restored once per test run by a collection fixture. Cases: a `.slnx` and a `.sln` with Domain and WebApi projects, clean and broken; a single `.csproj`; a `.slnf` that leaves a project out; a directory with exactly one solution and one with two; a multi-targeting project; a project with a compile error; an unrestored project; a project with a source generator whose output has a plain file name; a project whose `obj/` holds generated files, which must not count as sources. The fixtures carry their own `Directory.Build.props` and `Directory.Build.targets` so they do not inherit this repo's analyzers, warnings-as-errors or release-manifest check, and they are not in `src/Ariadne.NET.slnx`.
- **CLI and MCP:** `ExitCodeTests` and `ValidationToolsTests` move to fixture projects, keeping the exit-code and error-mapping cases.
- **Allocation:** the per-edge rule check under an `AllocationGate` budget of 0 bytes per call.
- **Regression:** the full suite, the AotSmoke test in CI, and the pack-validate consumer runs. Builds and tests run one at a time on the shared VM, and the AOT publish runs only in CI.

## Risks

| Risk | Impact | Mitigation |
|---|---|---|
| MSBuild assemblies reach the CLI or MCP output and clash with the SDK's | Load errors at run time | Reference only what MSBuildLocator's guidance allows; a test that opens a fixture from the built CLI catches it |
| MSBuild types load before `MSBuildLocator.RegisterDefaults` | `FileNotFoundException` for `Microsoft.Build` on first use | Registration in its own class and method; a test calls the entry point in a fresh process |
| Fixture restore makes the test run slow or flaky, or fails offline | Long or red CI | Restore once per run in a collection fixture; fixtures reference no packages beyond the SDK's |
| Fixtures inherit the repo's `Directory.Build.*` | Fixture builds fail on the release-manifest check or analyzer warnings | Fixture-local `Directory.Build.props` and `.targets` that stop the import chain |
| Binding every name is slow on a large solution | Slow CI and MCP calls | The baseline measures it; per-symbol layer cache; per-tree `SemanticModel` reused for the whole tree |
| A verdict changes between `SourceValidator` and the new engine on an existing test | A silent change in behaviour | Port every existing validator test before deleting the old one; a changed verdict is explained in the PR, such as the issue #1 cases |
| The breaking commit lands without `!` | release-please cuts a patch | The plan names the breaking commit; review checks the marker |
| The CI consumer sample needs an SDK to load its fixture | Pack-validate fails on runner changes | The runner already has the SDK from `setup-dotnet`; the step restores the fixture explicitly |
