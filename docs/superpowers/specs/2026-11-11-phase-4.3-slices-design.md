## Goal

A pack can group types into slices by a namespace capture and require that the slices have no cycles, or that they do not depend on each other except through types the rule allows. The built-in `modular-monolith` pack uses this to keep each module out of other modules' internals, a fixture proves it, and #32 is closed. Every `KnownGaps` entry with phase `4.3` is closed.

## Why

ArchUnitNET's `Slices().Matching(...).Should().BeFreeOfCycles()` and `.NotDependOnEachOther()` have no Ariadne form, and they are what 4.1's slice rows record as gaps. Issue #32 is the same idea from the other side: the `modular-monolith` pack puts every module's `Core` in one layer, so `Orders.Core` may reference `Billing.Core`, the dependency a modular monolith exists to forbid. One construct closes both.

## Decisions

Taken with the owner on 2026-11-11:

- **A new `slices` rule kind** (approach A below). It has one or more `matching` patterns, each with one capture, then `freeOfCycles: true` or `independent: true`, and an optional `allow` selector naming targets that any slice may use.
- **Captures follow Ariadne's glob rules.** `(*)` captures exactly one namespace segment and `(**)` one or more; the rest of the pattern is an ordinary dotted glob. So `Shop.(*).**` puts `Shop.Orders` and `Shop.Orders.Core` in one slice, `Orders`. ArchUnitNET's own semantics differ (see Findings). Its `X.(*)` and `X.(**)` translate to Ariadne's `X.(**)`, which gives the same slices; the parity harness proves this, and 4.5's guide documents it.

## Findings that shape the work

- **ArchUnitNET 0.13.2's slice matching, measured** with a throwaway program on 2026-11-11 (0.13.5 behaves the same). Types in `Shop.Orders`, `Shop.Orders.Core`, `Shop.Orders.Core.Deep`, `Shop.Billing`, `Shop.Billing.Core` and `Shop`:
  - `Matching("Shop.(*)")` and `Matching("Shop.(**)")` give the same slices: `Orders`, `Orders.Core`, `Orders.Core.Deep`, `Billing`, `Billing.Core`. The slice name is the whole namespace after the fixed prefix, so every sub-namespace is its own slice. `Shop.Root` is in no slice.
  - `Matching("Shop.(**).Core")` gives `Orders` and `Billing`, holding only the types directly in `Shop.<x>.Core`.
  - `Matching("Shop.(*).Core")` ignores `.Core` and behaves like `Shop.(*)`.
  - `MatchingWithPackages(p)` gives the same slices as `Matching(p)`; only the name differs, being the slice's full namespace (`Shop.Orders.Core`).
  - `BeFreeOfCycles` reports one failure per cycle, with every slice of the cycle in it. `NotDependOnEachOther` reports one result per slice, failed when it depends on any other slice.
- **The two semantics agree on Ariadne's `(**)`.** Ariadne's `Shop.(**)`, read as a glob, captures every segment after `Shop.` to the end, which is ArchUnitNET's slice name for both `Shop.(*)` and `Shop.(**)`. `Shop.(**).Core` captures the segments between `Shop.` and a final `.Core`, as ArchUnitNET does. ArchUnitNET's `Shop.(*).Core` has no faithful translation, because its suffix is ignored; the catalogue notes say to drop the suffix, which gives `Shop.(**)`.
- **Slice rules must see every project at once.** `ArchitectureValidator` checks each project's `TypeGraph` on its own. A cycle can run through three projects (`Orders.Infrastructure` in project C references `Billing` in project B, which references `Orders.Core` in project A), and no single graph holds it. Slice rules therefore run once over all graphs, as `UniqueNameRules` does. Each graph's edges include references into other projects' types, so the union of the edges is the whole dependency picture.
- **A type seen in several target frameworks counts once,** as in `UniqueNameRules`.
- **`forbid` exceptions exempt the depending type only.** That fits slices too: `exceptions` on a slice rule exempt source types. Allowing a *target* needs the new `allow` key.
- **The `modular-monolith` pack has no `rules:` today.** Its modules are `<Module>.Public`, `.Core` and `.Infrastructure`, plus a `Host` layer outside any module. The milestone design keeps that convention and does not make the pack configurable.

## Approaches considered

- **A — A `slices` rule kind (chosen).** One rule shape covers both ArchUnitNET slice conditions and #32. Cycles are a property of the whole slice graph, which only a dedicated rule can check.
- **B — Capture variables in `forbid` selectors,** as #32 sketched: `from: "**.{m}.Core.**"`, `to: "**.{n}.**"`, with `m` ≠ `n`. More general, but it starts an expression language over variables and still cannot say "no cycles". Rejected.
- **C — Per-module layers.** A layer gains a capture and becomes one instance per module. It changes the layer model every rule relies on, and cannot say "no cycles" either. Rejected.

## Approach

### Pack shape

```yaml
rules:
  - id: SHOP-MODULES-INDEPENDENT
    because: A module reaches another module only through its public API.
    slices:
      matching: ["Shop.(*).**"]
      independent: true
      allow: { namespaces: ["Shop.*.Public.**"] }
  - id: SHOP-MODULES-ACYCLIC
    because: Modules form a hierarchy, so each can be built and tested without the ones above it.
    slices:
      matching: ["Shop.(*).**"]
      freeOfCycles: true
```

- **`slices`** is a new rule key, next to `forbid`, `allowOnly`, `require`, `bannedPackages` and `uniqueNames`. A rule has exactly one of them, as today. The rule keeps `id`, `because`, `description`, `exceptions`, `locked` and `allowEmpty`.
- **`matching`** is a non-empty list of dotted namespace patterns. Each pattern has exactly one capture segment, `(*)` or `(**)`, as a whole segment. Every other segment follows today's dotted glob rules (`*` within a segment, `**` for zero or more segments).
  - A type belongs to a slice when its namespace matches a pattern; the slice name is the captured segments joined with `.`.
  - `(*)` captures exactly one segment; `(**)` one or more.
  - When a pattern can match a namespace in more than one way, the match with the earliest capture start wins, and for `(**)` at that start the shortest capture that still lets the rest of the pattern match. So `**.(*).Core.**` on `A.Orders.Core.X.Core.Y` captures `Orders`. The loader's message for patterns and the docs state this rule.
  - When several patterns match a type, the first in list order decides its slice.
  - A capture needs at least one segment, so a namespace with nothing where the capture sits, such as a root `Public.Contracts` under `**.(*).Public.**`, is in no slice.
  - A type whose namespace matches no pattern is in no slice. It is neither checked as a source nor counted as a target.
- **`freeOfCycles: true`** or **`independent: true`**: exactly one, and it must be `true`. Both, neither, or `false` is a load error. (`independent` implies acyclic, so a rule that wants both writes `independent`.)
- **`allow`** is an optional selector, with the keys a `to` selector of `forbid` accepts today, `layers` included and `members` excluded. A reference whose target type matches `allow` does not count as a dependency between slices, for either condition. When 4.2 has landed, `allow` accepts its selector traits too, because it is parsed by the same selector reader; this phase adds no case for them.
- **`exceptions`** exempt source types, as on `forbid`: a type an exception covers is neither checked as a source nor counted in a cycle edge. An exception amendment from a child pack works as for other rules.
- **Errors at load time**, each as a `path: reason` line in the usual `Rule pack '{name}' is invalid.` error: a pattern with no capture or more than one; a capture that is not a whole segment (`Shop.Ord(*)`); `(*)` or `(**)` in any key other than `matching`; an empty `matching`; a `matching` entry that fails dotted-glob validation; `allow` with `members` or with no key; the condition rules above.

### Model

In `Ariadne.NET.Abstractions`, additive public API:

- `RuleKind.Slices = 6`.
- A new `SliceDefinition` class (`[Validate]`): `IList<string> Matching`, `bool FreeOfCycles`, `bool Independent`, `TargetSelector? Allow`. Member rules: `Matching` not empty, no null entries; exactly one of the two booleans true (a `Must` rule). The loader enforces the capture rules; the validator backstop only checks what it can without the engine's glob code.
- `RuleDefinition.Slices` (`SliceDefinition?`), set when `Kind` is `Slices`. `From` is required on `RuleDefinition` today; a slices rule sets it to an empty `TargetSelector`, as `uniqueNames`' loader path does for unused members. The builder confirms how `uniqueNames` and `bannedPackages` fill `From` and follows the same pattern.

`RulePackReferenceCheck` checks layer names in `slices.allow`, like rule targets. `RulePackMerger` merges slice rules by id like every other rule, and an amendment with only `id` and `exceptions` appends exceptions as today.

### Engine

- **`SlicePattern`** (internal, `Analysis/`) compiles one `matching` entry and answers `bool TryCapture(string ns, out string slice)` without regex. It reuses `Glob`'s segment matching for the parts before and after the capture. The loader calls a static `SlicePattern.Validate(string)` that returns the same failure messages as `Glob.Dotted`, plus the capture errors.
- **`SliceRules`** (internal, `Analysis/`) is compiled once per run from the pack, like `ForbidRules`, and checked once over all graphs, like `UniqueNameRules.Check(layers, pack, graphs)`. Per rule:
  1. Assign each source type of every graph to its slice. Types are keyed by assembly name and display string, as `UniqueNameRules.Collect`'s `TypeId` keys them, so types of the same name in two assemblies stay apart, and a type seen in several target frameworks of one project counts once. An exception exempts a type as a source only, as `forbid`'s exceptions do: an excepted type keeps its slice, its own references are not counted, and references to it still are.
  2. Walk the type edges (`TypeGraph.Edges`, not `MemberEdges`) of every graph, as `forbid` does. An edge counts when its source is not excepted, its source and target both have a slice, the slices differ, and the target does not match `allow`.
     - **Only types declared in a loaded project have a slice,** targets included: a target gets its slice from its namespace only when it is a source type of some graph in the run. A framework or package type never has one, so a `**`-led pattern cannot create a dependency on `System.Foo.Core.X`. This matches ArchUnitNET, which only knows the assemblies it loaded.
     - **A type's namespace** is its containing namespace, so a nested type sits in its outermost type's slice. Generic arguments are already separate edges in the graph.
     - **`allow` is matched as a `forbid` rule's `to` is,** through the same `TargetMatcher` and `LayerMap`, so `layers` resolve exactly as they do for `forbid`.
  3. **`independent`:** one `ViolationKind.SliceDependency` violation per counted source type and target type, with `ReferenceCount` and the first reference's `Location`, as `forbid` reports. Message: `Type 'Shop.Orders.Core.OrderService' in slice 'Orders' depends on 'Shop.Billing.Core.Invoice' in slice 'Billing', and rule 'SHOP-MODULES-INDEPENDENT' keeps slices independent`, plus the reference count suffix the other dependency violations use.
  4. **`freeOfCycles`:** build the slice graph from the counted edges and find its strongly connected components (Tarjan, iterative). For every slice edge A → B with both slices in the same component of two or more slices, report one `ViolationKind.SliceCycle` violation. Its `SourceType` is the type in A whose first reference to B comes earliest by location, `Target` that reference's target, `Location` that reference, `ReferenceCount` the number of references from A to B. Message: `Slice 'Orders' depends on slice 'Billing' (first through 'Shop.Orders.Order' -> 'Shop.Billing.Invoice'), and slices Billing, Orders form a cycle, which rule 'SHOP-MODULES-ACYCLIC' forbids`, with the component's slices sorted ordinally. Components, not elementary cycles: linear time, and the set of slices reported equals the union of ArchUnitNET's reported cycles.
  - Every violation's `SourceType` lies in a slice the rule's patterns name, which 4.1's `Projection.Slices` relies on.
  - "Earliest by location" uses `TypeGraphBuilder.Compare` (file path, line, column), as the validator's merging does. Violation order in the report is the validator's existing final sort; `SliceRules` returns its violations in pack rule order and needs no order contract of its own.
  - **Framework scopes.** Steps 2 to 4 run once per scope, built as `ArchitectureValidator.AddMissingInterfaceViolations` builds its scopes: one per named target framework, holding that framework's graphs and every graph whose project has a null target framework, or a single scope over all graphs when no project names a framework. A cycle needs every one of its edges in one scope, so `A → B` only in `net8.0` and `B → A` only in `net10.0` is no cycle. A violation found in several scopes is reported once, with the earliest location and the highest reference count. Its `TargetFrameworks` lists the named frameworks of the scopes that found it, and is left empty when every scope found it, as the validator's per-project merge leaves it.
- **`ViolationKind`** gains `SliceCycle = 14` and `SliceDependency = 15`. 13 is `RequirementNotMet`, which Phase 4.2 adds; if 4.3 lands first, 13 stays free for it. `SarifReportWriter` treats both as type-located kinds (the default branch already does). The JSON writer serialises the name, so it needs no change; the builder confirms.
- **`ArchitectureValidator`** calls `SliceRules.Check(...)` next to `UniqueNameRules.Check(...)` and adds the result to the report. `RulePackDescriber` describes slice rules for `ariadne rules` and the MCP tools: patterns, condition, allow.
- **Vacuity.** `VacuityRules` treats a slices rule whose patterns place no type in any slice as a `VacuousRule`, unless `allowEmpty`. A rule that finds one slice is not vacuous; it simply cannot fail, as in ArchUnitNET.
- **Code generation** ignores slice rules.
- **Every code path that iterates a pack's rules** must tolerate a `Slices` rule with an empty `From`: at least `DependencyRuleChecker` (filters by kind), `RequireRules`, `UniqueNameRules`, `BannedPackageRules`, `MemberNameFilter`, `VacuityRules`, `LayerProbe`, `RulePackReferenceCheck`, `RulePackMerger` and the describer. The plan's first engine task greps for `RuleKind.` and `.From` uses and lists each site it checked.

### `modular-monolith`

The pack gains:

```yaml
rules:
  - id: MM-MODULES-INDEPENDENT
    because: A module may use another module only through that module's public API.
    allowEmpty: true
    slices:
      matching: ["**.(*).Public.**", "**.(*).Core.**", "**.(*).Infrastructure.**"]
      independent: true
      allow: { layers: [Module.Public] }
```

The module is the segment before `Public`, `Core` or `Infrastructure`. A module's `Core` may still use its own `Public` (same slice) and any other module's `Public` (allowed); it may not use another module's `Core` or `Infrastructure`. `Host` is in no slice and stays free. `allowEmpty` matches the pack's roles, so a solution without modules in this shape is not a vacuity error. Cycles between modules through their `Public` APIs are not forbidden by the built-in pack, because `allow` removes those edges; a team that wants that adds its own `freeOfCycles` rule. `version` goes from `1.0.0` to `1.1.0`.

A new fixture, `tests/fixtures/modular/` (`Modular.slnx`, restored like the other fixtures), has modules `Orders` and `Billing` across at least two projects: `Billing.Core` uses `Orders.Public` (allowed), `Orders.Core` uses `Billing.Core` (a violation), and `Host` uses both modules' `Core` (allowed). Its `.architecture/rules.yaml` extends `builtin://modular-monolith`. A Workspaces test asserts exactly one `SliceDependency` violation with rule id `MM-MODULES-INDEPENDENT`, from `Orders.Core` to `Billing.Core`. The fixture is added to `FixtureProjects`' restore targets. After the PR merges, #32 is closed with a link to it; the PR body says `Closes #32`.

### Closing the parity gaps

For every `KnownGaps` entry with phase `4.3`, add the rule with the case's `AriadneRuleId` to the kind's `.architecture/rules.yaml`, delete the entry, and set the catalogue row to `covered`, or to `divergence` with a `Divergences` entry when the harness shows a difference this design did not foresee (triaged as 4.1's "Measuring today's kinds" says). The ArchUnitNET pattern `X.(*)` or `X.(**)` in a case becomes `X.(**)` in its pack rule. `Gap_has_no_ariadne_rule` fails for any entry whose rule was added and not deleted, so the order is forced. At the end `KnownGaps.Entries` has no entry with phase `4.3`, and a test asserts it.

**Proving the translation.** `SNotDependOnEachOther`'s `Broken` part gains a nested namespace: `Broken.Orders.Internal.Helper`, referenced by a type in `Broken.Orders`. ArchUnitNET treats `Orders.Internal` as its own slice and flags `Orders`; Ariadne's `(**)` does the same. A pack written as `X.(*).**` would not flag it, which is the semantic difference the catalogue's notes explain. `Clean` gets no nested dependency, since ArchUnitNET would flag it.

**What the harness compares.** 4.1's `Projection.Slices` compares slice names. For 4.3 to agree with it, the slice name both sides report must be the same string for `Matching` and `MatchingWithPackages`: this groom amends the 4.1 plan's Task 3 and Task 8 so that a slice case's projected name is the slice's **full namespace**, the pattern's fixed prefix plus the captured segments. That is what `MatchingWithPackages` reports already; for `Matching`, the harness prepends the prefix. The fixed prefix is the literal segments before the capture; a pattern with segments after the capture is not used by any parity case, so the harness does not need a rule for it. Each slice row has one case whose pattern spans the kind, `Parity.<Kind>.(**)`, so slice names start with `Parity.<Kind>.Broken.` or `.Clean.`, and 4.1's `Clean`/`Broken` prefix assertions apply unchanged. `Clean` and `Broken` never reference each other.
