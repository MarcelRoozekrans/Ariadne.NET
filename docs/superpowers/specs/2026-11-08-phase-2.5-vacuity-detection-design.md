# Phase 2.5 Design — Vacuity detection

**Date:** 2026-11-08
**Phase:** `2.5`
**Surface:** `Backend`
**Stage:** phase (one phase, implementation-ready)
**Status:** approved 2026-11-08

Milestone 2, Rule engine v2. Builds on `2026-11-04-milestone-2-design.md`. Phases 2.1 to 2.4 are complete, so nothing here waits on an unfinished phase.

## Goal

A rule, a role or a layer that selects no type fails the run with its own violation kind, unless the rule or role sets `allowEmpty: true`.

## Intent and why

A pack that checks nothing looks the same as a pack that passes. Rename a namespace and every rule that named it turns into a green no-op, and nobody notices until the architecture has drifted. Phases 2.2 to 2.4 left this open on purpose: a selector that matches nothing is silent. The Daedalus suite carries hand-written non-vacuity tests such as `SubagentRunnerType_IsLoaded` for exactly this reason; vacuity detection retires them.

## Decided earlier (milestone design)

- Vacuity fails by default, with a per-rule opt-out `allowEmpty: true`.
- Built-in packs set `allowEmpty` on their component roles (the role-placement entries in `componentRoles`, a type separate from `RuleDefinition`) only, because a generic pack such as `ddd-tactical` names roles a solution may not have.
- Layer selectors in built-in packs have no opt-out. A solution that extends `clean-architecture` without a Domain layer should hear about it.

## Decided in this brainstorm (owner, 2026-11-08)

- **Subject side only.** For `forbid` and `allowOnly` the `from` selector must match at least one type. For `require` the `for` selector (the `from` key of the model) must. The `to` side, `against` and `members` are never checked: a clean solution legitimately has no forbidden type or member, so a check there would fail every good solution.
- **Approach A.** One solution-wide pass after the project loop, two new violation kinds. See Approaches.

## Goals

1. Each compiled matcher counts the types its subject selector matched, across all projects and target frameworks of the run. Types are counted once per type, as name collisions are.
2. After the project loop, every rule, role and layer with a count of zero yields one violation.
3. `ViolationKind.VacuousRule = 11` covers rules and roles. `ViolationKind.VacuousLayer = 12` covers layers. Both are solution-level violations: no file and line, like `NameCollision`.
4. `RuleDefinition` and `ComponentRoleDefinition` gain `AllowEmpty` (bool, default `false`), read from `allowEmpty` in YAML.
5. A rule with `allowEmpty: true` produces no violation when empty.
6. `bannedPackages` is vacuous when its non-empty `from` assembly globs match no loaded project. An empty `from` covers every project and is never vacuous.
7. `uniqueNames` is vacuous when its `for` selector matches nothing. Its `against` side is not checked.
8. A role is vacuous when no type in its layer carries its name or one of its `alternativeNames`.
9. A layer is vacuous when no type in the solution maps to it.
10. The built-in packs set `allowEmpty: true` on every component role and on no rule or layer. This repository's `.architecture/rules.yaml` and its tests pass with default-fail.
10a. **No cascade.** A rule whose subject selector names only layers that are already reported as `VacuousLayer` produces no `VacuousRule`: one root cause gives one violation. Selectors cannot name roles, so roles never cascade into rules. (My call.)
10b. **What counts as a match.** A type counts when the rule's subject selector matches it, before exceptions and before any dependency is looked at. A rule whose only subject types are all excepted is not vacuous. The count covers the whole run, so it does not depend on evaluation order. (My call.)
10c. **Merging.** `AllowEmpty` is carried through pack merges as `Locked` is. A child pack cannot amend it on an inherited rule (tracked with #36). Packs have no disabled-rule concept today, so nothing is exempt on that ground. (My call.)
11. CLI `validate`, MCP `validate_source`, CLI `rules` and MCP `get_rules` show `allowEmpty` and the new kinds. The stable error text names the rule or layer and which selector matched nothing.

## Non-goals

- Checking `to`, `against`, `members` or exception selectors.
- Warnings or severities. A vacuous rule is an error; `allowEmpty` is the only opt-out.
- Per-project vacuity. Whether a rule matches in Web but not in Domain is not a question the model asks.
- The pack reference and JSON Schema for `allowEmpty`: phase 2.6. This phase adds a short note to the rule-schema page.
- Letting a child pack amend `allowEmpty` on an inherited rule: tracked with #36, which already covers amendments.

## Anti-goals

- A vacuity result that depends on project order or target framework count.
- A second matching pass that can drift from the real checkers.
- Silencing a vacuous layer from a built-in pack. The fix is a retarget in the child pack, not an opt-out.

## Constraints

- Vacuity is relative to what was loaded. A run on a single `.csproj` sees only that project's types, so a pack with layers across several projects reports those layers as vacuous. This is documented, not special-cased. The error text is fixed wording plus the number of projects loaded; tests assert on kind and rule or layer id, never on the text. (My call.)
- The default changes outcomes for existing packs, so the change is breaking: `feat!` with a `BREAKING CHANGE` footer, and a `BEGIN_COMMIT_OVERRIDE` block in the PR body before merge (lesson of 0.3.0).
- `Ariadne.NET.Abstractions` stays AOT-safe; the AotSmoke test runs in verification. No new runtime dependencies.
- Perf stays within the 2.4 baseline noise. The counter is an integer increment on a path that already matches.

## Approaches

**A. One solution-wide pass after the project loop. Chosen.** Matchers expose a match counter; after all projects are analysed, zero counts become violations. Two kinds, `VacuousRule` and `VacuousLayer`. No second matching pass, and it follows the pattern name collisions already use. Cost: every compiled checker gains a counter.

**A with one kind.** Same pass, but a single `EmptySelector` kind told apart only by message. Rejected by the owner: tooling that filters by kind cannot tell a missing layer from a dead rule.

**B. Per-project vacuity.** Rejected. In a multi-project solution a Domain rule is empty in Web and Infrastructure, so it fires everywhere or needs a project filter.

**C. Separate pre-pass.** Match every selector against the type list before running rules. Rejected: it matches types twice and duplicates logic that lives in the compiled checkers, so the two can drift.

## Tests

- Unit, per rule kind: subject matches nothing is a violation; matches something is clean; `allowEmpty: true` is clean; `to` matching nothing is clean.
- Unit: role vacuity, layer vacuity, `bannedPackages` with a non-empty and an empty `from`, `uniqueNames` with `for` empty.
- Unit: counts are per solution, not per project; a type seen in several target frameworks counts once.
- Integration: every built-in pack validates against a fixture solution that covers none of its roles, and fails only on layers it lacks, never on roles.
- Integration: this repository passes its own pack in CI with default-fail.
- Loader: `allowEmpty` accepted on rules and roles, rejected elsewhere as an unknown key; non-bool value rejected.
- AotSmoke and the perf comparison against `docs/perf/phase-2.4-baseline.md`.

## Risks

| Risk | Impact | Mitigation |
|---|---|---|
| Existing user packs start failing on upgrade | Users turn rules off or stop upgrading | Breaking marker and release notes; `allowEmpty` documented; the error names the exact selector |
| Built-in layer selectors fail ordinary solutions that extend a broad pack | Users stop extending built-ins | Intended signal, per the milestone design; the error says to retarget the layer |
| Counters add cost on the hot path | Slower CI and agent loops | Integer increment only; perf check against the 2.4 baseline |
| Single-project runs report many layers as vacuous | Confusing first run | Error names the projects loaded; documented in the pack reference note |
