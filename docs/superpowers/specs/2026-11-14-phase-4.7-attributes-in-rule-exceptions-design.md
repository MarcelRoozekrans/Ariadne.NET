# Phase 4.7 Design — Attributes in rule exceptions

**Date:** 2026-11-14
**Phase:** 4.7
**Surface:** Backend
**Stage:** phase (one phase, implementation-ready)
**Status:** approved 2026-11-14

## Goal

A rule exception, including an exception in an amendment, accepts `attributes`. The key means what it means in a selector, so ArchUnitNET's `DoNotHaveAnyAttributes` gets a pack form. The parity case `p-have-any-attributes:not` is then covered and #97 closes.

## Intent

The Milestone 4 audit of 2026-11-14 failed on this gap alone: `KnownGaps` still holds `p-have-any-attributes:not`, and the milestone's definition of done needs `KnownGaps` empty for in-scope kinds. On 2026-11-14 the owner decided #97's "needs a decision" in favour of `attributes`, with the selector key's meaning.

- **Goal:** `exceptions: [{ attributes: ["Ns.AuditedAttribute"], because: … }]` loads, validates and exempts every source type that carries the attribute.
- **Non-goals:** `baseTypes` and `interfaces` in exceptions (owner, 2026-11-14: `attributes` only, because `assignableTo` already covers both negations); matching on attribute arguments; inherited attributes. Each of these is either already deferred or outside the selector key's meaning.
- **Anti-goal:** an `attributes` that means something different in an exception than in a selector.

## Approaches

1. **Add `Attributes` to `RuleException`, next to the traits (chosen).** It is a new list property. The loader learns the key, and `TypeSelector.From(RuleException)` passes it into the attribute slot of the existing `Compile` call, which receives `[]` today. Matching needs no new code. This is additive, so it is a `feat`, not a breaking change.
2. **Add `attributes`, `interfaces` and `baseTypes` together.** This would make every selector key except `layers` and `members` usable in an exception. The owner rejected it: it overlaps with `assignableTo` and widens schema, docs and tests for no parity gain.
3. **Replace `RuleException`'s lists with a nested `TargetSelector`.** This is a breaking public API change for one key, so it was dropped.

## Decided behaviour

- **Meaning:** the meaning is the selector's. `attributes` holds dotted globs over the full name of each attribute class (its original definition) that is applied directly to the type. Any one glob may match. Like every exception key, it is AND-ed with the other keys of the same exception, and it alone is enough to make the exception valid.
- **Where it applies:** every rule kind whose exceptions compile to `TypeSelector` takes it: `forbid`, `allowOnly`, `require`, `uniqueNames` and `slices`, plus amendments of those rules. A `bannedPackages` exception rejects it at the key with the existing reason ("a package belongs to a project, so … names it by 'assemblies'"), because `bannedPackages` reads only `assemblies`. The merger rejects an amendment built in code that sets it on an inherited `bannedPackages` rule, through `ExceptionKeyRules.UsedKeys`.
- **Patterns:** the loader checks it with `Glob.Dotted`, as it checks the selector key, and a capture is rejected as it is elsewhere outside `matching`.
- **Messages:** "needs at least one of …" now lists `'attributes'` after `'types'` for the kinds that take it.

## Tests

- **Loader:** an exception with only `attributes` loads into `RuleException.Attributes`; an invalid glob is reported at its line; `attributes` on a bannedPackages exception is rejected at the key; an amendment exception with `attributes` loads and merges.
- **Merger:** a code-built amendment with `Attributes` on an inherited bannedPackages rule is rejected.
- **Analysis:** a `forbid` whose exception names an attribute exempts a type that carries it and still reports a type that does not, and `require` and `uniqueNames` get one check each that the exception applies.
- **Schema:** `PackSchema` valid and invalid cases.
- **Parity:** `p-have-any-attributes:not` passes side by side with ArchUnitNET, and `KnownGaps` is empty. The harness already fails if a gap entry outlives its gap.
- **Docs:** `MigrationGuideSnippetTests` and `MigrationGuideTests` still pass.

## Left to the builder

The test file placement follows the existing loader, merger and analysis tests. The exact wording of the doc sentences is the builder's call, as long as it stays within the decisions above.

## Risks

| Risk | Impact | Mitigation |
|---|---|---|
| The schema's bannedPackages `if`/`then` misses the new key | The schema would accept what the loader rejects | The new `PackSchema` invalid case fails until it is added |
| The parity `:not` result differs, for example on `Contracts.AuditedAttribute` itself | The case fails | Use the same `from` scope as the positive rule's ArchUnitNET side; the harness compares projected type sets |
